# V4 增量校准人数：固定配方的小规模证据

固定 V3 方法、source 与所有训练目标，只把 V4 的拟合用户改为原有序 64 人中的前 16/32 人；保留同一 16 人验证集、local8/joint4、batch8、seed17 和短尾4步。原64权重与分数复用。固定原登记32人与原4096顺序前128人，共159人的并集一次执行，两组分开报告；无人按结果挑选。

|V4 拟合人数|记录的校准流程秒数|同16人验证 teacher MSE|V4校准 FLOPs（T）|
|---|---:|---:|---:|
|16|42.40|0.02260|0.819|
|32|57.84|0.01327|1.109|
|64|74.44|0.00701|1.693|

16/32 是本轮 V4 增量拟合人数。三个分支都继承已经训练的256人起点与64人 V3 模型，不能写成“整个方法只需16人”。原64计时来自历史执行，非同期受控速度比较；完整80人的 source/teacher 构造仍是固定保留费用，未按人数除小。

固定128人上，两协议点估计均随16→32→64改善；不能据此说16/32已经足够，也没有测到更大人数是否继续改善。Next-item 的重建增益分母很小，恢复百分比会超过100%，正文宜比较直接 AUC 差。32人 feedback 仅8个负例且 Rebuild 低于 Reuse，不适合判断恢复率或替128人趋势作结论。

固定 epochs 与 batch 后，人数增多也增加优化步数。这是原训练配方的“人数—成本—质量”敏感性，不能把收益完全归因于样本多样性；纯样本效率需要等步数控制。所有结论只覆盖固定前版下的一条 V4 边，不证明跨版本全链、其他模型规模或工业人口所需拟合量。

全量159人/两协议共38,864条候选评分，实际评估196.87秒。原64在每协议前4个固定用户的重评分最大绝对误差4.77e-7，其他64分数按完整候选身份复用。最初评估在开始评分前因浅复制只读代理失败；已保留失败记录并改为共享只读对象、复制可变会话状态，未改训练或数学逻辑。

详细质量与区间见 quality.json、uncertainty.json；原分数和配置见同目录 scores.parquet、configuration.json；训练账见 ../training_summary.json。此轮不选择新最佳参数，不重跑原64训练，不扩展校准角色。
