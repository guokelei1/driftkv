# 八个真实用户的码交接批处理

源为 V5 发布前的 V4 current codes：先以 V4 prefix 反锚，再以 V5 prefix 物化。8人均为已有 fit 源、真实1024行，不平铺用户。
B=1 将同8人逐个处理；B=8 合批处理。均使用 prepared feature bank、row_chunk1024、FP32/TF32 off、3次暖机及5次交错重复。

逐用户与未改 stable reference 比较通过；原生K/V逐元素不变，所有转换使用同一份持久码存储。临时空间不含常驻表、原生状态与测量用输入/参考副本。
这只测量 C 中的码转换子项：不包含共享准备S、历史追赶、推荐、排队或数据搬入。不能据此声称完整S+N×C已验证或生产吞吐提升。CUDA事件数来自另一次不计时的profile，包含其列明的设备事件。

## 五次测量的波动

- anchorize_v4：B1 13.29–13.63 ms；B8 13.55–13.70 ms。
- materialize_v5：B1 13.86–14.07 ms；B8 14.06–14.08 ms。
- handoff_v4_to_v5：B1 27.08–27.17 ms；B8 27.41–27.48 ms。

两阶段交接按每用户先反锚再物化，独立阶段则分别遍历8人；两个独立中位数之和不等于组合测量的中位数。组合计时还有明显波动，不能把其单个比值当成稳定加速倍数。
当前调用包含Python调度、ID范围检查同步及小型索引传输；CUDA event区间也包含主机提交之间的设备空闲，不能当成纯GPU忙时。这里只观察到单阶段合批显著减少重复调用，未进一步归因组合波动。
