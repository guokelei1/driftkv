# 融合码转换：真实状态上的实现选择

各轮使用相同8个真实V4状态，先按V4反锚，再按V5物化；不重训、不修改原生K/V。
当前源码为`fused_conversion.py`。共享与私有分支各一次Triton调用，覆盖所有层和用户，
每个程序完整生成本分支输出后原地写回。冻结特征仍由原生K/V与固定物品项计算，SiLU与
Q变换顺序不变，没有缓存第二份逐行特征。

| 后端 | 8人反锚中位ms | 8人物化中位ms | 8人完整交接中位ms |
|---|---:|---:|---:|
| 既有Torch合批，另一次测量 | 8.186 | 8.836 | 19.073 |
| attempt1：整块native dot | 13.666 | 14.070 | 27.459 |
| attempt2：64坐标分块dot | 0.624 | 0.561 | 1.073 |

attempt3保留分块dot，将历史长度、批大小和stride改为运行时参数，避免真实会话每遇到
新长度都编译一个转换核。完整交接中位1.474ms，交接码差至多7.63e-6；
单阶段核对的最大码差1.05e-5，均在预先设置的容差内。
这次单形状微测略慢，但选择它是为控制全轨迹的编译工作。后续真实会话使用此版本，
不能只保留attempt2的最快单形状数值来描述最终实现。

首版虽减少调用，但实测比Torch合批慢；第二版把共享分支的384输入分块处理，降低同时
存活的中间量。数值检查通过，最大码差约1.05e-5，原生K/V逐元素不变，持久码同一buffer。
反锚和物化各2个设备事件；核不产生全局逐行临时张量，表与小矩阵常驻空间另计。
这些是单卡、输入已驻GPU、3次预热及5次交错重复的转换测量。不同后端在不同时段执行，
比值仅用于实现选择，真实会话的三版配对正确性和完整周期时间另验证。

精度与账目说明：两轮均为FP32状态、Triton显式TF32x3矩阵乘，Torch参考关闭TF32。
早期生成的attempt1/2摘要模板中的“FP32/TF32 off”和ID同步描述只适用于Torch参考，
本页更正该文字；原始计时与检查值未改。新生成器已记录具体后端。
两轮共享/私有码宽补齐到16，第二版满行dot工作约为有效dot的2.08倍；这不等同于TF32x3
机器指令数。不能只用原公式的有效FLOPs声称新核没有补齐成本，执行时间和补齐敏感性分报。

输入ID由上游映射校验；核不逐层执行GPU min/max同步。发布级打包权重及dense逆矩阵
增加约0.4MB共享状态/版本，其准备时间在真实会话接入时单列。转换算子测量不包含校准、
全目录准备、用户状态搬入搬出、排队或后续纠正读取，不能据此给最终规模加速结论。
