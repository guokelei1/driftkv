# 八个真实用户的码交接批处理

源为 V5 发布前的 V4 current codes：先以 V4 prefix 反锚，再以 V5 prefix 物化。8人均为已有 fit 源、真实1024行，不平铺用户。
B=1 将同8人逐个处理；B=8 合批处理。均使用 prepared feature bank、3次暖机及5次交错重复。
后端：triton；精度：FP32 state; TF32x3 native/compact dots。

逐用户与未改 stable reference 比较通过；原生K/V逐元素不变，所有转换使用同一份持久码存储。临时空间不含常驻表、原生状态与测量用输入/参考副本。
这只测量 C 中的码转换子项：不包含共享准备S、历史追赶、推荐、排队或数据搬入。不能据此声称完整S+N×C已验证或生产吞吐提升。CUDA事件数来自另一次不计时的profile，包含其列明的设备事件。

## 五次测量的波动

- anchorize_v4：B1 0.86–1.14 ms；B8 0.76–0.78 ms。
- materialize_v5：B1 0.89–1.15 ms；B8 0.77–0.79 ms。
- handoff_v4_to_v5：B1 1.72–1.97 ms；B8 1.47–1.50 ms。

两阶段交接按每用户先反锚再物化，独立阶段则分别遍历8人；两个独立中位数之和不等于组合测量的中位数。只测5次，不将单个比值视为稳定服务加速。
API计时包含Python调度；CUDA event区间也可能包含主机提交之间的设备空闲，不能当成纯GPU忙时。

融合核要求上游已验证物品ID范围，避免每层GPU标量同步。持久行码不增，但另有发布级打包权重及矩阵；其大小和tile补齐dot工作见JSON。
