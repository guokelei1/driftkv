# 共同模型执行的图复用诊断

公平会话表明，码转换省下的时间被频繁模型读写与固定校准抵消。本探针先检查共同模型路径是否主要受框架分发影响：对两方法的完整评分、追加及原生重建同等使用 CUDA Graph，不修改权重或请求计算。

输入取原 V5 校准源中的8个不同真实fit用户（V4模型、1024行缓存），既有动态门控参数。评分使用源候选；追加复用历史尾部的真实输入值，仅作形状计时，不将这次重复追加作为质量轨迹。B1/B8分别测量。

14个操作的图输出与同输入原执行逐元素相同，核对前改换了候选输入。多查询评分、增量追加从数毫秒降到约0.5–1.7ms；B8重建约6.5→6.2ms，改善小得多。支持继续把共同模型路径的launch开销压低，但尚不支持整体时间收益。

图输入staging包含原生KV、码和item ID的设备拷贝，未覆盖实际会话CPU组批/用户scatter、页传输、变长分流与校准。每形状额外静态工作区和capture时间在JSON内，不计入这张暖态表；不能把微探针直接乘30k。下一步接入真实会话，动态码前缀需作为GPU标量输入，不能把首次捕获的前缀长度固定到后续请求。
