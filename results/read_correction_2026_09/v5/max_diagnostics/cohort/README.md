# 用户群体审计（2026-09-29）

## 可引用结论

三种规模使用相同的选择规则，但并非同一批用户。每条边从各自完整源池中，按“用户相对整个异类标签参考池的 Full−Reuse 排序优势”选取 3000 人，并保留这些用户的全部请求。该分数不是每用户 AUC；单类用户也可被选入。首边 Medium / Large / Max 的源池分别为 13,812 / 36,458 / 91,297 人，3000 人分别占 21.72% / 8.23% / 3.29%。因此，同一个固定人数规则在三种规模上的选择强度不同。

用户与模型配置共同变化，跨规模差异不能单独归因于层数。三规模同名边的五个日期窗口均为 `[231,245)`、`[245,259)`、`[259,273)`、`[273,287)`、`[287,301)`，上下文均为 1024。实际 checkpoint 为 Medium 6L/H192、Large 10L/H320、Max 16L/H320；数据基础用户数为 30,000 / 79,681 / 200,000，已知 item 词表约为 138万 / 222万 / 353万。Large 的 dataset.json 中旧 `model` 标签不是实际 checkpoint 配置，本审计使用校准记录里的实际 `model_config`。

Max 的用户来源并非 Large 的简单扩容。首边 Medium 的源 UID 全部属于 Large；Large 与 Max 却仅共享 9,285 个源 UID，分别占两者 25.47% 和 10.17%。两者选中面板仅共享 141 个 UID。首边选中面板负例比例为 23.60% / 54.69% / 76.14%，这是群体分布改变的描述，**不是 AUC 下降的独立原因**：两类条件分布固定时，类别先验比例本身不改变 AUC。

可观察的群体差异不足以单独解释 Max 的失败。在 V3→V4 的 Large/Max 精确共享 61 UID、876 个原始请求上，标签、历史长度和追加数完全一致，Q512 相对 Reuse 的 AUC 变化仍分别为 **+5.191 / −4.579 个百分点**。按标签分别将活动量、历史长度及旧缓存占比分箱重加权到共同支持后，该边 Max 的变化仍为 **−2.044 个百分点**，共同支持保留 99.97% 的原请求。该对照排除了这些已测分布差异作为充分解释；它不隔离训练数据、checkpoint 与网络结构的影响。

固定 seed 的独立随机 256 用户对照中，同一 Max 模型与同一校正器的首边 C128 / C512 ΔAUC 点估计为 −6.810 / −1.340 个百分点；V3→V4 为 −5.571 / −4.144 个百分点。首边256用户的按用户cluster bootstrap区间跨0，不能仅凭点估计认定稳定退步；为提高精度，仅沿原hash顺序一次扩为2048人，保留原256人和同一排除集合。随机群体未按新结果重选，全部结果保留。V3→V4 随机面板自身 Full−Reuse 为负，故这里报告直接 ΔAUC，不把该边比值型“恢复率”解释为正向恢复。GPU 对照与区间由主任务执行，原始证据在相邻 `random_evaluation/` 和 `offline/`。

## 校准群体与历史概况

Q512 使用 512 个拟合用户及 16 个独立验证用户，均与本规模五条边的评测/检查用户集合隔离。用户仅按 UID 哈希预留；拟合候选为一半最近的已知历史 item、一半已知词表均匀采样，无反馈标签参与拟合。下面校准历史长度来自实际 pre-release 捕获；“后续旧状态占比”只是这些预留用户后来真实请求的描述，未参与拟合。

| 首边 | 校准捕获平均长度 | 评测平均长度 | 校准用户后续旧状态占比 | 评测旧状态占比 |
|---|---:|---:|---:|---:|
| Medium | 941.03 | 964.38 | 0.631 | 0.740 |
| Large | 948.78 | 977.07 | 0.680 | 0.729 |
| Max | 948.71 | 967.02 | 0.694 | 0.746 |

Max 校准历史没有出现独有的明显短窗口问题。Max V3→V4 的对应平均长度为 973.77 / 998.31，旧状态占比为 0.669 / 0.728。两类用户在实际候选分布、活动量和标签条件下仍可能不同，完整按类统计保存在 `audit.json`；候选热度仅使用评测期源请求频率作描述，不能解释为发布前热度。所有评测候选都是 target-known，此数据不能判断真正 OOV 冷启动行为。

## 每用户 AUC 与复现

首边具有双类标签、能够定义每用户 AUC 的人数分别为 817 / 1215 / 1539。Max 的 1539 人中，Full 较好 295 人、相同 1040 人、Reuse 较好 204 人；其余 1461 人保持空的每用户 AUC，但全部参与全局 AUC。不能将缺失值填零，也不能用它删除用户。

- `audit.py`：只读生成 15 个面板的完整审计。
- `audit.json`：类条件统计、源/选中 UID 交集、精确请求配对与共同支持重加权。
- `panel_summary.csv`、`per_user_auc.parquet`：全局和全部用户结果。
- `prepare_random.py`：seed17 固定 UID 哈希抽样，排除所有保留校准/验证及预留 UID；选人发生在读取标签与新方法输出之前。
- `random256/{scale}/{edge}/requests.parquet`、`manifest.json`：随机诊断面板及原始 Full/Reuse 双评分来源。
- `expand_random.py`、`random2048/max/v0_to_v1/`：仅首条Max边的固定前缀扩容，原256人的所有请求和控制评分逐项保持相同。
- `random_panel_sources.json`：随机面板、manifest 和 GPU 输出的 SHA256 关联记录。

这些文件是独立诊断，未修改原冻结 3000 用户面板、模型、校准器或历史结果。共同支持重加权是描述性标准化，不是因果估计；单 seed 的实验也不建立跨训练 seed 的统计结论。
