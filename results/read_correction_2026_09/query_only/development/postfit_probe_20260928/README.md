## 定位结果

下面只提炼诊断点；全部 42 个结果及负值都在上述原始记录中保留。

| 配置 | Medium 恢复率 | Large 恢复率 | Max 恢复率 |
| --- | ---: | ---: | ---: |
| 全层，alpha=1 | 44.35% | -145.63% | -48.25% |
| 全层，alpha=0.5 | 24.20% | -62.85% | -20.32% |
| 全层，alpha=0.1 | 4.57% | -10.07% | -3.25% |
| 仅第一层，alpha=1 | 45.44% | -176.66% | -11.61% |
| 仅后两层，alpha=1 | 0.03% | 3.35% | -24.72% |

1. Medium 的该边，第一层主导当前仿射修正的收益，后两层影响很小。
2. Large 的该边，第一层主导损害；仅后两层有很小的正收益。降低全层强度可减轻损害，
   但测过的全层正强度均未变正。
3. Max 的该边，收缩减少损害，但这轮所有 14 个配置仍没有超过 Reuse。
   其 128 用户子集仅有 795 请求，不能将此处的恢复百分比直接推广到原 3k 面板。
4. 响应拟合误差、最终 logit MSE 与排序质量并不等价：Medium 原全层修正的 AUC 提升，
   但到 Full 的 logit MSE 从 Reuse 的 0.05389 上升到 0.06315；
   Large 的 alpha=0.25 把 MSE 从 0.03553 降到约 0.0310，AUC 仍下降。
   因而下一轮需要直接检查最终排序迁移，不能只按中间层 MSE 或最终 logit MSE 选方案。

## 当时提出的后续假设

优先修正校准与实际请求的差异，再扩展校准用户数：

1. **候选/时间分布**：v1 每用户 16 个均匀已知目录候选、查询时刻固定发布时刻；
   实际评价是自然候选与滚动混合缓存。下一版从独立校准用户的合法发布前真实请求/
   候选分布构造校准点，保留历史严格先于对应查询，并记录教师访问成本。
   若纳入混合缓存校准，只用发布前已有事件构造可复现的模拟追加轨迹，不能取评价期
   未来轨迹训练后再回评较早请求。
2. **监督目标**：保留同 q 的逐层响应拟合作为初始化，再探索冻结主模型的最终输出/
   排序蒸馏或层级强度拟合，评价真实 AUC。不能仅凭原始 logit MSE 更小就称排序改善。
3. **层配置**：对第一层、后层和全层等少量候选分别沿各自真实低层路径重新拟合，
   避免把本次后处理裁剪造成的 q 分布偏移当作层能力结论。
4. **用户预算**：沿固定、独立、嵌套的校准 UID 扩展 `C=128/256/512/1024`，
   同时记录用户数、教师/训练成本和推理成本。扩大用户数是可探索方向，当前结果
   尚不能证明单纯增加 C 能修复候选分布或排序目标的偏差。
