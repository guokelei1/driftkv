## 口径

- 恢复率 = `(方法 AUC − Reuse AUC) / (Full AUC − Reuse AUC)`。
  全部 15 条边的 Full−Reuse 分母为正；负值代表方法低于 Reuse。
- 相对成本 = `新增校准与推理 FLOPs / (Full FLOPs − Reuse FLOPs)`。
  这是解析计算量，包含教师访问、拟合、验证和额外推理，不是实际延迟。
- 下列均值按边等权，先算各边恢复率再取平均，不是合并全部请求重算 AUC。
- C 表示校准用户数。H 另有每点 16 名教师验证用户，成本已计入。

## 观察

- Q 的 60 个点中 43 个正恢复，12/15 条边至少一档为正。Medium 20/20 个点为正，
  Large 13/20，Max 10/20。与 v1 相同 C128/C512 的 30 个配对中，25 个 AUC 提高。
  低成本恢复潜力得到一些支持，但 Max 尚弱，三规模不能概括为稳定成功。
- Q 只有 3/15 条曲线逐档不下降；总体均值在 C512 后没有继续提高。
  Medium V3→V4 的 C512 在 6.19% 成本下恢复 59.29%，说明存在有效低成本配置，
  但这一个例子不代表所有边，也不能单独证明相对前四个 baseline 的总体优势。
- H 的 45 个点中 43 个正恢复；C128 与 C512 均为 15/15 正恢复。
  总成本范围 113.12%～807.09%，超过 Full−Reuse 的额外重算计算量。
  Max V0→V1 的 C512 恢复 94.67%，成本 705.96%；Medium V0→V1 同档恢复 112.04%。
  恢复超过 100% 表示该面板上 AUC 超过 Full，不是预测准确率超过 100%。
- H 相对旧的轻量 H，仅 21/45 个相同预算点 AUC 提高，Medium 仅 3/15。
  本轮支持额外用户历史的恢复潜力，尚不能说明更重的历史编码普遍更好，
  也没有达到约 50% 成本实现约 90% 恢复的目标形态。
- 完整成本按每边这 3,000 名用户的请求数摊销校准；服务请求量变化会改变校准摊销项。
  没有用删点、移动横轴或选取最佳点替代完整曲线。
