# Read correction v4（2026-09-29）

本轮已于 2026-09-29 完成。选定的非线性 `map_all` 是当前 H 的基础实现；
后续 C64/C256 补齐及当前 Q-v5/H-v4 总图见[当前结果](../motivation_final/README.md)。
独立 v4 调度和旧 v4 图已退休，校准、读取及完整结果继续保留。

本轮先在 Medium/Large 的四条既定开发边做小实验，再决定完整设置；
Max 正常评测，不依据其质量结果选择方法。论文不改，旧结果和执行来源全部保留。

v3 的高成本主要来自额外训练，恢复未明显提高。本轮测试每请求、每层显式处理完整
用户历史：拼接该位置的所有 head 的 K/V，学习跨 head 变换，得到请求内临时 K/V，
再用当前修正分支实际产生的 q 按原生 ELU+1 算子读取。只有读取响应改变，持久缓存
及随后 append 均不改；没有 Design 的摘要、发布期视图或状态维护。

## 最小线性探针

- 固定开发边：Medium V0→V1、V3→V4，Large V0→V1、V1→V2。
- C128 拟合用户及其后 16 名独立教师诊断用户，每用户等距选最多 128 个合法历史位置。
  这些 UID 与评价面板分离。当前最小方案仅用发布前、位置对齐的 Current−Parent K/V
  差做岭回归（ridge=0.01，FP64 解），不使用反馈标签或最终分数拟合。
- 评价仍为原 3k 面板中固定 hash 的 128 名用户及其全部真实滚动请求。
- 同时记录完整历史映射与仅旧 producer 前缀映射；后者只是诊断候选，不假定新追加
  状态等于 Full，因为它可能继承旧状态的影响。
- Q-v2、旧 H-v1 C512 和 v3 作为已有对照。小样本不替换完整结果。
- 缓存不变、恒等映射、已知教师映射、padding/旧前缀处理和闭式回归数值检查已通过。
  显存分配上限 70%，启动前至少 75% 空闲；四卡独立探针。

纯线性版本的额外推理成本预计约 Medium 39%、Large 50%，另计真实校准开销。
随后实现的候选在同一 token 变换上增加非线性残差；事前预计每请求真实推理成本
约 Medium 59%、Large 75%，另计校准；不通过延长无收益训练来凑横轴范围。
实际方法与规模选择以这轮开发证据决定，不设某条边的质量中断阈值。

代码：`src/hstu_kvcache/read_correction_v4/` 与 `scripts/read_correction_v4/`。

## 已完成的开发探针

以下均为同一组固定 hash 的 128 用户；成本是把真实拟合账本与完整 3k 面板的
历史长度直方图组合得到的投影，不能当作完整 3k 的质量结果。每点全部保留原始预测。

| 开发边 | affine 全历史恢复率 | 非线性全历史恢复率 | 非线性旧前缀恢复率 | 非线性成本投影 |
|---|---:|---:|---:|---:|
| Medium V0→V1 | 89.17% | 95.37% | 82.42% | 63.24% |
| Medium V3→V4 | 90.13% | 90.25% | 88.28% | 64.07% |
| Large V0→V1 | 66.56% | 75.11% | 79.63% | 80.57% |
| Large V1→V2 | 40.65% | 47.59% | 50.06% | 80.46% |

非线性候选冻结 affine，追加 `2D→D/2→2D` SiLU 残差。使用 128 拟合用户、16 独立
验证用户、每用户 16 个均匀已知目录 query，训练 6 轮。损失为归一化 token K/V 残差
与同实际 q 的原生历史读取误差之和；每层由独立验证用户选择 epoch，包含零残差端点。
首次 affine 的每用户 128 个 token 拟合与非线性拟合共用同一次 Teacher 捕获。

非线性相对 affine 四条边均有提升，但两个 Medium 边仍低于旧 H 的同用户结果：
旧 H C512 分别为 108.28%、126.85%。旧 H C512 的两条 Large 为 61.34%、29.81%。
`affine_probe/matched_comparison.json` 保留旧 H C128/C512、Q v2、v3 和新 affine 的
完整配对分析，不能据此宣称新候选普遍优于旧 H。

新增 query 补偿候选在冻结非线性 token 映射后，逐层拟合
`(same-actual-query Teacher read − mapped history read) / history count` 的仿射残差，
然后推进已经修正的下层 query。只使用独立校准用户，验证仅作诊断；不进行分数混合
或按评价标签选层。其成本完整追加到原拟合成本中，缓存捕获不重复计费。

执行来源快照在 `source_snapshots/`，失败和较弱候选均保留。

## 本轮固定选择与全量执行

额外 query 补偿的全历史恢复率为 93.86%、88.71%、75.60%、38.68%，对应上述四条
开发边；其中三条低于不加该层的非线性版本，故正式采用 **affine + 非线性 token 残差**，
不加入额外 query 仿射层。选择先写入 `population_run/plan.json`，随后才运行 Max 资源
探针；Max 的精度不参与这次方法选择。全部补测记录在 `nonlinear_query_probe/`。

正式计划覆盖 Medium/Large/Max 各五条相邻边、每边原来的 3,000 名用户。C128、16 名
独立验证用户、6 轮和实际查询配置全部固定。每边同时报告全历史映射与仅旧前缀映射，
二者都是先执行完整 dense 映射再 gate，所以不虚减旧前缀方案的成本，也不把同成本
的两个点连成预算曲线。本轮先验证这个固定候选；没有通过延长训练增加成本点。

- 校准与探针：`nonlinear_probe/`（四个开发边和 Max 资源探针的拟合可直接复用，费用仍计一次完整拟合）。
- 正式输出：`population_run/evaluation/<scale>/<edge>/`；每 256 用户一个可续跑分片。
- 调度：GPU 0/1/2/3，每卡一条边；Max 较长的任务优先，全部 15 条边均执行。
- 原调度入口 `scripts/read_correction_v4/run_tmux.sh` 已退休；
  driver/stage 日志、退出状态及原始评分仍保留。

真实断点试验通过：64 用户完成后主动终止，续跑补齐 128 用户；已完成分片没有改写，
999 条请求与原连续探针的最大分数差为 7.16×10⁻⁷。记录在
`resource_canary/resume_check.json`。小样本实际摊销成本较高，正式图只纳入完整 3k 用户
的实际成本，不能拿小样本质量和完整面板成本投影拼成正式点。
