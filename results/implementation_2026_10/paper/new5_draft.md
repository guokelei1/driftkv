# 第五章 实现

CacheTide 在发布时准备共享状态，并在用户本版首次推荐或行为写入前物化当前码。服务期间，原生 K/V 与码共同参与纠正读取；新增行为据此生成 K/V，并追加本代零码。下次发布交接时，当前码先用旧发布状态转回锚码，再由新状态提前或按需物化。实现通过共享物品投影减少准备计算、融合读取减少中间张量，并以分块原地转换控制交接空间。

## 5.1 发布与用户码准备

流程的起点是为目标版本准备可读取的码。发布级准备可以跨用户共享，用户级准备则必须访问各自的驻留历史。若把两者混在逐条历史的编码中，同一物品会在不同用户和历史位置上重复投影，逐层执行又会反复读入完整 embedding。实现因此将物品项提前准备，将依赖上下文的 K/V 项留在用户准备阶段。对于第四章的固定坐标编码器，将固定中心和尺度吸收到线性权重与偏置后，有

$$
\eta_i=\operatorname{SiLU}\big([k_i,v_i]W_{\mathrm{KV}}^\star+\phi_\star(m_i)+b_\star\big),
\qquad
\phi_\star(m)=e_\star(m)W_{\mathrm{item}}^\star.
$$

固定物品项 $\phi_\star$ 按物品准备一次，跨用户和后续发布共享；当前发布的物品项 $D_t(m)$ 则由前代物品项与当前模型的 embedding 合成。两张表分别绑定固定坐标函数和当前发布，推荐模型的 embedding 继续正常更新。用户准备时，按物品标识查表，再计算自身 K/V 相关特征，代入第四章的码合成公式。SiLU 仍在 K/V 项与固定物品项相加之后执行，共享准备保留了上下文作用和非线性的位置。

共享表的编译进一步合并跨层计算：将各层物品投影权重沿输出坐标拼接，每个目录块只读取一次完整 embedding，通过一次矩阵乘法产生各层物品项；前代 $D$ 的变换按共享和私有坐标的小块批量执行。发布阶段由此提供可复用的表，用户阶段只处理实际驻留行，无须重复执行完整物品投影。

物品项复用减少逐条历史的重复投影，跨层合并进一步减少 embedding 加载和算子调用，后者保持有效投影的总算术量。当前采用覆盖模型物品 ID 空间的全目录表，不依赖未来请求；其准备计算和常驻共享内存均计入开销。用户特征按需计算并随使用释放，具体转换空间见第5.3节。

## 5.2 服务请求中的融合读取

用户码准备完成后，同一版本内的推荐与行为操作复用这份码，仍需为每个当前 Query 执行动态纠正。直接逐式执行会展开按头码，并生成覆盖全部历史的分数和权重。长历史下，这些中间张量带来额外分配和读写。实现将纠正与原生注意力放在同一历史分块内执行，减少请求路径上的中间结果。

请求侧先计算低维 Query 投影和门控。读取核直接访问原生 K/V、共享码坐标及本头私有码坐标，将码匹配项加入分数后，再执行原生缩放、ELU+1 和可见性掩码。每个块内，原生 Value 与低维码使用同一组注意力权重聚合；遍历结束后，对码聚合施加当前 Query 的 Value 门控，再投影回原生宽度。由此既无需生成逐条历史的高维纠正 K/V，也无需保存完整分数、权重或按头码副本。

门控由本次候选或行为物品的当前表示在线产生。实现对每个候选、每个头计算一次 RMS，再使用拼接的各层 Key/Value 门控权重批量投影；各层参数独立，候选之间保持独立归一化。少量 Query 采用向量规约路径，批量候选采用分块矩阵路径，在同一 Query 块内复用历史，避免单条行为承担较大 Query 块的补齐工作。

推荐在读取后完成评分；行为操作则继续通过当前模型生成新增 K/V，并追加零当前码。读取核利用已知零码后缀边界跳过码运算，原生 K/V 仍正常参与聚合，因果、窗口掩码及原生自注意部分沿用原模型。这样，优化后的读取也参与后续状态生产，形成持续增量服务路径。融合保持原有的有效算术，主要减少中间张量与重复加载，块边界和矩阵补齐仍带来额外工作。

## 5.3 交接时的原地码转换

服务进入下一版本时，仍处于当前码形式的用户码需要用旧发布状态反锚，包括提前物化但尚未读取的码，以及本代新增的零当前码。随后，新版本可以提前或按需从锚码物化。两个方向共用一份持久码缓冲区：实现按层、按历史行块临时生成 $\eta$ 与偏移，算完该块全部输出后覆盖原缓冲区。原生 K/V 和共享表只读，特征与输出工作区由行块大小控制，避免交接或首次使用时分配完整用户码副本。

$P/Q$ 使用共享与私有坐标的小块结构；反锚所需的逆在发布级对实际保存的 $P$ 以 FP64 计算，再以 FP32 保存复用。旧表须保留到依赖它的当前码全部反锚，已经保存锚码的用户无需转换。新旧表并存空间以及追加、FIFO 的临时分配另行计入；单份码约束的是逐行持久状态和上述转换路径。

## 5.4 系统配置与接入

上述流程通过 PyTorch 用户会话与统一历史读取回调接入原生模型，融合读取由 Triton 执行。会话负责发布交接、首次使用前的码物化及 FIFO，回调将同一纠正读取用于推荐评分与增量行为编码。CPU 维护行为顺序、物品标识和版本元数据；GPU 保存模型、原生 K/V、码及共享表。每个服务副本加载共享发布状态，加载时检查模型、校准参数、固定特征与物品 ID 空间的兼容性。

当前配置采用六头、每头32维，每层每行48个码坐标，每头读取共享3维和私有3维。用户转换行块为128，目录块为16,384，推荐候选批为16，均为执行粒度配置。用户状态记录码形态、版本及零码后缀边界，使准备、读取和交接访问同一组对齐的 K/V 与码行。

原生缓存和码使用 FP32 存储。小 Query 核采用 FP32 乘法与规约，矩阵核采用 TF32x3 乘法近似、FP32 累加，因而按数值容差而非逐位相同要求一致性。当前优化覆盖无相对位置偏置的 ELU+1 无梯度推理，校准仍使用可微 PyTorch 路径；后端显式选择，不支持的配置明确报错。原型以同步用户操作完成接入，尚不包含分布式并发发布与故障恢复。
