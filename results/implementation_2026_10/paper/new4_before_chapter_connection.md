# 第四章 CacheTide 设计

本章介绍 CacheTide 如何在连续模型发布中复用历史 K/V 缓存，并支持后续行为追加。

## 4.1 设计概览

模型更新后，新模型仍要读取此前保存的用户历史。重新编码这些历史会重复计算，直接读取旧 K/V 又可能偏离新模型重建历史时的响应。CacheTide保留原生 K/V，并维护紧凑码。读取时，系统根据当前候选物品，利用紧凑码调整历史匹配分数和聚合内容，从而纠正新模型的历史读取。

每次发布前，系统选取少量用户，将实际保留的缓存与新模型重建的缓存配对，学习码的更新规则和读取参数。部署后，请求复用已经准备好的码，并由当前候选物品决定本次纠正。发生新行为时，当前模型同样读取这些历史，再生成并追加新的 K/V。这样，发布前学习的纠正既服务于当前推荐，也支持历史继续增长。

后续发布继续保留原生 K/V，更新码及其读取参数。CacheTide 将多次码更新合并，使用户即使缺席若干次发布，返回时也能直接准备最新码，无需逐版重放。

下文依次介绍请求中的读取纠正（第 4.2 节）、连续发布下的码更新与状态维护（第 4.3 节），以及两部分参数的发布前联合校准（第 4.4 节）。

## 4.2 用紧凑码纠正历史读取

注意力读取包含两项工作：Key 决定当前 Query 如何匹配历史，Value 决定匹配之后取回什么内容。CacheTide 用紧凑码为这两项工作提供纠正信息。

*（配图说明：此处放置“紧凑码的生成与结构”示意图。左侧以同一用户某层的一条继承历史为例，将原生 K/V、对应历史物品的信息和已有码状态作为三路输入，送入参数跨用户共享的“码生成模块”，输出当前紧凑码。模块内标出两类历史特征提取分支：共享分支读取全部头的 K/V，私有分支各读取本头的 K/V，两者都使用对应历史物品的完整固定表示；这些特征再与已有码状态和该历史物品的当前表示共同用于生成当前码，具体更新规则留在第 4.3 节展开。右侧放大输出码，将其画成一份共享段和各头的私有段：六个头时，共享段 12 维、每个私有段 6 维，完整码共 48 维；一般宽度为 $12+6H$，其中 $H$ 为头数。再以两个头为例，用“固定选取坐标”展示它们如何从同一个共享段和各自的私有段取出读取码。共享段只画一份；每头最多可选 18 个坐标，实际读取可以更少，未选中的坐标仍保留并参与后续版本更新。）*

如图所示，紧凑码是与原生 K/V 对齐保存的低维辅助表示。它由跨用户共享的码生成模块准备：模块结合保留的 K/V、对应历史物品的信息和已有码状态，输出供当前模型使用的码。系统用新模型重建的历史学习码的生成规则和读取参数（第 4.4 节）；跨版本的更新与合并规则见第 4.3 节。

如图所示，码生成模块在提取历史特征时，共享分支联合读取同一条历史在所有头中的原生 K/V，私有分支只读取本头的 K/V；两者都结合该历史物品的完整固定表示。共享分支使各头能够利用跨头的历史线索，私有分支则保留本头的细节。由此，共享码集中保存供各头复用的信息，私有码为各头不同的读取纠正需求保留独立容量，在控制存储开销的同时保留头间差异。

**候选请求到来时。** 当一个候选进入评分流程时，当前模型需要从用户历史中取得与该候选有关的信息。CacheTide 将保留的 K/V 与紧凑码共同用于这次注意力读取：历史 Key 和码一起确定匹配分数，历史 Value 和码一起形成取回的内容，最终得到供模型继续评分的历史响应。

本次请求沿当前模型的原有路径生成 Query，保留时间、行为类型和历史上下文。同时，系统根据候选物品的当前表示计算两组门控系数，分别控制码如何参与匹配和内容聚合。读取历史时，Query 与原生 Key 的匹配构成基础分数，码提供候选相关的补充；得到的权重随后用于汇总原生 Value 和码，形成输出。因此，在复用相同历史 K/V 和码的情况下，匹配权重与读取内容仍能随候选变化。

**Key 侧：共同计算注意力分数。** 以下以一层中的一个头为例。当前 Query $q$ 与第 $i$ 条历史的原生 Key $k_i$ 给出基础分数 $q^\top k_i$。该头还从共享部分和自己的私有部分取出读取码 $z_i$，用它补充候选与这条历史的匹配。

为让 Query 与码匹配，投影 $P_K$ 将 $q$ 降到码的宽度，再由本次候选的 Key 门控 $g_K$ 调整各维，得到 $\tilde q=(P_Kq)\odot g_K$，其中 $\odot$ 表示逐维相乘。最终的历史匹配分数为

$$
s_i=q^\top k_i+\tilde q^\top z_i.
\tag{4-1}
$$

本次候选的 $g_K$ 由各条历史共用，但不同的 $z_i$ 会给出不同的分数补充。原生 Query $q$ 继续匹配原生 Key，$\tilde q$ 则匹配码。系统按当前模型的缩放、激活和可见性掩码，将合并后的分数转换为注意力权重 $\alpha_i$，用于接下来的内容聚合。

**Value 侧：共同形成读取内容。** 得到权重后，系统用同一组 $\alpha_i$ 分别汇总原生 Value $v_i$ 和读取码 $z_i$。Value 的加权和提供原有的历史内容，码的加权和则提供附加信息。当前候选的 Value 门控 $g_V$ 调整这些附加信息，再由投影 $P_V$ 将其从码的宽度映射回原生 Value 宽度，与原有内容相加：

$$
o=\sum_i\alpha_i v_i+P_V\!\left(g_V\odot\sum_i\alpha_i z_i\right).
\tag{4-2}
$$

两个加权和使用的是 Key 侧共同确定的历史权重；$g_V$ 调整码带来的内容补充，不另行分配历史权重。所得 $o$ 是该头面向当前候选的历史响应，随后继续进入当前模型。

上述两组门控在各头内独立计算：对候选物品表示做 RMS 归一化后，分别经过 Key、Value 的线性变换和 $1+\tanh(\cdot)$，得到与读取码同宽的系数。

**联合读取的作用与开销。** 这一过程保留原生 K/V 的数值及基础匹配、聚合计算，并通过紧凑码引入候选相关的补充。两个投影及生成门控的参数在发布前校准，同一服务版本内固定。行为追加以本次行为物品沿用相同路径。

Query 投影和门控每次读取只计算一次，K/V 与码可以在同一次历史遍历中处理，码聚合后只需一次回投影，无需逐条历史执行请求相关的非线性编码。门控固定时，纠正可折成固定的有效 K/V；随候选变化时，一般无法预先合并，因此系统复用历史码，在本次读取中形成具体纠正。

## 4.3 连续发布中的码更新与维护

第 4.2 节给出了如何使用当前码读取历史，连续发布还需要明确码如何随版本更新。行为追加会使窗口包含不同版本生成的 K/V，而这些行都需要面向当前模型的码。用户也可能缺席若干次发布；若一直保存旧版本使用的码，返回时便需要逐版更新，或继续保留解释旧码所需的参数。

**可合并的码更新。** 以下以一层中的一条历史为例，省略用户和条目下标，$m$ 表示该历史物品。每次发布的单步更新为

$$
c_t=A_tc_{t-1}+B_t\eta+h_t(m).
$$

其中，$c_{t-1}$ 是上一服务版本使用的码，$\eta$ 是从原生 K/V 与完整固定物品表示提取的特征。$A_t$ 变换旧码，$B_t$ 调整历史特征的作用；物品项 $h_t(m)=H_te_t(m)+b_t$ 使用当前模型的物品表示 $e_t(m)$。这些参数在第 4.4 节与读取参数一起校准。

更新结构在校准前确定：$A_t,B_t$ 按共享部分和各头私有部分分块，$A_t$ 采用可逆的块正交形式；固定特征编码器在后续发布中保持不变。该约束仅作用于码更新，读取中的候选门控仍可非线性。由于更新对旧码和固定特征保持仿射，多次学得的更新可以在发布时合并：

$$
\begin{aligned}
P_t&=A_tP_{t-1},\\
Q_t&=A_tQ_{t-1}+B_t,\\
D_t(m)&=A_tD_{t-1}(m)+h_t(m).
\end{aligned}
$$

$P_t,Q_t,D_t$ 从 $P_0=I,Q_0=0,D_0=0$ 开始累积，由单步更新参数计算，不另行拟合。它们承载版本变化，每条历史则保存一份同宽的固定输入状态，称为锚码 $a$。当前码由锚码、固定历史特征和本版物品项构造：

$$
c_t=P_ta+Q_t\eta+D_t(m).
\tag{4-3}
$$

跨发布时，每行只保留锚码；历史特征可从已有输入重算，版本参数由用户共享。锚码根据当前码、该行输入与对应版本参数反算得到，无需单独训练。首发前未纠正的源状态以零锚码为起点。

读取历史前，系统先按行计算 $\eta$，再完成两次小矩阵乘法和一次物品项查表，将三项相加，得到供第 4.2 节使用的当前码。结果覆盖原码缓冲区，同版后续请求直接复用。不同版本生成的行使用自己的锚码和历史特征，由同一套当前参数构造码；用户跨过多次发布后也无需生成中间版本码。准备成本包含固定特征计算，随历史长度增长，而不随缺席发布数增长。合并等价以存活原生行、物品标识和固定特征不变为前提，跨发布的读取质量仍需独立检验。

## 4.4 在发布前联合校准

每次发布前，CacheTide 联合训练第 4.2 节的读取纠正参数和第 4.3 节的码更新器。更新器先将旧码变为当前码，当前码参与纠正读取；两个训练阶段分别以重建历史的读取响应和评分为监督，共同更新这两部分参数。以下用 MSE 表示对样本和输出分量取平均的平方误差。

**训练对象与样本。** 本次可学习参数包括 $A_t,B_t,H_t,b_t$、Key/Value 读取投影及候选门控参数。校准期间，推荐模型及当前物品表示、输入的源 K/V 与旧码、过去的发布参数和教师状态均冻结。固定历史特征编码器在初始化时通过同类读取与评分监督建立，后续发布保持不变。当前码是更新器计算的中间结果，不作为逐用户独立优化的变量。

训练使用少量用户在发布前已发生的历史。系统保留上一服务版本实际可用的 K/V 与码，并用当前模型重建相同历史，得到教师缓存；两套缓存配合同一组已知候选形成样本，无需未来请求标签。源 K/V 可以来自不同生产版本，但输入码统一面向上一服务版本；本次学习的是这份服务状态到当前教师的接续。拟合、选参与独立质量验证分别使用不同用户。

**第一阶段：逐层对齐读取。** 从低层向高层推进，每次优化一层的更新器与读取参数。系统固定已校准的低层路径，取得当前层的 Query，再用同一个 Query 分别读取源缓存与教师缓存。两条响应按相同的历史长度和固定头尺度归一化后，记为 $r$ 与 $r^\star$，训练目标为

$$
L_{\mathrm{read}}=\operatorname{MSE}(r,r^\star).
$$

头尺度由拟合用户长度归一化后的教师与原生读取残差的 RMS 确定并固定。梯度经过当前码回传到本层更新参数；捕获的 Query 与教师目标保持固定。

**第二阶段：联合对齐评分。** 沿完整推荐路径共同调整所有层的更新与读取参数。对同一用户历史和候选，学生分别直接读取完整源历史，或留出已观察历史的短尾、先纠正读取前缀再因果续写尾部，得到原始评分 $y$ 与 $y'$。两者都对齐当前模型重建完整历史后的同一教师评分 $y^\star$：

$$
L_{\mathrm{score}}
=\tfrac12\operatorname{MSE}(y,y^\star)
+\tfrac12\operatorname{MSE}(y',y^\star).
$$

没有可用短尾的样本只使用直接读取项。模型权重虽冻结，评分梯度仍穿过模型计算和续写的新增 K/V，回传至更新器与读取参数，使监督覆盖纠正读取对后续状态的影响。两项目标分阶段使用，不另设码数值或跨版本合成的训练目标。校准结束后，系统按第 4.3 节合并本次更新，在线仅准备和读取码，不继续优化参数。

**服务与成本细节。** 缓冲区记录码的形式和版本，推荐与行为追加均先准备当前码，活跃用户可提前准备；交接期间新旧表并存。新行为读取当前历史后，追加当前模型生成的原生 K/V 和零当前码，其锚码一般不为零；FIFO 同步移除 K/V 和码，已知零码后缀可跳过码运算。窗口可混合不同版本的行，新行也可能继承读取误差，因此校准使用实际状态并加入短尾续写。每行只存一份定宽码；全局固定编码器、物品表、发布表及读取参数，以及准备计算、在线纠正、过渡双表和临时张量均需计入成本。物品项可共享准备，历史特征仍按用户行计算。合并要求存活原生行、物品 ID 空间、模型结构及条目语义稳定；代数等价不保证长期读取质量，块正交与实际求逆也无法消除长期偏移造成的有限精度抵消。
