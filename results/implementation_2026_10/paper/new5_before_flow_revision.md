# 第五章 实现

CacheTide 的实现围绕两项主要开销展开：码准备中的宽维物品投影，以及读取纠正产生的中间张量。此外，码形态转换需要受控的临时空间，纠正路径也需要接入原生增量读写。本章说明这些计算如何组织，沿用第四章的模型、训练目标和码更新规则。

## 5.1 共享码准备

码准备同时依赖原生 K/V 和完整物品表示。若逐条历史执行编码，同一物品会在不同用户和历史位置上重复投影，逐层执行又会反复读入完整 embedding。实现将可共享的物品项与依赖用户上下文的 K/V 项分开。对于第四章的固定坐标编码器，将固定中心和尺度吸收到线性权重与偏置后，有

$$
\eta_i=\operatorname{SiLU}\big([k_i,v_i]W_{\mathrm{KV}}^\star+\phi_\star(m_i)+b_\star\big),
\qquad
\phi_\star(m)=e_\star(m)W_{\mathrm{item}}^\star.
$$

固定物品项 $\phi_\star$ 按物品准备一次，跨用户和后续发布共享；K/V 项仍按用户的实际历史计算，两项相加后再执行 SiLU。因此，共享物品投影不会消除历史上下文的作用，也不改变非线性的位置。当前发布的物品项则由 $D_t(m)$ 保存，在发布时由前代物品项与当前模型的 embedding 合成。固定表绑定初始坐标函数，$D_t$ 随发布更新，当前推荐模型的 embedding 继续正常更新。

共享表的准备也存在跨层重复加载。实现将各层的物品投影权重沿输出坐标拼接，每个目录块只读取一次完整 embedding，通过一次矩阵乘法产生各层物品项；前代 $D$ 的变换按共享和私有坐标的小块批量执行。用户准备码时查取对应物品项，再与自身 K/V 特征合成，无须逐条历史重复计算完整物品投影。

物品项复用减少逐条历史的重复投影，跨层合并进一步减少 embedding 加载和算子调用，后者不改变有效投影的总算术量。当前采用覆盖模型物品 ID 空间的全目录表，不依赖未来请求；表的准备计算和常驻共享内存均计入系统开销，目录分块只限制准备过程的临时空间。

## 5.2 与原生注意力融合的读取

读取纠正需要与当前 Query 交互，但直接逐式执行会先展开按头码，再生成覆盖全部历史的分数和权重。对于长历史，这些中间张量会带来额外分配和读写。实现将纠正计算与原生注意力放在同一历史分块内执行，使动态纠正保留在读取路径中，同时避免物化完整历史的中间结果。

请求侧先计算低维 Query 投影和门控。读取核直接访问原生 K/V、共享码坐标及本头私有码坐标，将码匹配项加入分数后，再执行原生缩放、ELU+1 和可见性掩码。每个块内，原生 Value 与低维码使用同一组注意力权重聚合；遍历结束后，对码聚合施加当前 Query 的 Value 门控，再投影回原生宽度。由此既无需生成逐条历史的高维纠正 K/V，也无需保存完整分数、权重或按头码副本。

门控由本次候选或行为物品的当前表示产生。实现对每个候选、每个头计算一次 RMS，再使用拼接的各层 Key/Value 门控权重批量投影；各层参数独立，候选之间也保持独立归一化。发布级准备只整理读取投影参数和码坐标，依赖当前输入的投影与门控仍在线计算。

行为追加通常只有少量 Query，推荐则包含一批候选。前者采用向量规约路径，避免为单条行为补齐较大的 Query 矩阵块；后者采用分块矩阵路径，在同一 Query 块内复用历史。对于本代新增的已知零码后缀，读取核跳过码运算，原生 K/V 仍正常参与聚合；因果、窗口掩码及原生自注意部分沿用原模型。融合保持原有的有效算术，主要减少中间张量与重复加载；块边界和矩阵补齐仍带来额外工作。

## 5.3 分块原地码转换

只保存一份持久码，并不自动保证转换时没有完整副本。实现按层、按历史行块临时生成 $\eta$ 与偏移，算完该块全部输出后覆盖原缓冲区，随后释放临时特征。原生 K/V 和共享表保持只读，转换工作区由行块大小控制，而不随完整历史长度增长。

$P/Q$ 使用共享与私有坐标的小块结构；反锚所需的逆在发布级对实际保存的 $P$ 以 FP64 计算，再以 FP32 保存复用。这些安排控制转换空间和重复准备，不改变码更新规则。行为追加、FIFO 以及新旧共享表交接的临时或并存空间另行计算。

## 5.4 系统配置与接入

原型基于 PyTorch 增量推荐模型，融合读取由 Triton 在 GPU 上执行。CPU 维护行为顺序、物品标识与版本元数据；GPU 保存模型、原生 K/V、码和共享物品表。每个服务副本加载一份共享发布状态，用户分别维护与 K/V 对齐的码、码形态及零码后缀边界；加载时检查模型、校准参数、固定特征及物品 ID 空间的兼容性。

纠正路径通过统一历史读取回调接入原生增量编码。推荐查询和行为写入共用该路径：推荐候选不写入缓存，新增行为由当前模型读取已纠正的历史后生成 K/V，并追加本代零码；FIFO 同步维护原生行与码行。当前配置采用六头、每头32维，每层每行48个码坐标，每头读取共享3维和私有3维。用户转换行块为128，目录块为16,384，推荐候选批为16，均为执行粒度配置。

原生缓存和码使用 FP32 存储。小 Query 核采用 FP32 乘法与规约，矩阵核采用 TF32x3 乘法近似、FP32 累加，因而按数值容差而非逐位相同要求一致性。当前优化覆盖无相对位置偏置的 ELU+1 无梯度推理，校准仍使用可微 PyTorch 路径；后端显式选择，不支持的配置明确报错。原型以同步用户操作完成接入，尚不包含分布式并发发布与故障恢复。
