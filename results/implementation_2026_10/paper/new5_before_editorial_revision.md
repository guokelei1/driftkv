# 第五章 实现

CacheTide 将发布时的共享准备、用户码状态转换和请求中的历史读取分开实现。共享准备不读取用户历史，用户码转换按需访问原生 K/V；请求读取复用已经准备的码。实现保留第四章的模型、训练目标和码更新规则，通过复用物品侧计算、融合历史读取及限制转换临时空间降低工程开销。

## 5.1 共享码准备

完整物品表示参与码生成，但不必为每条历史重复执行宽维物品投影。对于第四章的固定坐标编码器，将固定中心和尺度吸收到线性权重与偏置后，按输入来源拆分为

$$
\eta_i=\operatorname{SiLU}\big([k_i,v_i]W_{\mathrm{KV}}^\star+\phi_\star(m_i)+b_\star\big),
\qquad
\phi_\star(m)=e_\star(m)W_{\mathrm{item}}^\star.
$$

固定物品项 $\phi_\star$ 只准备一次，跨用户和后续发布共享；K/V 项仍按用户的驻留历史计算。SiLU 保留在两项相加之后，后续码空间变换仍作用于激活后的特征，不跨越非线性合并。相同物品在不同历史上下文中因此仍可生成不同特征。候选门控使用的动态 RMS 也保留在线计算，不按固定归一化折叠。

当前发布的物品项使用另一张表 $D_t(m)$。发布时，从上一张表和当前物品表示分块合成新的表；用户准备码时直接查表，无须再次为每条历史计算当前物品投影。两张表的生命周期不同：固定表绑定初始坐标函数，$D_t$ 绑定当前发布；当前推荐模型的物品 embedding 继续正常更新。

为减少重复读入和小矩阵调用，实现将各层的物品投影权重按输出坐标拼接。每个物品块只读取一次完整 embedding，通过一次矩阵乘法产生各层物品项，再分别与相应历史项合成。上一版 $D$ 的变换按共享和私有坐标的小块批量执行。全目录表覆盖模型的物品 ID 空间，不依赖未来用户请求；其准备计算和共享内存均计入开销。目录分块限制的是编译工作区，两张完整输出表仍占共享空间，不将批内去重再次计算为投影节省。

## 5.2 与原生注意力融合的读取

直接逐式执行第四章的读取公式，会生成按头展开的码、完整分数和权重等中间张量。实现先在请求侧准备低维 Query 投影和门控，再按历史块读取原生 K/V 与对应码，在块内完成匹配纠正、原生注意力激活和两类聚合。每个块同时累计原生 Value 与低维码，历史遍历结束后再将码聚合投影回原生宽度，无须生成逐条历史的高维纠正 K/V。

门控输入是本次候选或行为物品的当前表示，同一操作内先按候选、按头计算一次 RMS，再使用拼接的各层 Key/Value 门控权重批量投影。各层保留独立参数，候选之间不混合归一化或门控值。读取投影参数和所需码坐标在加载发布参数时整理，Query 投影仍在线计算；内核直接寻址共享坐标与本头私有坐标，避免先复制一份按头展开的历史码。

实现分别适配小 Query 操作与批量候选。Query 数不超过四时，每个 Query、每个头使用向量规约路径，避免将单条行为补齐到较大的 Query 矩阵块；较大候选批使用矩阵分块路径，在同一 Query 块内复用历史数据。当前矩阵路径采用 Query 块16、历史块64；不同 Query 块仍可能重复读取历史，码宽和边界补齐也存在额外指令工作，不将逻辑 FLOPs 等同于硬件执行量。

内核沿用原生缩放、ELU+1 和可见性掩码：码匹配项先加入分数，再进行激活；行为写入继续屏蔽未来位置和窗口之外的位置。原生自注意部分按原模型路径处理。对于本版本新增的零码后缀，使用前缀边界跳过码点积和码聚合，原生 K/V 读取仍覆盖全部可见行。零码跳过由已知协议决定，不通过近似阈值省略非零纠正。

## 5.3 分块原地码转换

锚码与当前码共用一份持久缓冲区，转换时也无需复制一份完整用户码。实现按层、按历史行块读取原生 K/V 和物品项，临时生成该块的 $\eta$ 与偏移，完成小块矩阵变换后覆盖原缓冲区。每个输出块的全部坐标在覆盖前计算完成；原生 K/V、物品 ID 及共享发布表只读。$\eta$ 随块释放，不作为第二份逐行状态保存。

$P/Q$ 按共享12维与各头私有6维的结构计算，不为每行执行通用稠密48维变换。反锚所用逆矩阵在发布级准备一次：对实际保存的 $P$ 小块使用 FP64 求逆，再以 FP32 保存并复用。这样避免将有限精度连乘后的转置直接当作精确逆；长期偏移增长与相消误差仍需单独检验。

行块大小限制额外特征与转换输出的临时空间，而不改变码宽或转换规则。只有其当前码全部完成交接后，旧发布状态才可退休；新旧共享表的并存空间单独计算。原地覆盖约束的是码形态转换；行为追加与 FIFO 的临时分配继续由增量缓存接口管理。

## 5.4 系统配置与集成

原型基于 PyTorch 增量推荐模型，在 CUDA 端使用 Triton 实现融合读取核。CPU 维护行为时间顺序、物品标识与用户版本元数据；GPU 保存模型、原生 K/V、码及共享物品表，码准备时按需传入对应行的标识。每个服务副本加载一份共享发布状态，用户之间复用表和参数，各自维护原生状态与码。

实现通过统一历史读取回调接入原生增量编码路径，推荐查询和行为写入使用同一套纠正读取。原生投影、模型块、评分与 FIFO 规则保持原定义；推荐候选不写入 K/V，新增行为按当前模型读取已纠正的历史后写入原生状态，并追加本代零码。每个用户保留与 K/V 行对齐的码缓冲区、当前码／锚码形式及已知零码后缀的前缀边界，共享物品表和发布参数由服务副本统一加载。

加载时绑定模型、校准参数、固定特征签名、物品 ID 空间及 $P/Q/D$，在准备用户状态前检查兼容性。当前优化路径覆盖无相对位置偏置的原生 ELU+1 读取，支持六头、每头32维、每层每行48个 FP32 码坐标，读取共享3维和本头私有3维；其余码坐标仍参与版本演化。默认用户行块128、目录块16,384、推荐候选批16，均为执行粒度配置。改变粒度不改变学习机制，但需要核对相应数值与资源边界。

原生缓存和码使用 FP32 存储。小 Query 核采用 FP32 元素乘法与规约，矩阵核采用 TF32x3 乘法近似并以 FP32 累加，因此与参考实现保持数值容差意义上的一致性，不要求逐位相同。后端显式选择；不支持的形状、激活或训练模式明确报错，不在后台静默切换。校准继续使用可微 PyTorch 路径，Triton 读取与原地码转换用于无梯度推理。当前原型按同步用户操作验证接入与状态交接，不据此宣称已实现分布式并发发布或生产环境吞吐保证。
