# 共享准备与码生成的实现核验

本轮沿用冻结的 `A_itemgate6_rms_roll4`，没有训练、改变特征、选择用户质量或替换旧发布文件。实现位于 `scripts/implementation_2026_10/prepare.py`；GPU1上的真实物品子集检查通过后，执行完整目录V3→V4→V5连续编译，结果保存在本目录。最终权威结果为 `final_real_subset/summary.json` 和 `final_full_catalogue/summary.json`，包含冻结参数、模型、原发布表及最终源码SHA。较早的 `real_subset/`、`full_catalogue/` 是补充兼容检查前的执行，保留为过程记录，不代替最终绑定。

## 计算如何放置

固定特征保持 `eta = SiLU((nativeKV @ W_native + phi_star(item)) + bias)`。`phi_star=e_star @ W_item` 跨用户、跨后续发布共享；固定仿射归一化已包含在有效权重中，bias单独保留。不同原生行仍分别做native投影和SiLU，不把非线性后的Q变换移到SiLU之前，也不持久保存eta。

当前发布共享项为 `D_t=A_t D_previous+H_t e_t+b_t`。当前模型embedding仍更新。实现将六层物品权重沿输出维拼接，对每个物品chunk只lookup和投影一次；D历史项仍按共享12/私有6的小块计算，并沿层维批处理，避免稠密48×48投影浪费零块算术。固定phi和D具有不同生命周期，不能共用旧表。

连续编译在执行lookup前检查前代固定特征语义：feature mode、摘要宽度以及固定bank SHA或native basis必须兼容。缺少层元数据、缺少bank SHA和同shape不同特征均明确拒绝；这些检查不改变有效路径的浮点运算。

`native_feature_chunks` 按用户原生行产出临时eta；一次反锚或物化内的P/Q运算复用这份特征。按既有理论口径，每行eta为84,384 FLOPs；若按两个块矩阵乘法、两次向量加法计算，完整一次转换为93,600 FLOPs。旧完整成本函数为转换保守计入三次向量加法，得到93,888 FLOPs，本轮不重写这份既有账。如果逐行重复计算完整物品投影，会额外增加110,592 FLOPs。这是共享准备相对朴素逐行执行的计算差异，**当前方法的原成本已经包含共享准备，不能再从17.38%的预算中重复扣除**。

## 核验结果

- CPU检查12项通过，覆盖FP32/FP64固定特征、三次发布合成、实际算术账、SiLU不能跨越发布变换的反例，以及7种不兼容或缺失元数据的负例，见 `final_cpu_tests.log`。
- 真实子集为种子固定的4,092个唯一物品，包括PAD及最大模型ID，不依据请求或未来标签选择。各版D与原逐层编译的最大差为0。
- 全目录为1,380,766个模型物品ID；新V4/V5从新V3/V4表接续，未复制旧D作为结果。完整D最大绝对差为V3的7.15e-7、V4/V5的9.54e-7，相对L2均小于1.3e-8；P/Q逐位一致。
- 重新拼接计算的完整固定phi表最大差7.63e-6，相对L2约1.52e-8。将新表用于8名冻结fit源状态的7,510个原生行，eta最大差3.81e-6，相对L2均小于8e-8。误差来自GEMM形状与求和重排；没有改变非线性或归一化语义。

## 工程收益和边界

每个全目录投影仍是152.70GF；D发布准备仍分别为153.0994/159.4620/159.4620GF，与原发布账逐项相同。新实现减少的是重复embedding读取与操作调度：每版lookup/物品投影调用从510降到85，理论embedding读取payload从6.363GB降到1.060GB；有上一代D时小块运算调用从3,570降到595。Payload不是物理DRAM流量，后者受缓存影响。

4,092物品的隔离CUDA准备（2次warmup、5次重复、FP32且关闭TF32）中，逐层参考中位数约9.60–9.66ms，拼接实现约7.59–7.60ms，约1.26–1.27倍。该小测对各版当前参数使用首份发布路径，不含旧D合成；完整连续编译另通过数值和成本检查。不能据此声称完整服务吞吐或p99改善。final_full_catalogue中的单次完整编译耗时也不是与原publication CLI端到端耗时的公平对比，后者包含加载、SHA和保存。

固定phi表及每份D表各为1,590,642,432字节。分块限制临时projection张量，不能消除常驻共享表；新旧D交接仍需要两份D。核验进程峰值约5.99GB CUDA allocated，属于此进程比较工作集，并非实际部署稳态/过渡峰值。完整目录已覆盖全部物品，不存在投影miss，不能再叠加“批内去重”浮点收益。对有限表或按需准备可另行考虑去重，但本轮没有引入该分支。

复现：

```bash
env OMP_NUM_THREADS=2 MKL_NUM_THREADS=2 python scripts/implementation_2026_10/run_prepare.py --gpu 1 --full-catalogue --output <new-result-directory>
```
