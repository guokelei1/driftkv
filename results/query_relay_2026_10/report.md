## 机制

D1 保留原生 K/V，每层每条历史仅维护一份48维码，布局为共享12＋6个头各私有6。为了控制所有行为写入的成本，目前每头读取共享3＋私有3，其余码维度通过更新矩阵参与后续演化；这明确是读取容量的退让，不声称完整18维已经满足预算。

当前候选使用本次候选物品（行为写入时则为本次行为物品）的 Current 完整 embedding `u(q)`，重排到各头后计算 `g(q)=1+tanh(U·RMS(u(q)))`；各层的原生 `q`、打分投影和注意力仍正常运行。物品向量是 Query 已知内容，不包含未来标签。这避免原生 query 中公共 type/action 特征淹没候选差异；没有新增网络、参数、训练目标或逐条目状态。额外 embedding lookup 的流量单独报告。在 Key 修正投影与 Value 修正聚合上分别门控：

\[
 s_i(q)=q^\top k_i+[(D_Kq)\odot g_K(q)]^\top z_i,
 \qquad
 o(q)=\sum_i\alpha_i(q)v_i+D_V[g_V(q)\odot\sum_i\alpha_i(q)z_i].
\]

因此，一份固定原生K/V与码会对不同Query给出不同修正；一般不能等价为原生Query空间中的固定有效K/V。结构具备这种能力，不意味着训练必然让它带来显著质量收益，必须单独消融。原生历史循环不包含逐条目非线性：Query端只算一次门控；码仍线性参与打分与聚合，可在一次历史扫描中计算。当前是普通PyTorch参考实现，未证明加载系统吞吐或p99优势。

此处动态性具体指Query的候选物品内容：同一物品的时间/type/action变化不会直接改变item gate，仍由原生query/模型处理。固定候选物品时可以写出其条件有效K/V，跨候选通常不能用同一份固定有效K/V表示；门控学成常数或作用方向被抵消时则可能退化。“没有新增参数”限定为相对上一门控候选只更换输入，不能理解成相对无门控KV映射完全没有额外参数。

D2 每次发布只校准到当前教师，先逐层读取对齐，再用冻结完整推荐模型的最终分数对齐。训练数据来自已经发生的行为及该候选自己的连续缓存轨迹。完整分数阶段同时使用静态历史与4步因果续写两种视图，目标仍为相同教师分数，不增加在线判定器、未来反馈标签或服务教师。后续来源里可以有不同出生版本的原生K/V；它们已有上一服务版本的码，更新器学习的是**上一服务状态到当前读取**，并未证明原生K/V都被改造成了上一版Fresh。

局部对齐按历史长度归一化，并用fit集原生/教师读取残差的尺度平衡各头；联合阶段拟合教师原始logit，不加排序标签或额外动态性目标。两阶段简单指目标和服务依赖简单，不等于纯新旧K/V逐项回归。首版还继承既有编码器训练、16名validation用于选轮次，其费用与角色均保留，不能当独立验证。

这避免为每种出生版本分别训练和串接读取器，但不消除源状态分布的异质性。校准仍需使用真实连续轨迹，前版码作为既有兼容状态输入；48维摘要和仿射更新是否足够是实证问题，而不是“单跳”一词带来的保证。固定η及稳定ID空间换来了直接合成，也限制了未来可适应的漂移形态。

D3 要解决的是：同一原生历史可能跨过多个发布，逐版串行运行旧编码器会让冷用户的准备成本随缺席版本数增长；改写K/V又会丢掉D1的读取机制。A分支让跨版本更新仅在紧凑码空间递推：

\[
 c_i^{(t)}=A_t c_i^{(t-1)}+B_t\eta(x_i)+H_t(e_t(m_i)).
\]

其中 `x_i` 是存活条目的原生K/V与固定物品ID；`η`是冻结的首版小编码器特征，包含冻结的首版物品投影，其值只在准备码时重算，不作为逐条目持久状态。当前模型和物品embedding仍在查询、写入与 `H_t` 中正常更新。B分支额外增加与固定原生摘要的乘性交互；它没有明显必要性，成本更高。

由于更新对旧码和固定特征保持仿射形式，可在发布时合成共享 `P_t,Q_t,D_t(m)`，从锚码直接得到最新码：

\[
 c_i^{(t)}=P_t a_i+Q_t\eta(x_i)+D_t(m_i).
\]

这里合成的是小码状态的演化，不是把过去的动态读取改成静态K/V，也不是保证任意多版教师漂移都能被准确修复。服务只用当前读取参数，冷用户无需逐版执行旧更新器。

合成成立依赖三个具体条件：存活条目的原生K/V与ID不改写，固定特征函数不随发布变化，码更新对旧码保持仿射。令`P_t=A_tP_{t-1}`、`Q_t=A_tQ_{t-1}+B_t`、`D_t=A_tD_{t-1}+H_t(e_t)`，代入上一版公式即可得到当前版公式；与门控是否非线性无关。门控属于当前读取器，更新只在码空间进行，因此不需要合成历史的Query函数。这个等式保证跳过发布的准备结果与相同原生状态上的逐版码更新一致，不能保证教师质量无限保持。

每个用户只有一份码缓冲区：活跃时保存当前码，发布时转换为锚码；没有行为和请求的用户保留锚码，下一次任何历史读取（包括行为写入）直接准备最新码。新行为在当前模型下通过**纠正的历史读取**生成原生K/V，在本版本内附零码；下次发布再更新。FIFO淘汰时同时移除对应码。零码是出生协议，不代表上层新增K/V等于当前模型从头重建的结果。

有界全局状态存在明确的退休条件：删除旧P/Q/D之前，所有仍保存该版本current码的用户都必须先反锚。当前逐用户同步发布的转换次序满足此条件，完整成本已收取这些行级转换；不能宣称把旧current码留在离线用户处、直接删表后还能无条件懒恢复。部署时这是一次发布交接，不是重建K/V，也不需要新的学习器；并发发布和持久状态交接尚未实现。单缓冲指一份持久码，PyTorch更新时的临时tensor峰值未作同样保证。

例如在M3读取由M1/M2/M3生产的三段K/V：M1条目已经通过M2的码演化状态接续到M3，M2条目也更新成M3码，M3新增条目本版保持零码；本次请求只执行M3的一套门控读取器，不串行执行M1→M2和M2→M3的两个读取器。沉默用户即使没有运行M2的码准备，也用原锚码、固定η和M3合成表直接得到同一最新码。这里“接续到M3”指码状态的版本，不意味着原生K/V被改写成M3精确缓存。

出生零码能够兼容同一锚坐标：若条目在版本s出生、当期`c_s=0`，则下次发布转换时得到`a=-P_s^{-1}(Q_sη+D_s(m))`。旧条目和新条目因此可以用同一份发布公式计算后续码，无需保存每条目的全部版本链。实际实现对已保存的P小块在发布时求逆一次，再进行原有行级矩阵乘；只增加全局小矩阵，不增加行级缓存。历史码空间可合成与当前读取的非线性分别受约束，不把“动态修正可静态沉淀为完整K/V”当成前提。

因此，高频/低频用户只是准备时机不同：可以发布前准备高频用户，也可以全部首次读取时准备；核心计算和目标版本相同。这里不按活跃度选择不同纠正模型，也不以代差阈值强制全量重建。当前同步原型只检验该读写协议，尚不包含并发发布、故障恢复或加载系统调度。

## 早期分支的实验与保留证据

模型固定为Medium：6层、6头、每头32维，历史窗口1024，V2→V3→V4→V5，原基础模型不再训练。新校准每版64 fit＋16 validation、local8/joint4、16个历史候选、4步续写、seed17；首版继承已有256/16校准并完整收费。全部旧拟合及预留角色排除于质量评估。

开发主任务在测质量前登记为每16次真实行为触发一轮推荐，每轮1个真实后续物品＋15个固定均匀负样本；评分排除同时间和未来行为。这是next-item候选任务，采样负例不是实际feedback负例，不能与原反馈AUC合并。原请求任务保留为单独对照。

精确定义是每版从首个实际行为位置开始，每隔16个原始行为位置调度；若该位置目标不在已知物品空间、或没有严格更早的历史，就跳过该轮，不另外补选有利事件。所有行为仍正常追加、计费。固定30k账本实际为28,803,460次追加、1,598,231轮推荐和25,571,696次候选评分，约每18.02次真实追加对应一轮有效推荐。16是实验触发参数，未声称其为工业通用频率。

恢复率由三个发布AUC差的等权均值计算： `(Relay-Reuse)/(Rebuild-Reuse)`。Rebuild每个用户每次发布在首个推荐请求重建一次，之后正常原生增量运行；没有请求的用户不收重建费。完整成本来自独立固定30k真实事件账本，所有行为写入、查询、准备码、锚码转换、发布目录、教师与校准都收费。

恢复率可能超过100%，这只表示AUC增益超过该Rebuild参考，不表示得到比精确教师更精确的K/V。窗口内继承的上层K/V可能包含窗口更早历史的影响，Rebuild则从保留窗口重新开始；两条随后增量运行的路径不相同。教师误差与AUC增益分别报告，不把Rebuild当作排序质量的绝对上界。

早期layer-query A的完整目录三次发布实际执行，覆盖全部1,380,766个模型物品ID。四份独立共享准备的主成本为17.3791%；若校准源K/V需另行重建，为18.6137%。每条码占原生K/V的12.5%；另有每副本约3.182GB全局φ表与D/P/Q，四副本约12.726GB，不能把全局表藏进“12.5%紧凑状态”。发布交接时新旧D并存，另多一份约1.591GB D，至少约4.773GB/副本（四副本约19.089GB），尚未包括编译分块等临时tensor。离线质量原型保留三份D及多版模型以按用户回放，其进程峰值不是稳态服务内存证明。额外查询算术占原生完整query约9.079%、原生注意力（含self）约13.499%，不是可忽略开销。17.3791%的分母仅为367.627TF的K/V重建预算；计入共同的行为写入与完整query后，完整建模服务从Full1007.021TF降为Relay703.284TF，净省30.1619%，源状态重建敏感性下净省29.7112%。不能把17.38%当作整个推荐服务的成本比例。

早期layer-query A完整4096人的同历史门控消融已合并首128人及其余3968人，覆盖全部3,471,712次候选评分；动态重放与原轨迹分数逐项完全相同。每次保留同历史、同16候选集合、同纠正写入轨迹，只把各层门控换成该集合内均值。去除集合内共同offset后，动态分支相对参考评分向量的MSE降低28.2959%，共同UID bootstrap95%为[20.2788,37.2931]%；这表明候选之间的门控变化对相对评分响应有实际作用，效果并非只有共同offset。这里的参考是**同任务中每用户每版首请求重建一次、随后正常增量追加的Rebuild评分轨迹**，不是每请求从头重建的Fresh精确教师，也不是K/V本身误差。

该响应改善没有带来排序优势：动态减同集合均值门控的pooled AUC为−0.00002367，UID95%[−0.00002815,−0.00001983]；集合内pair-AUC差为−0.00031543，UID95%[−0.00043017,−0.00021875]，均显著不利。活跃集合内门控RMS标准差为0.00398–0.02447，不同集合均值的RMS标准差为0.03069–0.14802；集合间变化通常更大，但不能仅凭这一统计把来源归因于用户或历史。该只读消融仍保留q投影和普通attention的Query依赖，不能当成一个充分训练的静态K/V映射对照。全量证据支持“Query变化部分能改善对该参考相对响应的拟合”，不支持“改善排序”或“优于K/V映射”。

早期layer-query A的小样本诊断单独保留：其128人的同集合消融AUC差为+0.00001633、centered评分MSE点值改善约21%，两者UID区间均跨0；16个保留validation用户在发布点对精确Current重建教师的centered评分MSE则略退化。这与完整线上增量轨迹的参考不同，不能被全量28.3%的响应改善覆盖。另一个全局fit均值门控对照中，完整4096人的动态减均值AUC为−0.00001712，UID95%[−0.00002192,−0.00001247]；严格新用户主任务中该差为−0.00002109，95%[−0.00003134,−0.00001126]。这些不利消融与方案总体恢复率分别报告。
