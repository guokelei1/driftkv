本轮只核对既有历史的 FIFO/生产版本形状，并做三层 CPU 合成结构检查。没有训练、GPU质量回放或重跑已完成控制。来源与必要设置见 [analysis.json](analysis.json)，设计候选写在 [/home/gkl/work/paper/new4.md](/home/gkl/work/paper/new4.md)。

V4/V5 首次评分时，83.342%/84.284% 有评分用户仍保留早于上一版本的行；连续两窗口有评分的用户中为80.199%/81.056%。统计对象是现有未重基轨迹，不能当作实行代差阈值后的重建比例或开销。它反驳的是“超界源状态仅来自少量回流用户”的假设。

CPU例子中，精确重建第一层历史后，新增行的第二层 K/V 与同一重建起点下的当前参考一致，第三层仍有差异。使用当前现成 helper 的单个1024行原生投影成本为一次全缓存生成的6.301%；helper也计算了Q，已收费。它不是完整服务成本，也没有验证代码纠正写入、推荐质量或20%目标。

分层重基本身与已有Layer重算相近。后续若研究它与码作用范围、新增状态生成和跨发布接续的结合，需保留这个区别；不能把此结构检查称为新机制已成立。

## 跨版本纠正的合成检查

用户进一步将问题聚焦为：只训练相邻发布的纠正时，怎样合并历史纠正而不增加每次读取的版本链。只读检查见 [composition_analysis.json](composition_analysis.json)，使用既有共享12＋私有6的V3/V4/V5冻结权重，CPU、float64、2线程，没有训练或质量回放。每层将Key和Value解码器及实际码访问关系合成为384×48的联合映射；相对最大奇异值1e-6的阈值下，单版数值秩48、两版联合96、三版联合144。三版联合映射的最优无结构约束rank48近似，其相对Frobenius残差为4.636%–13.039%。这个残差不能解释为AUC损失，也没有按实际码分布或共享/私有约束加权；它说明现成投影不能直接无损累加为固定48维状态。

使用V3第一层冻结投影的合成例子（seed17、7历史行、5查询）中，D1在线读取与临时展开 `k + code @ key_decoder`、`v + code @ decoder` 后读取的最大输出差异为2.842e-14。这是单次读取的代数等价检查，不涉及写回缓存、跨版本状态质量或20%成本。当前Query响应不能据此描述为“静态有效K/V无法表达”；紧凑存储和低维在线计算的作用仍需与这个更强的说法区分。

后续候选可以约束各版纠正落在共同低维基中，再累计系数；这需要明确投影参数化、校准输入与沉默用户的补齐方式。共同基、固定总码预算内的更新和长期质量尚未实现或验证，不能将“静态沉淀”直接当作已成立的操作。
