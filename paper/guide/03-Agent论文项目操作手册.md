# Agent 论文项目操作手册：从研究材料到可信论文

## 1. 这份手册解决什么问题

本手册规定 Agent 如何使用本目录中的论文写作准则，完成论文检查、论文创建和论文修改。

它不是一套固定的提示词，也不是把写作过程机械拆成若干表格。它提供的是一条可调整的工作路线：Agent 在每个阶段都要先理解研究和读者，再参考相应的规则、文章和研究材料，检查当前结果是否足以进入下一阶段。

本手册的核心原则是：

> Agent 不是把研究材料改写成英文，而是把真实的研究问题、证据和边界组织成读者能够正确理解的科学叙事。

因此，Agent 不得用语言流畅性掩盖研究空白不成立、实验不能回答问题、证据不足、引用不支持或结论超出范围等问题。

## 2. 与其他文档的关系

本手册是执行入口，不替代规则库。

**本项目的默认体裁是 CS 系统会议论文（SOSP/OSDI/NSDI/ATC/EuroSys/FAST 等）。** 涉及全文结构、章节命名、章节顺序和篇幅分配的一切判断，以 [guidelines/14-系统论文结构与体裁.md](guidelines/14-系统论文结构与体裁.md) 为准；原书派生的规则库继续管辖与体裁无关的层面（段落功能、句子衔接、归属、时态、情态陷阱、数字的评价方向、echo 语言、图表叙事）。凡规则库中出现"target journal"，一律理解为"目标会议及其近年录用论文"。不得按原书默认生成 Methods/Results/独立 Discussion 的期刊式章节结构。

## 2.1 强制原则回顾：任何工作前必须重新连接规则库

这是本手册的强制要求，不是可选建议。

Agent 在撰写、检查、修改、重构或评价任何论文内容之前，必须先回顾本目录中与当前任务相关的 principle、规则、案例和检查清单。不能因为之前已经读过、记得大意，或当前句子看起来很简单，就直接凭一般写作经验开始处理。

至少要完成以下动作：

1. 判断当前任务属于全文、章节、段落、句子、语言、图表、引用、实验/方法或投稿检查中的哪一类；
2. 打开并回顾对应的 guideline，而不是只依赖本手册中的概括；
3. 回顾该 guideline 中的规则强度、适用条件、例外、完成标准和正反例；
4. 开始工作前明确当前要使用的规则入口；
5. 检查过程中如果任务范围发生变化，重新回顾新增范围对应的 principle；
6. 完成后再用对应 checklist 和案例库复核，确认修改没有违背上游规则。

这里的“回顾”不要求每次重新通读整个仓库，也不要求把 principle 全部复制给用户；但 Agent 必须实际重新定位并阅读当前任务需要的相关规则，确保当前判断与本项目的写作逻辑相连。

在以下情况下，回顾是不可跳过的：

- 开始检查一篇已有论文之前；
- 开始创建一篇新论文或章节之前；
- 开始根据实验、代码、架构或数据材料写作之前；
- 从结构检查转入段落、句子或语言修改之前；
- 从 Results 转入 Discussion/Conclusion 解释之前；
- 用户要求“润色”“改得更像论文”但没有指定具体规则时；
- Agent 发现自己准备使用一般经验、惯用表达或目标文章模式替代本项目规则时。

强制回顾的最低判断标准是：Agent 能说明“当前要解决的写作功能是什么、相关 principle 要求什么、当前材料是否满足它、修改可能改变哪一层的科学含义”。如果不能说明，应先回顾规则，不能直接输出修改结果。

## 2.2 回顾不是形式动作

回顾的目的不是完成“我已经看过文档”的仪式，而是避免以下常见偏离：

- 把单篇目标文章的写法误当成普遍规则；
- 把 NORMALLY 或 OPTIONAL STRATEGY 写成 MUST；
- 为了语言流畅而删除研究空白、证据、限制或归属信息；
- 把 Results 中的观察改写成 Discussion 中的因果结论；
- 把用户未提供的实验事实、数据或文献结论补写出来；
- 只做句子层面的润色，却没有检查全文、章节和段落功能；
- 过度使用 may/might/could，或反过来使用超过证据强度的因果和创新表述。

因此，Agent 应把相关 principle 当作当前任务的工作上下文，而不是只在项目开始时读过一次的背景知识。

## 3. Agent 的基本工作观

### 3.1 先理解任务，再决定写什么

开始工作时，Agent 先确认：

- 这是检查已有论文、修改已有论文，还是从研究材料创建论文；
- 论文属于什么研究类型、文章类型和目标期刊；
- 目标读者已经知道什么，不能假定知道什么；
- 研究的核心问题、主要成就、外部贡献和可能影响分别是什么；
- 当前有哪些事实、数据、实验、图表、代码、架构文档和引用可以使用。

如果这些内容尚未明确，Agent 可以先提出合理的工作假设并标记出来，但不能把假设写成研究事实。

### 3.2 先建立叙事和证据，再润色句子

Agent 的优先级通常如下：

```text
研究目的和读者
-> 问题、研究空白和贡献
-> 方法/实验/架构是否能够回答问题
-> 结果和证据是否支持主张
-> 章节、段落和句子功能
-> 语言、格式和投稿要求
```

这对应项目中“从全文到章节、段落、句子再到语言”的修订顺序。Agent 不应一开始就逐句改语法，除非用户明确只要求语言编辑。

### 3.3 每个阶段都要有一个可判断的结果

不要求每一步生成固定格式的文件，但 Agent 至少要能回答：

- 当前阶段解决了什么问题；
- 哪些内容已经有证据，哪些仍是推断或缺口；
- 发现的问题是否会阻止进入下一阶段；
- 下一步应该参考哪些材料和规则。

如果关键事实缺失，Agent 应停在相应阶段请求材料，或明确说明只能生成结构草稿，不能生成事实性结果。

## 4. 三种主要工作模式

### 模式 A：检查一篇已有论文

适用于检查草稿、已投稿论文、已发表论文或他人的论文。

建议顺序：

```text
识别论文类型和读者
-> 快速建立全文地图
-> 检查研究问题、方法、结果和结论是否闭合
-> 检查章节和段落功能
-> 检查证据、引用、图表和表述强度
-> 检查句子和语言
-> 给出按优先级排列的修改建议
```

先读标题、摘要、章节标题、图表、每段首句、Discussion/Conclusion，再回到全文逐段核对。这是 [guidelines/01](guidelines/01-全文叙事与反向工程.md) 所说的 reverse engineering 入口。

检查时优先找会改变论文可信度或读者理解的问题：

- Introduction 的 gap 是否真的由本文回答；
- 每个研究问题或假设是否有对应的实验和结果；
- Methods 是否足以复现关键步骤；
- Results 是否把观察、解释和推测混在一起；
- Discussion 是否只是重复 Results；
- Conclusion 是否超出证据和研究范围；
- Title、Abstract、Discussion 和 Conclusion 是否承诺了同一件事；
- 图表、引用和补充材料是否在读者需要的位置出现。

### 模式 B：从实验、系统或研究材料创建论文

适用于用户提供实验记录、数据分析、代码、系统架构、模型设计、图表或研究报告，但尚未形成完整论文的情况。

建议顺序：

```text
盘点研究材料
-> 判断研究问题和论文类型
-> 检索并分析相关研究和目标文章
-> 形成问题、空白和贡献的暂定叙事
-> 检查实验/系统/架构是否支持这个问题
-> 整理结果、图表和证据边界
-> 写 Methods、Results、Discussion/Conclusion
-> 回写 Introduction
-> 写 Abstract 和 Title
-> 全文审计
```

这里的“先写”不是绝对规定，而是为了让 Introduction 建立在真实的方法和结果上。若研究问题尚未确定，Agent 应先帮助整理问题和证据，而不是直接写一篇看似完整的论文。

对于系统或工程研究，至少要把以下关系说清楚：

```text
研究问题 -> 系统/模型设计 -> 实现或实验设置 -> 评价指标和基线
-> 结果 -> 对问题的回答 -> 局限和适用范围
```

系统论文的成文骨架按 guideline 14 组织：Introduction（含贡献列表和结果预览）→ Background & Motivation（含自测数据和需求 R1..Rn）→ Overview（抽象、架构、life-of-a-job）→ Design ×2–3 → Implementation → RQ 驱动的 Evaluation（Discussion 通常并入其中）→ Related Work → Conclusion。写作顺序通常是：先稳定 Design/Implementation 与 Evaluation 的证据，再回写 Overview 与 Introduction，最后写 Abstract 和 Title。

架构文档可以说明系统由什么组成、如何连接和为何这样设计；它不能自动证明系统有效。有效性仍需要实验设计、基线、消融、扩展性数据和评价结果支持。

### 模式 C：修改和重构现有论文

适用于研究事实基本稳定，但论文故事线、章节顺序、论证力度或语言表达存在问题的情况。

建议先区分问题类型：

1. 科学内容问题：研究问题、实验、数据或结论本身不闭合；
2. 论证结构问题：信息正确，但没有形成研究地图和读者路径；
3. 章节接口问题：Introduction、Methods、Results、Discussion 和 Conclusion 之间没有对应；
4. 段落句子问题：功能混杂、衔接跳跃、指代不清；
5. 语言问题：时态、语态、情态、因果词、术语或句法造成误读；
6. 投稿适配问题：目标期刊的结构、长度、标题和格式未匹配。

先修复前面的类型，再处理后面的类型。语言编辑不能替代科学论证修复。

## 5. 参考文章和文献的使用方法

### 5.1 参考文章不是一类材料

Agent 应根据用途区分文献，而不是把所有文章混成一个列表：

- **领域地图文献**：帮助说明研究方向如何发展、已有共识和主要分歧；
- **关键或奠基文献**：说明概念、方法或理论从哪里来；
- **近期研究文献**：确认当前 gap 是否仍然存在，避免把已解决的问题写成空白；
- **方法/基准文献**：支撑方法来源、基线、评价指标或实验设置；
- **目标期刊文章**：观察标题、摘要、章节、图表叙事和语言习惯；它们不一定都是科学论证中最重要的引用；
- **反例或相反结果文献**：帮助构造比较、边界和 Discussion，而不是只挑选支持自己的研究。

### 5.2 推荐的检索顺序

检索顺序可以按项目调整，但通常从宽到窄：

```text
研究对象/现象和核心术语
-> 综述、观点或领域地图
-> 关键机制、方法或基准研究
-> 近年直接相关研究
-> 目标期刊中的相近文章
-> 争议、反例、局限和应用研究
```

检索时使用同义词、旧术语、新术语、方法名、对象名、条件名和结果名组合。不要只用用户当前的一种叫法，因为术语变化本身可能造成假 gap。

### 5.3 选择目标文章

目标文章首先用于 reverse engineering。通常至少选择四篇与研究主题、研究类型和目标期刊相近的近期论文，并观察：

- 标题承诺了什么；
- 摘要如何压缩问题、方法、结果和价值；
- Introduction 如何从背景进入 gap；
- Methods 的细节和补充材料如何分配；
- Results 如何组织图表和总体趋势；
- Discussion 如何区分成就、贡献、影响和局限；
- 哪些规则是稳定模式，哪些只是单篇文章的特殊做法。

目标文章的结构只能作为证据和参考，不能直接复制，也不能把单篇文章的段落数量当作硬规则。

### 5.4 文献检索的完成判断

检索不以“搜到很多文章”为完成标准，而以能否支撑当前写作判断为标准。至少应能回答：

- 这个研究问题为什么重要；
- 已有研究已经解决了什么；
- 当前仍缺少什么；
- 本研究与已有方法或结果有什么关系；
- 是否存在相反结果或会削弱结论的研究；
- 目标期刊通常如何组织类似论文。

如果这些问题仍不能回答，应继续检索或降低当前表述的确定性。

## 6. 论文创建和检查时的共同审计线

Agent 应持续维护以下几条对应关系，不必拘泥于具体表格：

```text
研究问题/假设 <-> 方法/实验 <-> 结果 <-> Discussion 解释 <-> Conclusion 主张
研究空白 <-> 本文行动 <-> 研究成就 <-> 外部贡献
图表 <-> 正文中的观察和比较
引用 <-> 它实际支持的事实、方法或解释
限制 <-> 结论边界和未来研究
```

任何一条对应关系断开，都应优先处理，而不是继续润色下游文字。

### 6.1 证据和表述强度

Agent 要区分：

- 研究中直接观察到的结果；
- 对结果的直接解释；
- 与已有研究的比较；
- 有证据支持的推论；
- 尚未验证的机制、应用或未来方向。

因果动词、时态和情态动词必须与证据强度匹配。特别检查 [guidelines/10-时态语态语气与语言.md](guidelines/10-时态语态语气与语言.md) 和 [guidelines/13-原书正反例与诊断案例.md](guidelines/13-原书正反例与诊断案例.md) 中关于 `must`、`can`、`cannot`、`should`、`-ing` 和因果表达的案例。

### 6.2 实验与系统材料的边界

Agent 可以帮助整理实验和架构，但不得凭空补充：

- 未提供的实验参数、样本数量、对照条件或重复次数；
- 未运行的实验结果和统计显著性；
- 未验证的系统性能、泛化能力或实际应用效果；
- 用户没有提供来源的文献结论；
- 为了让故事闭合而虚构的限制、数据或机制。

缺少这些内容时，可以生成待填结构、检查问题和条件化表述，但要清楚标记为待确认内容。

## 7. 柔性阶段框架

下面是建议的共同阶段。Agent 可以合并、跳过或回退阶段，但不能无说明地跳过关键判断。

### 阶段 1：任务定位

明确工作模式、文章类型、目标期刊、目标读者、已有材料和用户希望的最终结果。参考 [00-项目说明与使用方法.md](00-项目说明与使用方法.md) 的使用顺序和 [guidelines/01-全文叙事与反向工程.md](guidelines/01-全文叙事与反向工程.md) 的读者/体裁原则。

进入下一阶段的判断：Agent 能说清楚“现在要检查或构建什么论文，以及判断成功的标准是什么”。

### 阶段 2：材料和文献侦察

盘点正文、实验记录、数据、代码、图表、架构文档、已有引用和目标期刊文章。用宽到窄的方式检索背景、方法、近期研究和目标文章，并记录不确定或相互冲突的信息。

参考 [guidelines/01](guidelines/01-全文叙事与反向工程.md)、[guidelines/02](guidelines/02-Introduction.md)、[guidelines/03](guidelines/03-Methods.md) 和 [guidelines/11](guidelines/11-图表引用与研究规范.md)。

进入下一阶段的判断：已有材料足以初步说明研究对象、相关研究、方法来源和需要解决的问题；若不足，明确缺口。

### 阶段 3：研究问题、贡献和证据地图

提炼或检查核心研究问题、研究空白、研究行动、成就、贡献和影响。把每个研究问题与相应的方法、实验、结果和结论联系起来。此阶段可以是暂定的，后续结果可能使问题表述变窄或重写。

参考 [guidelines/01](guidelines/01-全文叙事与反向工程.md)、[guidelines/02](guidelines/02-Introduction.md)、[guidelines/05](guidelines/05-Discussion.md) 和 [guidelines/06](guidelines/06-Conclusion.md)。

进入下一阶段的判断：Agent 能指出论文要回答什么、凭什么回答、回答到什么范围，以及哪些内容只是解释或推测。

### 阶段 4：研究设计和可复现性检查

检查实验、模型、系统架构、数据处理和评价方案是否真的支持研究问题。对方法尤其检查材料来源、参数、顺序、停止条件、对照、重复、选择理由、方法修改、图表和局限。对于架构研究，还要检查设计组件、实现、基线、指标和实验结果是否一一对应。

参考 [guidelines/03-Methods.md](guidelines/03-Methods.md)、[guidelines/04-Results.md](guidelines/04-Results.md) 和 [guidelines/11-图表引用与研究规范.md](guidelines/11-图表引用与研究规范.md)。

进入下一阶段的判断：缺失项已经补齐、被明确标记为限制，或确认当前只能写出条件性/结构性草稿。

### 阶段 5：全文故事线和章节蓝图

根据真实问题、方法和证据决定全文顺序。先建立章节任务、段落功能和 Section interface，再写完整句子。可使用 [templates/章节功能模板.md](templates/章节功能模板.md) 和 [templates/段落与句子角色模板.md](templates/段落与句子角色模板.md)。

参考 [02-核心写作框架-速查.md](02-核心写作框架-速查.md) 以及对应章节 guideline。

进入下一阶段的判断：只看标题、章节标题和段落首句，能够复述论文的研究路径和中心贡献。

### 阶段 6：起草或重构正文

按照需要写或重构 Methods、Results、Discussion、Conclusion、Introduction、Abstract 和 Title。写作过程中保留证据位置、引用功能、图表入口和限制，不要先删除这些支架再追求简洁。

创建新论文时，通常先稳定 Methods/Results，再写 Discussion/Conclusion，之后回写 Introduction，最后写 Abstract 和 Title；检查已有论文时则从最影响论证闭合的部分开始。

进入下一阶段的判断：每个章节完成其功能，关键主张有相邻证据或明确的范围限定，章节之间没有明显承诺断裂。

### 阶段 7：多层检查和迭代

先查全文目的和章节接口，再查段落功能、句子衔接、证据强度、图表引用、术语、时态、语态、情态、标题摘要和投稿要求。使用 [guidelines/12-修订投稿与检查清单.md](guidelines/12-修订投稿与检查清单.md)、[templates/论文自检清单.md](templates/论文自检清单.md) 和正反例库。

发现上游问题时回退，而不是只在下游打补丁。例如，若 Conclusion 超出证据，应回到 Results/Discussion 检查证据和解释，而不只是把 Conclusion 改得更委婉。

进入下一阶段的判断：剩余问题主要是可接受的风格选择、目标期刊差异或已明确标记的研究限制，没有未处理的关键逻辑断裂。

## 8. Agent 的输出方式

Agent 可以按用户需要输出全文、章节草稿、诊断报告、修改建议或下一步问题，但每次工作都应让用户知道：

- 当前采用哪一种工作模式；
- 参考了哪些本目录规则和哪些外部文章；
- 哪些判断来自研究材料，哪些来自文献，哪些是 Agent 的暂定推断；
- 发现了哪些会影响论文可信度的问题；
- 哪些内容已经可以写，哪些内容需要用户补充或验证；
- 下一步最有价值的动作是什么。

对于已有论文，优先报告“问题位置—问题类型—读者可能的误读—证据/规则依据—修改方向”。对于新论文，优先报告“当前研究问题—现有证据—缺失材料—建议的叙事路线”。

## 9. 最低限度的完成标准

一篇论文项目可以暂时进入写作或修改阶段，当 Agent 至少能够说明：

1. 目标读者和文章类型；
2. 核心研究问题或当前缺失的问题定义；
3. 研究空白与已有工作的关系；
4. 研究方法、实验或系统设计如何回答问题；
5. 关键结果和证据边界；
6. 研究成就、贡献、影响和局限之间的区别；
7. Title、Abstract、Introduction、Discussion 和 Conclusion 如何保持同一条中心线。

如果第 2–5 项中有关键空缺，Agent 仍可以帮助整理研究计划或论文骨架，但不应把它当作已经完成的科学论文来润色和包装。

## 10. 与现有项目的迭代关系

本手册第一版有意保持开放：不同学科、研究类型和目标期刊可以调整阶段顺序、章节组合和文献检索深度。后续若在实际论文上使用，应把反复出现的新情况记录为：

- 新的研究类型或文章结构；
- 现有规则的适用条件；
- 现有规则之间的冲突；
- 目标期刊的稳定习惯；
- Agent 容易误判的检查案例。

只有在多个真实项目中验证后，才适合把某个可选做法升级成更强的 Agent 规则。
