## 2. The Main Thread Running Through the Book

```text
Identify article type and readership
    -> reverse engineer target articles
    -> map the functions of titles/subtitles/graphics/paragraphs/sentences
    -> wrap the research information in functional order
    -> control the reader's path with sentence-initial position, connectors, tense and terminology
    -> make achievement, contribution, impact explicit
    -> continually update the models using recent samples from the target journal
```

This main thread is more stable than the fixed IMRaD headings. IMRaD is the common external order the book adopts for ease of reference; it is not the production order in which the writer must write, nor the only order in which readers actually read. Writers normally produce the Methods, Results, Discussion/Conclusion first, then the Introduction, Abstract and Title; some journals place the Methods at the end of the paper or in supplementary materials.

## 2.1 Applicability boundary: this project writes systems-conference papers, not IMRaD journals

The book's unit structure assumes a STEMM journal article. This project's papers use the systems-conference skeleton defined in [guidelines/14-系统论文结构与体裁.md](guidelines/14-系统论文结构与体裁.md). Use this mapping when applying the book's units:

| Book unit | Systems-paper section it actually governs | What changes |
|---|---|---|
| Introduction | Introduction | Add contribution bullets + numeric results preview (SYS-02); the research map largely moves to Related Work near the end |
| Methods | Design ×2–3 + Implementation | Overview-before-detail, rationale, ownership, honest problems apply; wet-lab rules (equipment, spatial language) do not; reproducibility is delivered by Implementation + artifact |
| Results | Evaluation | All evidence/evaluation rules apply; organization is by research question with setup, baselines, ablations, scaling (SYS-07/08) |
| Discussion | "Discussion and limitations" subsection inside/after Evaluation | Mirror logic and echo language apply; a standalone Discussion section is usually absent |
| Conclusion | Conclusion | The 100–200-word journal norm does not apply |
| Abstract / Title | Abstract / Title | Apply with conference conventions (SYS-11): result numbers in the abstract, `SystemName: description` titles |
| Checklist and Tips | All sections | Apply unchanged |

Sections with no book counterpart — **Background & Motivation with measured evidence, Overview, Related Work as a standalone end section** — are governed entirely by guideline 14.


## 3. The Mirror Interface Between Introduction and Discussion

| Introduction action | Discussion response |
|---|---|
| Enter the paper from the field/topic | Return from the study results to the field/topic |
| Provide background and existing knowledge | Explain how this paper advances or revises that knowledge |
| Draw the research map | Place this paper back on the research map |
| Point out the gap/problem | State to what extent it has been resolved |
| Introduce this paper, methods and expected contribution | Summarise achievement, contribution, impact |
| Narrow the reader toward Methods/Results | Lead the reader toward the Conclusion, applications and future work |

Therefore, once the Introduction is written, each item should be answerable in the Discussion; if it cannot be answered, the Introduction's gap, aim or promise needs to be rewritten.

## 4. Section Modules and Cross-Section Topics

### 4.1 Section modules

1. Whole-paper narrative, readership and research purpose;
2. Introduction's background, research map, gap and this paper;
3. Methods' reproducibility, rationale for choices, procedure and problems;
4. Results' evidence, graphics, evaluation, comparison and implications;
5. Discussion's contribution, interpretation, literature positioning, limitations and applications;
6. Conclusion's final message, boundaries and way forward;
7. Abstract's independent communication;
8. Title and keywords as the discovery entry;
9. Paragraphs, sentences, tense, voice, prepositions, articles and modals;
10. Graphics, citations, supplementary materials, submission and revision.

### 4.2 Topics that cannot be handled in isolation by section

- **Reader knowledge assumptions**: affect everything from the first sentence, the Methods overview, the Results method recap through to the Conclusion.
- **Contribution ownership**: passive voice, tense and impersonal subjects are especially dangerous in Methods, Abstract and Conclusion.
- **Evidence strength**: causal verbs in Results, modal verbs in Discussion and application claims in Abstract must be consistent.
- **Research map**: which literature the Introduction selects, which methods the Methods compares, how the Results contrast, and how the Discussion interprets - these form one line.
- **Given-to-new information**: controls both intra-sentence order and paragraph/section interfaces.
- **Terminology echo**: do not arbitrarily switch the same concept to scheme, framework, approach, method etc. just to avoid repetition; when the Discussion revisits earlier text, using the same vocabulary is especially needed.
- **Information-surfing**: Title, Abstract, Results, Discussion and Conclusion must be able to work independently to some extent.
- **Modal verb traps**: must (= certainty without evidence), can (= three meanings), can not ≠ cannot, should (= two meanings) and other traps run through Results, Discussion, Conclusion and Abstract, and must be checked sentence by sentence at every position where a modal is used.
- **-ing structure ambiguity**: -ing forms show no tense or subject and may have more than ten logical relations; they are high-risk in Methods, Results and Discussion.
- **Evaluative language and naked numbers**: key numbers in Results, Abstract and Discussion must have an evaluative direction, otherwise different readers will judge high or low on their own.

## 5. Source Handling Rules During Extraction

| Book material | Handling in final document |
|---|---|
| Explicit rules | Convert directly into rules, preserving applicability boundaries |
| Explanations of positive/negative examples | Convert into "problem - cause - fix action" |
| Example sentences | Keep only short sentence slots and the function they demonstrate |
| Exercises | Convert into writer self-checks or reverse-engineering steps |
| Word lists | Embed by writing function; do not separately encourage mechanical word-fitting |
| Single-paper cases | Mark as examples; do not promote to cross-disciplinary absolute rules |
| Target journal suggestions | Record as "verify against recent target articles" |

## How Positive/Negative Examples Run Through the Book

The book's cases should not be viewed as an independent language appendix. They respectively test risks at different levels of the whole paper:

| Level | Typical contrast | Test target |
|---|---|---|
| Narrative | Literature list / research map | Whether the literature drives the reader toward the gap |
| Time | was paid / has been paid | Whether the gap is a historical state or a current state |
| Method | then / until stable | Whether the experimental order is reproducible |
| Result | 23% / as many as 23% / only 23% | Whether the number has a clear evaluation and baseline |
| Evidence | caused / associated with / may have resulted from | Whether the causal strength exceeds the design |
| Discussion | repeat results / repeat then interpret | Whether it moves from finding to meaning |
| Conclusion | Kinetic analyses suggest / We have synthesized | Whether contribution ownership is clear |
| Sentence | this result / explicitly repeat the key noun | Whether the reference is unique |

The corresponding specific sentences and fix records are in [the book's positive/negative examples and diagnostic cases](guidelines/13-原书正反例与诊断案例.md).
