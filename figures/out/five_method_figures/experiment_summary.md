# Five-method cross-scale figure: experiment summary

This note documents only the data and methods shown in `five_methods_horizontal.pdf`.
The figure contains five method panels, each with 6L, 10L and 16L curves and a
mean curve. `selected_points.csv` contains the plotted points and interpolated
means.

## Data and plotted values

Each evaluation uses a 1,024-event retained history and real following-window
feedback. The primary metric is pooled ROC-AUC. For a method (m), the plotted
recovery is

\[
  100\frac{\mathrm{AUC}_m-\mathrm{AUC}_{\mathrm{Reuse}}}
  {\mathrm{AUC}_{\mathrm{Exact}}-\mathrm{AUC}_{\mathrm{Reuse}}}.
\]

The vertical axis displays this recovery clipped to [0, 100]. The horizontal
axis is theoretical incremental FLOPs as a percentage of one Current Exact
cache rebuild. It includes teacher construction, fitting, profiling or cache
conversion, and method-specific extra reads; wall-clock time is not used.

The mean curve is the pointwise mean of the three scale curves after display
clipping, evaluated at common FLOPs positions. The first three lowest-cost
points are omitted from the plotted `shared correction` curves, and the first
three from the `shared + basic user signal` curves, solely to remove unreadable
points near zero. The complete measurements remain in the three-scale ledger.

Representative mean values in the plotted figure are:

| Method | First displayed point (FLOPs, recovery) | Higher-cost point | Final displayed point |
| --- | ---: | ---: | ---: |
| Layer recomputation | (18.6%, 22.5%) | (83.7%, 82.3%) | (100.0%, 91.3%) |
| Tail recomputation | (4.6%, 2.8%) | (61.8%, 52.0%) | (100.0%, 100.0%) |
| KV translation | (32.3%, 58.6%) | (59.4%, 71.5%) | (100.0%, 71.8%) |
| Shared read correction | (3.5%, 20.3%) | (35.9%, 19.5%) | (84.4%, 19.1%) |
| Shared read correction with basic user signal | (3.6%, 51.6%) | (36.2%, 52.2%) | (85.2%, 51.4%) |

The 6L and 10L diagnostics use the matched 10,000-user evaluation protocol.
The 16L diagnostic uses an independently selected 10,000-user Max cohort; its
protocol is otherwise matched in history length, feedback metric and cost
normalization.

## Common configuration

- Model families: frozen 6L Medium, 10L Large and 16L Max HSTU models.
- Evaluation: 10,000 user snapshots per completed edge, 1,024 retained events,
  real known-target feedback, pooled ROC-AUC.
- Teacher budgets for the shared-read rules: 32, 64, 128, 256, 512, 1,024,
  2,048, 4,096 and 7,144 users; the plotted panels display the retained
  higher-level points after the readability trim described above.
- DroidSpeak calibration: 32 teachers, 16 fixed candidate queries per teacher,
  all contiguous layer intervals, one selected interval per recomputation width.
- Tail recomputation lengths: 32, 64, 128, 256, 512 and 1,024 events.
- KV translation: 256 teachers, source-layer counts 1, 2, 3 and 4; every
  evaluation user's cache is converted before reading.
- Shared-read fitting: 16 fixed queries per teacher and ridge 0.01.
- Execution: GPU scoring with CPU-side teacher-cache preparation; all reported
  costs are theoretical FLOPs, independent of execution time.

## Method definitions

**Layer recomputation.** Recompute a contiguous block of model layers on the
retained history and use the resulting state for the read. The calibration
search chooses the best interval for each allowed recomputed-layer width.

**Tail recomputation.** Keep the old cache for the prefix and recompute only a
suffix of the retained history. Increasing the suffix length increases both
theoretical cost and the amount of refreshed state.

**KV translation.** Fit a teacher-supervised mapping from the old K/V tensors
to the new model's K/V tensors. The plotted curves vary the number of source
layers used by the translator while converting each user's cache.

**Shared read correction.** Learn one release-level read correction from a
small teacher group and apply it to each user's native read response:
\(\Delta r=N b\). The fitted rule is shared across users; the user's cache
enters through the native response and read length.

**Shared read correction with basic user signal.** Use the same shared rule,
augmented by a low-cost user-specific response term:
\(\Delta r=N b+T r\), where (r) is the user's native read response.
This is the simple personalization comparison in the final figure; it is not
the full later serving design.

The figure is generated by `figures/src/five_method_selected.py` from the
retained AUC and theoretical-FLOPs ledger.
