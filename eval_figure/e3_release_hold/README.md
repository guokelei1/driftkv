# E3：一次发布后的长续写趋势（模拟）

接在 Figure 6 的定期发布结果之后。主动延长单次模型及纠正参数冻结的服务过程，观察随追加推进，累计计算投入和恢复收益如何共同变化；不推导最佳发布周期或通用淘汰阈值。Figure 5／6不变。

## 图的结构

- 一条成本—恢复率轨迹。每个点同时表示同一检查点的累计费用和质量，没有两条曲线的无意义交点。
- 横轴：累计完整附加 FLOPs／同群体一次初始 Rebuild 费用（%）。初始化、校准、必要教师／源准备、共享表、用户准备和全部纠正读写均计入。
- 纵轴：匹配反馈检查点的恢复率 `100×(AUC_CT−AUC_Reuse)/(AUC_Rebuild−AUC_Reuse)`。
- 点旁的0N、0.25N、0.5N、0.75N、1N、2N是累计追加量；N为初始窗口长度。小箭头指示服务推进，这不是不同预算配置的前沿图。
- 无阴影、大参考线、跨图引导线或持平点标记。轨迹总体向右下，表达费用积累、恢复收益减弱，而不要求每一步严格单调。

参考了 Ekya（NSDI 2022）Figure 3的成本—质量坐标与稀疏点标注：[官方PDF](https://www.usenix.org/system/files/nsdi22-paper-bhardwaj.pdf)。另用同一数据试画了柱＋线和对齐横条，仅借其视觉结构，不借相关工作的数据或结论。三种草图见 `paper/build/hold_trends_20261020/comparison.png`。

## 固定设置与解释边界

代表例为 Yambda-Max、N=1,024、模拟活动人口200,000、拟合64人，每次追加前按固定11／12交替配置评分；它们是声明的合成配置，不是实测请求规律或最终设置。原点之前已发生一次触发读取，相应准备和读取均入账。模型及纠正参数冻结，Reuse、CacheTide和起始重建一次的Rebuild分别延续自己的状态。

原生公共评分与追加工作从双方同时扣除，完整总 FLOPs另存；横轴不是总服务时间比例。没有下一发布便不收交接费。零码后缀旁路保留，原始旧行淘汰后主要附加算术平台化，不能为了画上升趋势强制纠正全窗。既有数值计算和AUC数组完全不变；历史持平插值只在计算账中保留，不再主导图或结论。

恢复率降低不等于绝对AUC误差增加：Rebuild−Reuse缺口也会缩小。正式结果保留三方法原始AUC、共同检查点的真实反馈和覆盖；分母趋近零时改报绝对差，日志不足2N便缩短范围。不以本预览声称“7天有效、180天无效”。
