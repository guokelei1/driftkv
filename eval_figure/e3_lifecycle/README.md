## 两个量共同展示

每个版本内直接配对 **恢复率折线＋成本柱**，共用0—100%刻度：

- Recovery：`100 × (CT AUC − Reuse AUC) / (Rebuild AUC − Reuse AUC)`。
- Added cost：完整附加 FLOPs／同版历史重建预算，以百分比表示；柱顶给出数值。
- 灰色 `Δ`：同版 `100 × (Rebuild AUC − Reuse AUC)`，单位AUC百分点（pp），只作点旁数值标注。

Recovery、Added cost和灰色Δ AUC gap(pp)在顶部公共图例并列解释，图注只说连续恢复与成本，不再解释Δ。点旁Δ数值保持与各版本对应。

两个百分比的分母不同，各自按定义读数；线与柱的纵向差不构成额外效率指标。不再把成本作为图下数值行，也不增加第三轴。浅色带斜线的成本柱与深色圆点折线在黑白打印下仍能区分。

此前比较了同轴柱线、双轴柱线、成本—恢复轨迹三种表达，选择前者。双轴若将成本范围缩至0—25%，会把约17%的柱放大到接近80%恢复率线的高度；成本—恢复轨迹又需要依靠点标签寻找版本顺序。备选图只保存在 `paper/build/lifecycle_joint_20261019/alternatives.png`，不额外插入正文。

## 五版本数据的含义

当前图读取 `data.json` 新增的 `lifecycle_preview`，其中覆盖四配置、各五个明确的合成发布点。Max的五版数值原样保留；新增Large的V1／V2仅为模拟，重叠V3—V5沿用其旧默认点的AUC和费用。此前三版本／四配置的输入保留，不混为五次实测，也不改变已接受的核心前沿图。

V1是第一轮被评估的模型更新，前面已有V0原生缓存，因此Reuse、Rebuild和恢复率均有定义；它不是从零建立推荐模型。五版本模拟账把一次性初始化计在V1，其余各版计本次拟合、共享准备、转换和所有附加读写。正式五次连续发布的模型检查点仍需准备；本轮不训练基础模型，也不声称已经拥有五次真实轨迹。
