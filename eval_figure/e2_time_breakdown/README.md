# E2：相同资源下的时间分解与存储小表（模拟）

当前接入论文6.5，替代旧人口／孤立路径比值表；时间用图、持久存储用四行小表，不另画显存或存储对比柱图。6.6保留Base→+P→+F工程优化与工作负载敏感性。

## 问题和画法

同一模型组在相同硬件上处理同一因果事件账，Rebuild一次重建后原生服务，CacheTide准备码后纠正读写。单栏约3.35×3.15英寸，2×2覆盖Yambda／RecFlow×Large／Max；每个面板两条横向堆叠条，条末是总时间（ks）。分段为：

1. Fit/tables：首次固定特征初始化、当版校准、必要教师／源准备和共享表生成。
2. State prep：Rebuild历史重建，或CacheTide码物化。
3. Service ref.：匹配原生服务路径的完整时间参照。
4. Service Δ：完整纠正评分／追加时间减去原生参照，不是融合核内部的独立计时。
5. Handover：结束时的码反锚。
6. Transfers：共有搬运加实际新增码和共享表搬运，只收一次。

斜线标出码准备、拟合、服务差和维护。所有事件都保留，图形不靠删除共有服务放大收益。FLOPs与字节不被换算成时间。主图只有当前四组数据，不复用旧Full未定义分支。

## 模拟身份与正式测量

`data.json`是一套**新声明的均匀模拟事件账**：每用户12次候选评分、4次追加、N=1024，各模型组64名拟合用户，人口也仅为模拟配置。操作时间系数都是布局占位值；不能把它们理解为现有模型的实测，不能由图外推性能。旧`e2_time_scale/`路径示意数据并不能直接推出全周期，本图没有将旧比值表冒充完整处理实测。

正式比较应冻结实际人口及因果事件，直接执行同一完整轨迹，记录资源上限与各方合理批量。总时间来自完整处理过程；互斥阶段用于解释它，含packing、同步和搬运。服务阶段可以按原生参照与增量差作代数拆分，但若有重叠就不能相加重复收费；若服务差实测为负必须保留符号，不能为了当前正向堆叠图置零。首次初始化收全，后续发布不重复收取；共同底座训练独立说明。不模拟生产到达、排队、吞吐或延迟。

## 持久存储小表

`storage_table.py`从同一`data.json`计算四配置的原生K/V总量、新增存储和增加比例，输出`storage_ledger.json`与`table_6_5_storage_simulated.tex`。表格为原生LaTeX，直接同步到`paper/main.tex`中的`tab:eval-storage`；不修改现有时间图。

原生K/V字节为`U×N×L×2Hd×4`，码字节为`U×N×L×(12+6H)×4`。只保留一份锚码／当前码缓冲区；共享部分包括全目录固定特征表、当前物品表、交接时仍保留的一份旧物品表和共享参数，每个声明副本计一次。预览中三张物品表各宽`12+6H`，共享参数包大小为声明的模拟占位值，包含当时保留的固定和发布参数。参数和目录数据不是实测文件体积。

该表是全人口持久缓存与纠正状态，不是GPU常驻分配或累计搬运字节；共同底座、原始数据归档及临时工作区在范围外。按十进制GB/TB报告。全部用户假设完整1024行窗口、FP32、一份共享副本；Large／Max假设10／16层、10头、每头32维，RecFlow形状尤其仍是假设，不能用于声明模型资产已就绪。正式表按实际保留行数、形状、目录和参数文件大小重算。
