## 发布内演化

同一用户、同一原始因果前缀，对照Reuse、cutover一次Rebuild、一次KV映射及教师强制新写入诊断。后者只保留存活的初始mapped旧行，新行来自教师自身持续轨迹，不用每点fresh重建替代once-Rebuild。它用于定位写入传播，不报告在线节省。

零追加cutover与第一次真实请求分开。固定发布前历史/均匀候选Q16面板，在新增行为检查点比较teacher logits残差和同学生query的局部read残差；合成面板不用于真实反馈AUC。真实AUC仅在真实请求候选/时间上算。记录实际追加数、旧行存活比例和各点用户支持；时间戳并列遵循请求先于同秒行为。对后续可用用户做配对初始误差比较，避免人口组成变化伪装成退化；不足512用户的点只作数值/覆盖诊断。

教师强制改善后续残差可支持“新写入携带了可避免误差”；旧行清空后free-running误差仍可能继续，不能把producer=current当作清除。若初始就无收益，应先诊断映射/优化，不能声称观察到了先好后坏。误差也可能随淘汰减轻，不强求单调。

## 固定快照候选分析

固定缓存和时间，仅改变候选。用mapped路径自己的各层query读取teacher KV，记录逐层/头误差、去候选均值能量和候选方向变化，隔离下层query差异。结果只说明受限映射残差如何随候选变化；attention本身依赖query、Full本身也是固定KV，故不能据此推出门控必要性。

如需继续回答候选条件是否有额外信息，再固定同一F/行基底，以相同结构/预算比较真实物品条件与固定/置换条件，并做独立候选验证。只置换额外校正输入，native候选保持正确。只在训练后置换不足以证明优于充分拟合静态方案；rich-query结果也不能冒称item-only gates证据。不恢复三模块收益阶梯，不在Motivation验证compact code等最终实现。

## 版本变化与停止条件

先固定历史快照，比较旧目标版本的映射与按当前目标重新校准的映射；随后再引入持续写入，分开版本失配与状态传播。重新拟合必须匹配实际保留状态，不能将原生M1输入映射错误套到已由M0迁移的状态。两边明显失败时暂停扩跑并改诊断，不默认跑齐五边。

先完成11项CPU语义检查和实际Large小样本数值/速度检查；少于512用户不出质量结论。得到清楚信号再扩大复核。最终分别记录观察、可支持的缺失能力、不能推出的结论及相应Design要求，保留反例和费用。

## 对3.3叙事的建议（未修改论文）

建议采用“映射有用，但兼容性具有版本与轨迹依赖”这一主问题，辅以两个有边界的观察：

1. **可行起点。** 简单KV映射在两边cutover相对Reuse减少81.49%/70.51%的教师logit MSE，说明廉价校正值得研究；不宣称它已经饱和或达到固定AUC恢复率。
2. **缺少长期兼容保证。** 固定历史的版本对照显示，旧校正不能直接视为新目标的合适状态，因而需要显式维护校正的版本依赖。发布内教师新行对照则提示，应考察校正如何参与后续写入的上下文，而非只拟合初始静态快照。它是oracle轨迹对照，不独立定位到某个训练目标或写入操作。

由此可以提出“校正状态需要随目标版本维护，并考虑读写闭环”的设计要求。如何用仿射组合实现跨版本维护、如何处理跳过版本，以及最终方法能否得到类似收益，均留给Design推导和Evaluation验证。两条独立冻结快照不等于连续多版本实验。

**本轮不支持**“历史越长一次映射越失效”，也不足以推导“物品门控必不可少”或“交互天然低秩”。compact code、存宽读窄及其宽度可由成本边界提出，容量和有效性另做验证。不要把旧3.3预期的65/68/86%或秩2/6数字当作本轮结果；论文原文保持不变。

本轮机制探索与结果记录已完成，不继续扩跑其余release或恢复旧阶梯队列。保留全部反向证据；若后续要把“新增预算修复”进一步归因于“目标版本适应”，优先补同预算旧目标refresh对照，作为更强结论的证据，而非当前案例报告的前提。

## 用户要求的拓展：从简单correction遗漏什么出发

2026-10-23，用户进一步要求主动探索更多配置和测试角度，重点是解释为何值得设计某种能力，不要求证明候选门控必要性或最终Design优越性。上面的已完成结果保持原样；新结果写入`insight_extensions/attempt_1`，仍只用GPU1、原main2,000人及隔离fit100/val16，不修改论文。

- **已有残差重新分解。** 保留全部100个层头，分析候选变化是否局部集中；将教师logit误差精确拆成每用户共同偏移与候选间中心化误差，并对每检查点做同UID配对。原Q16内成对排序仅作教师排序一致性，不称真实AUC或检索质量。结果在原run的`residual_angles/`。
- **时间输入控制。** 保留原来的缓存、候选和全部advance边界，每个追加检查点分别用该点实际query gap和该用户cutover固定gap读取同一状态。对照区分时间输入变化与历史状态变化；cutover固定gap本身不代表发布后真实请求，只是控制变量。旧F不重新拟合。
- **候选面板与可预测性。** 同一64候选池中比较固定history/uniform面板及teacher-only定义的近分面板；F和teacher目标只算一次后切片。以当前物品嵌入的固定16维投影做闭式ridge，比较常数、真实物品及同UID内置换物品信息；真实与置换分别用同网格、同fit/val预算选正则。只预测冻结F剩余read/logit残差，不注入最终读路径；panel中心化目标和teacher-only选择是诊断，不冒称单请求部署方法。
- **校准源是否代表保留状态。** 同原始cutover、候选、拟合用户、目标与预算，增加在旧目标原生状态N上拟合的refresh，原有在实际旧映射状态A上拟合的refresh不改。交叉两种map×两种输入，统一对新目标teacher评分，避免把“某个map在两个输入都更好”误归为纯输入匹配效果。各拟合使用同算法、仅fit数据重算自己的归一化。

新的小人口运行仅作数值/效率检查；所有机制判读使用至少512名不同用户。先看两边，不默认扩大到五边或增加基础模型训练。保留负结果、实际支持数、配置与额外研究费用。

### 拓展发现一：总体偏移与候选间细节可以有不同表现

固定Q16误差可精确分解为每用户共同偏移的平方，以及去掉这一偏移后的候选中心化MSE。共同偏移的修复本身有意义，尤其可能影响跨用户汇总的反馈分数；这里拆分是为了看清另一部分，不把中心化指标替换原始MSE或AUC。

原数据中，append128时两边中心化MSE较同UID cutover增加约98%/138%，但teacher自身候选分数方差增加得更多。按teacher方差归一化后，误差反而从0.1355%→0.0881%、0.0965%→0.0641%，配对下降区间均排除零。原Q16的次序不一致变化区间也跨零。因此这些数据**仍不支持候选判别随历史持续退化**；绝对中心化误差增长不能单独充当该叙事。详见旧run的`residual_angles/report.md`与补充`teacher_scale_check.md`，两份均保留。

更有信息的是新源状态对照：在案例B实际A输入上，RA比RN的总体教师MSE更低（0.0211778对0.0230780），候选中心化MSE却更高（1.71888e−5对1.53298e−5）；两项差异的配对区间均排除零。案例A中，两个简单刷新都减少约33%–40%的总体MSE，但候选中心化误差仅减少约1%–3%，区间均跨零。简单correction可以修复很多总体误差，同时留下不同性质的候选间细节；它也可以在别的版本较好修复这些细节，不能概括为静态映射普遍做不到。

### 拓展发现二：候选相关的局部残差有结构

全部100个层头的分解保存在`residual_angles/head_residuals.csv`。总体候选变化比例很小，但事后识别的L0/H1在两边2,000用户上的候选中心能量比例约9.76%/9.73%，说明大能量公共残差会遮盖少数子空间的候选差异。这是探索性局部观察，不作为事先指定头的独立确认。

新实验固定F、cutover、时间和64候选池，broad16取池中前8与后8，near16只按teacher分数选择最小跨度的16项。每个面板的物品特征与残差按用户去候选均值；fit100、val16独立选择真实物品/置换物品两个同容量ridge的正则，main2,000仅评价。当前物品嵌入先作固定16维投影，不使用teacher目标作为预测输入。原生候选和query始终正确，置换仅作用于额外描述器。

| broad16局部read残差预测 | V1→V2 | V2→V3 |
| --- | ---: | ---: |
| 真实item相对常数减少的中心化残差 | 25.07% | 10.49% |
| 配对UID95%区间 | [23.62%, 26.66%] | [9.76%, 11.22%] |
| 上述改进占全部局部read残差 | 0.01905% | 0.004927% |

真实物品描述器也优于从头拟合、独立选正则的同容量置换描述器。两边都存在能由item信息预测的一部分局部候选残差，足以构成探索候选条件校正的理由；其绝对占比很小，不能描述为大幅质量恢复。这里的全部read占比是“长度归一化后各UID均值之比”，与前一段“每UID先取能量比再平均”口径不同，不直接比较两个百分比的大小变化。

保留限制：near16的read中心化残差仅改善2.49%/0.81%，绝对占比更小；broad16的logit残差改善接近零或区间跨零。案例B的near16 logit描述器还使中心化误差增加7.73%（UID95%增加[4.35%, 15.38%]）。因此当前证据是**item信息能够描述局部残差的一部分**，不等于item-only描述器能修好最终分数，更不等于最终门控效果。read与logit分别拟合，且都未注入读取路径，不能将此反例说成“优化read导致score退化”。

### 拓展发现三：误差大小需与候选分数间隔一起看

| teacher次序不一致率（学生ties计入） | V1→V2 | V2→V3 |
| --- | ---: | ---: |
| broad16 | 0.673% | 0.775% |
| near16 | 2.658% | 3.403% |
| near−broad，百分点 | +1.985 | +2.628 |
| 配对UID95%区间，百分点 | [1.816, 2.163] | [2.413, 2.848] |

两个面板在同一64候选池、同一用户状态下定义。近分面板的绝对残差更小，但teacher候选分数间隔也小，教师次序更容易不同。每边240,000个候选对的teacher非零支持均大于99.99%，浮点ties不是主体。面板只由teacher定义，不看F误差或未来标签；它是条件场景诊断，不能称作真实推荐AUC、检索质量或线上候选集现象。

两个面板相关，不作为独立重复；不因为near更敏感就替换原broad结果。完整模型、正则网格、层头及配对几何统计见`candidate_edge2/analysis`、`candidate_edge3/analysis`，其中负结果同样保留。

### 补充几何：少量候选变化方向值得探索

对每UID/层头的16候选×32维中心化局部read残差作事后SVD：broad16的rank1能量保留为99.25%/99.14%，near16为98.62%/98.56%；rank2在四个面板均超过99.97%。这说明这些快照中可见的候选残差并非任意高维噪声，值得尝试小容量候选侧调节。

这里没有历史行轴，且Q16中心化本身rank≤15；所以这些数字**不能**转述为E6的h截断、每行code2足够、质量恢复率或样本外因子可学习性。near面板的候选分量尤其小。每头完整统计、零残差计数和区间见各`candidate_edge*/rank_analysis`，不选取单一正头或单一面板代替总体。

### 未成为一致动机的配置：校准源匹配

同预算2×2中，案例A的RN在N/A两种输入上总体MSE都更好；案例B的RA总体MSE点估计双赢，但N输入上的优势区间跨零。两例总体交互为正，也不能推出每个输入都受益于源匹配。候选中心化误差的偏好还可能与总体偏好不同。因此本轮不把“必须用实际保留状态校准”写成已观察到的一致规律，而将它记录为版本与配置敏感性。

两套校准都仅用fit数据按同算法重算自己的归一化；归一化变化是本次处理的一部分。RN/RA快照费用约为一次新目标重建的59.2%/61.0%，原生N输入的诊断重建和前一版本工作另列，不称完整230次读取成本。两边全部4格、未校正端点、区间与费用见`source_cross_edge2/analysis`、`source_cross_edge3/analysis`。

### 时间控制的实际结果

两条边各2,000人全部完成，保留旧runner的advance边界，评分循环各约506秒（同GPU并发，非受控性能指标）。原合成append检查点在目标行为时间戳+1秒定义，因此“actual_gap”在这些检查点按构造为1秒，**不是未来真实反馈请求gap分布**。对照把同一用户同一检查点的gap改成其cutover原值，缓存、候选和teacher路径不变。

| append128候选中心化MSE | V1→V2，1,148 UID | V2→V3，1,141 UID |
| --- | ---: | ---: |
| 同UID cutover | 4.13950e−6 | 2.37915e−6 |
| 合成检查点gap=1秒 | 8.17799e−6 | 5.66251e−6 |
| 固定cutover gap | 3.47892e−6 | 2.12467e−6 |
| 固定gap相对cutover变化 | −6.6057e−7 | −2.5447e−7 |
| 上项UID95%区间 | [−9.4162e−7, −4.1215e−7] | [−4.1246e−7, −1.1155e−7] |

固定gap后，绝对中心化误差增长消失。两种gap下，按各自teacher候选方差归一化的误差都下降，不能写相对判别逐渐退化。可以保留的观察是：**同一个缓存近似的残差受读取上下文影响，cutover快照上的一个数不能代替其他读取条件**。固定gap是反事实控制，不是线上部署策略；结果也未独立定位到某个写入操作。

完整配对表、teacher方差尺度及原始分数在`gap_edge2/analysis`、`gap_edge3/analysis`；原始实际gap指标未覆盖。这组控制避免把时间输入切换包装成历史误差累积。

### 人口敏感性与运行核查

用固定规则`sha256('insight-extensions/20261023/'+uid).digest()[0] % 2`，先保存成员再读结果，将原2,000人分为973/1,027人，跨边成员一致。沿用既有fit100/val16选出的权重、尺度与正则，无重拟合、无挑选较好组。

两组broad16候选中心化read残差的真实item改进分别为24.82%/25.32%（边2）、10.29%/10.68%（边3），四组均优于置换且配对区间为正。四组near−broad次序不一致增加约1.86–2.71个百分点。它们是同一批已观察用户的固定权重敏感性，不是独立确认、拟合种子重复或五边稳定性。完整成员与两组所有结果见`split_check/`。

本轮新增6个人口运行（gap、candidate、source-cross各两边），每次固定main2,000人均exit0；加上已有数据CPU分解、事后几何与两个哈希子组。新增语义/统计检查与前轮相关检查合计35项通过，实际Large小人口检查仅验证数值和执行：gap/cache批量评分最大差7.15e−7，2×2实际源端点与原版本实验一致。

计算费用不混用：candidate目标收集分别约81.76/83.22 TFLOPs，包含fit/val/main的原生source和teacher重建、F物化、64候选两路径、same-q teacher read及投影；这是研究观察成本。两个面板、两种信息条件、read/logit的全部ridge拟合与验证约1.134 GFLOPs/边；全部main线性预测约13.111 GFLOPs/边。它们不包含原F的沉没成本，也不作为最终Design部署成本。校准源两套小模型仍为100fit、cap256，不新增foundation训练。

### 现在可以采用的动机链（仍未修改论文）

**建议主线：简单映射能够便宜地修复大量失配，但总体平均会掩盖与当前读取有关的细节。** 局部残差在少数子空间具有候选相关结构，物品信息能在不同用户上预测其中一部分；候选分数接近时，小残差也更容易对应次序变化。因此，让校正分支显式获得当前候选、尝试小幅且低开销的条件调节，是有数据依据的设计动机。这里无需断言所有静态映射都不可能做到，也无需在Motivation中证明具体门控优越。

事后read输出几何提示可以从小容量描述开始，3.2的费用边界则要求避免昂贵的每候选每行MLP；候选门控、紧凑状态及其具体容量由Design提出，再由Evaluation比较其有效性。旧版本校正的失配案例继续动机化版本维护；新时间控制则提醒校准应覆盖实际读取上下文。三个问题分别说明，不串成“f、fg、fgh必定层层上升”。

本轮保留的反例同样重要：没有历史越长越差的证据，item-only分数预测可以失败，校准源匹配没有一致优势。可将这些结果用来缩小主张、选择下一步问题，而非改写成预设收益。
