# 02 连续五次发布

对应Figure 7。回答固定默认方案在连续发布与实际追加后，恢复与完整成本能否持续保持。

- 范围：四配置V1–V5，只研究我们方法的连续跨版演化，不要求实验01各基线适配连续发布；不能每版换回新生成的源cache。
- 输入：01选定的默认设置；本实验独立建立V0起点、origin、逐版校准来源和连续状态。Reuse／Rebuild参照须绑定本实验共同协议，不能直接拼接01逐边分数。
- 前置：首版origin因果建立、后续来源一致、五版输出齐备；代数合成等价核对不能替代质量。
- 输出：逐版绝对AUC、gap、恢复率和完整成本；连续轨迹保存在02，其他分析按路径引用，不复制大份cache。
- 资源：质量与FLOPs可共享GPU；需要实际生成连续轨迹，不是01独立边的CPU汇总。
- 当前：Yambda底座五次更新在，最终默认连续纠正轨迹尚缺。

配置／汇总说明放 `configs/`，派生结果与来源引用放 `runs/`；见[总索引](../README.md)。
