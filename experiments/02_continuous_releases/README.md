# 02 连续五次发布

对应Figure 7。回答固定默认方案在连续发布与实际追加后，恢复与完整成本能否持续保持。

- 范围：四配置V1–V5；保留各方法自己的连续状态，不能每版换回新生成的源cache。
- 输入：01中默认候选完整轨迹、逐版Reuse／Rebuild参照、逐版费用。
- 前置：首版origin因果建立、后续来源一致、五版输出齐备；代数合成等价核对不能替代质量。
- 输出：逐版绝对AUC、gap、恢复率和完整成本；记录来自01的结果路径，不复制cache或重新跑默认链。
- 资源：质量与FLOPs可共享GPU；若01已产出所需字段，本实验主要是CPU汇总。
- 当前：Yambda底座五次更新在，最终默认连续纠正轨迹尚缺。

配置／汇总说明放 `configs/`，派生结果与来源引用放 `runs/`；见[总索引](../README.md)。
