# 08 适用边界

对应Figure 11的两个面板，固定最终机制后解释何时收益减弱。

- 长期固定发布：代表Yambda-Max，冻结模型与纠正参数，沿真实行为流累计追加，FIFO窗口保持N；在真实反馈事件上评价质量和累计FLOPs。优先复用01较早独立边或02较早连续快照，明确来源身份。
- 读取量边界：固定历史／追加条件，用四配置正式操作账推导读取量与净节省关系；不是线上请求分布或额外质量证据。
- 前置：最终候选快照和完整账；长期检查点的可观察人口及正负反馈量。不能事后只选达到2N追加的用户当总体。
- 输出：追加检查点的绝对质量／恢复、累计费用及样本数；CPU边界曲线与实际系数、假设。
- 资源：长期质量与FLOPs可共享GPU；公式核算主要CPU，无须独占计时。
- 当前：Max自然追加量覆盖已核实，正式长期质量和最终成本系数待完成。

配置放 `configs/`，两个面板的结果与输入引用放 `runs/`；见[总索引](../README.md)。
