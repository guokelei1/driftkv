# RecFlow Max：十模型、九条相邻更新边的评测明细

建议优先使用 **M0→M1、M4→M5** 做缓存复用受损的主案例；二者在原开发、未见用户确认、追加时序组中，NDCG@10 的配对 UID 95% 区间均完全为正。扩展案例依次考虑 **M2→M3、M7→M8**；保留 **M5→M6** 作为反向对照。选择依据是已观察的基线结果，因此这些是有依据的后续案例选择，不是对任意版本均会受损的无条件证明。

## 指标及比较含义

- 主指标：observed-positive request-macro NDCG@10；辅助指标：Recall@10；@5/@20 全部保存在配套 CSV。
- Rebuild：当前模型编码该请求严格过去的 1024 条历史，并由当前模型打分。Reuse：直接父模型编码同一历史，当前模型读取父版 KV 并打分。两路使用相同的完整日志排序候选。
- 绝对下降 Δ = Rebuild − Reuse；相对下降 = 100 × Δ / Rebuild。负值表示 Reuse 更高。表格为原始 0–1 指标尺度；例如 Δ=0.005473 等于 0.5473 个百分点，不是相对下降 0.5473%。
- 正例仅指已曝光且有效观看；未曝光是未知，只有零观测增益，不能当作真实负反馈。这是完整日志候选池排序，不能解释为无偏在线效果。
- 每个正例请求先计算指标，再对请求等权平均；零正例请求保留计数，不进入这两个指标的均值。
- 表中区间只针对 NDCG@10 的配对差值：UID 聚类 bootstrap，2000 次、seed 17、名义 95%。没有跨版本多重检验校正；Recall 表仅为点估计，未新增其置信区间。
- 本轮是逐请求匹配因果前缀的版本快照比较。每个请求都使用它自己的历史；不是在日初写一次缓存、整天持续复用的 serving/FIFO 实验。

## 后续论文实验的选边建议

| 优先级/用途 | 更新边 | 依据与限制 |
| --- | --- | --- |
| 1：主案例 | M0→M1 | 三组 NDCG 区间均为正，未见用户确认相对下降 16.24%，时序组 13.89%；Recall 同向。首次日更新损失最大，适合做清晰的机制与恢复实验。 |
| 2：常规更新复现 | M4→M5 | 三组区间均为正，未见用户确认下降 3.91%，时序组 3.60%；Recall 同向。可检验方法是否超出首次更新场景。 |
| 3：较小损失补充 | M2→M3 | 开发、时序组区间为正；未见用户确认点估计下降 1.30%，但区间跨零。不能称三组均确认。 |
| 4：较后版本补充 | M7→M8 | 时序组下降 2.20%、区间为正；其余两组 NDCG 点估计同向，但区间跨零；开发组 Recall 基本持平。 |
| 备选：人群差异案例 | M6→M7 | 时序组下降 1.97%，但开发点估计反向、确认接近零；确认 Recall 也反向。适合观察人群差异，不优先用作普遍损失证据。 |
| 备选：弱效应 | M1→M2 | 时序组下降 1.51%，区间下界仅 0.00002982；原两组均跨零。证据较弱，恢复率分母小。 |
| 反向对照 | M5→M6 | 时序组 Reuse 比 Rebuild 高 2.05%，区间完全反向；检验校准是否会引入额外损伤，报告原始质量差，不套用正损失恢复率。 |
| 反向/弱效应对照 | M3→M4 | 时序组反向 1.29%，但区间上界仅 −0.00001776；原确认接近零。保留，不作为正损失主案例。 |
| 低优先级 | M8→M9 | 三组主窗口区间均跨零，额外 D37 也跨零且反向；当前不支持稳定损失。 |

如果后续只做两条，选择 M0→M1 和 M4→M5；需要四条时再加 M2→M3、M7→M8。建议用同一固定时序人群和相同协议运行所有所选方法，并保留原确认组复核；完整九边基线及反向对照同时报告，不逐边挑更有利的人群。当前结果只说明哪些更新边适合研究版本兼容性，不证明校准方法已经有效。
