# Query relay 探索

目标：用非线性的 Query 门控读取纠正、简单的逐次发布校准和有界的码状态，贯通 D1/D2/D3。原生 K/V 保留；纠正历史读取参与新增 K/V 写入。质量目标是总体恢复率 80% 以上；成本目标是完整新增 FLOPs 不超过首次请求重建基线的约 20%。当前冻结候选为`A_itemgate6_rms_roll4`，完整开发人口、另一组新用户确认及独立静态对照均已完成；主行为任务通过，原反馈任务未达联合目标，详见[报告](/home/gkl/work/evokv/results/query_relay_2026_10/report.md)。早期layer-query A满足主任务恢复率/成本，却没有动态排序收益，不能作为最终动态性证据。

- `adapter.py`：共享 12＋每头私有 6 的 48 维码。A/B 为可合成的仿射码更新；C 为非线性递推对照，不保证能直接合成。Query 门控与读取投影可逐次发布调整。
- `gate_source=item`：门控使用本次候选或行为物品的Current完整embedding，原生各层q及q码投影不变；lookup流量单独收费，门控/RMS算术继续收费。当前只读共享3＋私有3；其余码维度保留给跨版演化，不声称完整18维满足成本目标。
- `session.py`：真实因果行为追加、纠正读取、FIFO 淘汰、当前新增零码；显式递推与编译锚码两种执行方式。零码是协议，不代表上层新增 K/V 等于 Fresh。
- `calibrate.py`：冻结骨干，局部读取对齐＋完整 query 的教师分数对齐。首次发布用 V2 原生来源；后续发布必须使用候选自己的连续状态。
- `--freeze-gates`：恒1门控独立静态控制，保留相同编码/递推和两个目标，但使用自己的训练来源、写入与carry checkpoint；不是在动态轨迹上只读覆盖门控。
- `evaluate.py`：保留原反馈任务；新的行为触发任务使用新的 Reuse/Rebuild 控制。门控均值替换只检验固定轨迹上的动态读取，不代表另一条写入策略。
- `aggregate.py`：合并互斥的冻结用户 shard 和已有小样本，校验完整目标人口与校准/全目录发布绑定。全部 matched scores 重新计算等发布 AUC 与共同 UID bootstrap，保留逐用户记录、服务计数和读取账本；同时报告动态门控相对 fit-only 均值门控，以及推荐轮次内 pair AUC/Hit/NDCG。
- `aggregate_same_history.py`：合并同历史、同候选集合的只读门控消融，逐项对照 retained native controls 和 dynamic 轨迹。共同 UID 重采样分析 pooled AUC、组内去offset的MSE与pair AUC，按活跃集合数合并门控矩；该消融仅去掉候选内门控变化，q投影和普通attention仍依赖query。
- `workload.py`：预登记 stride 8/16/32、每轮 2/16 候选。开发主设置为每 16 次行为触发一次推荐、16 候选，首个行为触发回流推荐。查询历史严格排除同时间行为。该任务为 next-item＋均匀负采样，不能与原反馈 AUC 混为一谈。
- `cost.py`：独立固定 30k 用户真实事件账本，计入读、写、码准备、锚码转换和共享发布准备。理论容量敏感性与实装读取宽度明确区分。
- `calibration_cost.py`：在已有计算边界累计局部 padded 读取、重新编码、冻结骨干 query 反传、教师捕获与行为写入 unroll 的 FLOPs。反传沿用保守的两倍前向估计；调用次数本身不能代替实际形状。
- `publish.py`：按原始模型物品 ID 编译完整 `[6, num_items+1, 48, ξ]` 发布表，保存实际算术、内存与广播字节；连续发布从上一份完整表合成，不依赖开发用户或未来物品并集。
- `precision.py`：`--anchor-inverse actual`对实际保存的P小块一次发布级FP64求逆后保存FP32，处理连乘转置不完全等于逆的问题。新增全局小矩阵和准备FLOPs单列；无额外行状态，不能保证无限发布数值精度。
- `diagnose_code_use.py`：固定动态写入轨迹，比较真实码、零码与仅从fit历史得到的全局均值码；实际历史码作用与仅Query门控作用分别检验。
- `budget_audit.py`：读取已完成的逐版校准和全目录发布，更新 `results/query_relay_2026_10/cost/current_candidate_budget.json/.md`。原始 origin 校准只收费一次；待完成校准不作假设，未发布编译项明确标为几何预测。主工作负载、原反馈和预登记频率分别使用自己的重建分母，同时报告完整 query 增量和全局共享表内存。

实验均写入 `/home/gkl/work/evokv/results/query_relay_2026_10/`。校准默认使用保留了 fit/validation 历史的 benchmark panel；质量默认使用 representative4096 panel，沿用冻结角色。小样本只检验机制，不构成总体质量证明。

完整读取每头 18 维存在显著写入成本压力。每头 12/6 维是明确的容量退让分支，其效果需要重新测量；不能沿用原共享结构的质量结论。编译评估可以仅建立开发子集物品表，但正式成本必须按完整部署范围收费。

原请求 builder 将真实 feedback 按用户、时间、物品分组，并过滤冲突标签；它没有控制推荐频率的 stride 参数。新的行为任务选择每版首个实际行为及其后每第 16 个行为，在该行为发生前，用严格更早的历史评分：一个观察到的物品加 15 个均匀采样物品。负样本只排除该轮正样本，不读取用户未来行为。它是合成 next-item 候选任务，并不声称这些采样物品是真实反馈负例。原反馈与新任务分别报告 AUC、恢复率和成本，不混合聚合。

主设置已在质量评估前登记为 stride16、16 候选；stride8/32 与 2 候选全部保留作工作负载敏感性。一次推荐轮次和一次候选评分是不同计数。每个 workload 都重新计算用户每版首次真实推荐的 Rebuild 分母，保留全部行为写入；不能沿用原请求的分母，也不能只报告刚好低于预算的设置。

20%预算以“全部新增方法FLOPs／每用户每版首推荐KV重建FLOPs”为分母，不是整个服务的成本占比。完整建模服务另算：Full＝共同native历史追加＋完整query＋首推荐KV重建；Relay＝同样的native追加/query＋全部新增方法成本（含校准和共享准备）。其净节省相对Full总服务报告，源状态需要重建时另列敏感性。query额外开销同时对完整native query和仅历史/self注意力报告；后者从真实读取矩阵形状计算QK、scale/ELU+1和AV，不含embedding、投影、门控和最终评分。这一阶段继承初始V2缓存，基础模型训练、检索基础设施、传输和实际运行时间不在这些FLOPs总量中。

初始采用已有 Structured V3 权重时，其 V3 校准费用约 9.695TF 只收取一次；未使用的历史 V4/V5 校准不收费。后续候选发布逐版记录自己的校准费用，前版候选 warmstart 不递归重复收费。教师重建计入主成本；若源状态需要重建，另列敏感性，或在确实必需时计入主成本。当前候选在相同教师分数目标下加入 4 步因果行为写入展开；这让校准覆盖短程续写，不构成长程残差已解决的证明。

RMS 门控对每个 Query、每个头只归一化一次，Key/Value 门控共享它；这部分 FLOPs 在读取、校准及写入中都收费。每头 6 维可以是纯私有 6，也可以是共享 3＋私有 3，二者读取算术相同，但表达和质量必须分别验证。主成本暂保留四份独立物品准备；一次离线编译再广播四份作为单列敏感性，保留四份内存并报告 D/P/Q 发布传输字节，不把广播假定作为默认过预算办法。

`feature_mode=origin_encoder` 是新增的固定特征分支：η使用冻结的 Structured V3 原编码器与冻结的 V3 物品表示，输入仍为存活条目的原生 K/V 和固定物品 ID。固定商品投影表按 `[6, catalogue, 48]` 保存一次，偏置单独保存以保持原加法顺序；每次更新只查表、投影原生 K/V 并执行 SiLU，ξ仍按需使用原生 RMS 摘要。它不增加逐条目状态，且可继续精确合成更新，但增加约 1.59GB 的单份共享表。完整成本单次收取该表的四份准备和存储；离线编译广播的传输另列。校准中记录实际构建资源，不在每版拟合和全点共享准备之间重复收费。
