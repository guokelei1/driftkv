# 相关工作与比较定位

审读日期：2026-10-19。本文为系统实验计划输入，不改变论文主张。

## 方法定位

CacheReforge 面向同一 adapter 连续更新，保留逐层参数锚点，以离线敏感度和运行时漂移选择连续重算区间，覆盖区间内的原生 K/V。DroidSpeak 则为模型对选择重算层，并优化跨节点缓存加载。两者均属于按层复用与重算；DroidSpeak 的应用背景也包含模型更新，因此“面向连续更新”本身不足以区分我们。[CacheReforge 正文与附录](https://arxiv.org/html/2609.30884v1)、[DroidSpeak 官方论文](https://www.usenix.org/system/files/nsdi26-liu-yuhan.pdf)

CacheTide 的待验证差异是：保留原生 K/V，在读取时进行候选相关纠正，并合成跨发布码更新。这与重算路径不同，但不能据此推断质量或成本更优。也应避免将静态映射描述为完全没有 Query 相关响应。

## 可借鉴的论证组织

CacheReforge 的四个实验问题形成“失配是否重要—恢复范围多大—范围由什么决定—连续运行是否划算”的证据链。我们的实验可据此分别回答问题强度、收益边界、机制作用和完整服务收益，无需复制其配置数量。

图的职责也应明确：选择对比图解释取舍；状态图把决策与状态变化对齐；质量图同时呈现任务收益与教师偏差；分布图呈现失败区域；机制图解释差异来源。每张图应回答一个问题。

## 比较实现与审稿问题

建议在我们的模型和连续轨迹上建立“校准选层重算”比较：仅用拟合用户选层或连续区间，固定后在相同评估用户、发布和请求序列上执行；保留重算后的状态供后续请求复用。明确可用起点及其隐藏状态来源，并计入校准、额外状态、重算与读取成本。称为适配的按层重算基线，不能声称直接复现完整 LoRA 服务系统。

比较应回答：

- 相同完整预算下，纠正是否优于重算一部分状态？
- Query 门控的收益是否超过匹配预算的静态映射或简单适配器？
- 缺席发布、持续追加和较长历史是否改变优势？
- 收益来自维护节省，还是转移成每次读取的额外开销？

## 证据边界

CacheReforge 的连续实验采用固定前缀和受控 LoRA 更新；其离线理论量与运行时漂移代理不同，后者不具有逐请求质量保证。执行层比例、缓存维护时间和总请求时间也不能互换，不能直接对照我们的完整 FLOPs。公开配置与汇总适合核实这些口径，不作为工业负载证据。[作者公开实验包](https://doi.org/10.5281/zenodo.22951118)
