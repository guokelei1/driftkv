# 当前研究状态与路线

更新日期：2026-08-11。

## 1. 研究问题

模型按时间窗口连续更新为 θ1、θ2、…；线上只使用一个当前模型 θt。若用户前缀 K/V 仍来自旧模型 θs，系统可以直接 Reuse，也可以用 θt 完整 Recompute。本文要研究二者之间可利用的精度—开销空间，并据此设计比全量重算便宜、比直接复用准确的维护方法。

第一步不是优化维护算子，而是建立一条真实、可重建、重复出现 Recompute 优于 Reuse 的大模型版本链。该基础现在已经具备。

## 2. 已选第一轮基线

数据与时间：

- KuaiRand-1K standard log；random-exposure log 不参与训练或评测。
- 2022-04-08 至 2022-04-21 构造 θ0。
- θ1–θ8 分别使用 04-22 至 04-29 的当天数据更新，并在各自下一自然日评测。
- 更新日目标不会进入同一版本的预测集；历史、正样本和候选集合均按 [评测协议](eval_protocol.md) 固定。

模型与目标：

- 8 层 HSTU，hidden size 512，8 heads，最大序列长度 512。
- video 与 author 两个字段，`latest_item_query`，归一化 sampled-softmax next-item 目标。
- 自然模型为 6,033,893,120 parameter bytes（5.620 GiB）。
- 冻结日窗口训练日程为：θ1/θ2 各 4 epochs；θ3 2 epochs；θ4 3 epochs；θ5/θ6/θ7 各 2 epochs；θ8 3 epochs。每个版本最多使用 20,000 个更新样本，具体学习率由冻结配置逐版本给出。

大模型容量：

- 使用 `strided_hash_v0` 将物理 embedding 容量扩至自然语义空间的 8 倍，只有一份 embedding，不使用相同副本伪造容量。
- 23,396,297 个物理行中，2,924,537 行可由当前 trace 访问；其余 20,471,759 行是不同的冷 catalog 行。
- 真实可达行、dense core 与 projection 从自然链逐元素搬运，最大 active-row 误差为 0；冷行只增加容量，不改变当前请求的函数。
- 每个版本为 47,960,055,552 parameter bytes（44.666 GiB），每份完整 checkpoint 为 48,077,080,276 bytes；模型必须在 GPU0/GPU1 两卡分片执行。
- 大模型推理得到的 28 个格与自然链完全一致。这证明扩容没有改变任务函数，但不证明冷行本身提升了推荐质量。

结论边界：

- 相邻版本 7/7 为正，均值 `+6.007%`，最小 `+1.613%`。
- 全部 28 格中 26 格为正，均值 `+8.852%`，中位数 `+6.612%`。
- 更旧 cache 往往损失更大，并出现 θ4←θ1 的 `+39.688%` 等突增，但不是逐 age 单调。
- θ5←θ3 与 θ7←θ4 为负值，必须原样报告；Full Recompute 是 cache 一致性参照，不是每个有限候选排名样本上的数学上界。
- MRR 与 HR@5 同时保存在结果文件中，不以单一指标替代全部推荐质量。

## 4. 为什么这条链可以作为第一轮 baseline

它满足当前机制开发所需的四个条件：连续自然日更新、所有相邻边都有正空间、跨版本通常会累积、物理参数超过单卡容量。评测是在真实两卡大模型上执行，而不是把中模型数值手工复制进表；容量 lift 的函数保持性质和两侧数值相等都由结果与验证器记录。

它仍然只是 `scientific_result=false`、`formal_result=false` 的单 seed 开发基线。论文正式结论还需要独立 seed、置信区间和冻结后的跨数据集确认。当前不能宣称损失必然随 age 单调，也不能宣称 44.67 GiB 模型比 5.62 GiB 模型质量更好。

## 5. 已淘汰的做法

- 不再用人为 K/V 坐标变换、手动乘倍数或事后改候选数制造矩阵。
- 不再以两层小模型或随机逐版本“抽卡”作为大模型结论。
- 不把 Recompute 强行设为每格质量上界，也不删除不利格子。
- 不继续维护互相冲突的旧路线文档；需要历史时以 git 历史和紧凑结果为准。

## 6. 下一步

先冻结这条链作为机制开发输入，不再为美化矩阵重训。下一阶段只做：

1. 在同一 θ1–θ8、同一候选集上实现并评测 cache 维护方法；
2. 报告方法恢复了多少 Recompute-over-Reuse gap，以及真实 GPU 时间、显存和传输开销；
3. 机制稳定后再做独立 seed 和正式协议，不把当前开发选择当作独立重复；
4. 模型文件丢失时严格按 [基线复现说明](BASELINE_REPRODUCTION.md) 重建，禁止从旧实验路径拼装 checkpoint。
