# 专家建议：从修正的校准依据到缓存续用决策

来源：用户于 2026-09-08 提供的完整专家意见。以下为按原有九个主题整理的存档，
保留建议、例子、反例、执行边界与引用，不是逐字转录。仓库核对与修订意见另见
[review.md](review.md)，不将专家的假设改写成已有实现或实验结论。

## 核心判断

“估计这份状态的风险”本身就是 Design 2 需要研究的核心，不能假定已解决。
再训练一个风险网络可能只是把共享修正器的泛化问题转给另一个共享预测器；
只依靠年龄或长度又容易成为经验规则。

首选折中：不另训“用户是否危险”的分类器，利用 Design 1 正则最小二乘的校准过程，
先检查当前修正是否被已有数据充分约束，再用独立校准残余判断这个检查能信到什么程度。
优先研究这条检测路线，不提前称为可靠误差上界。

## 一、统一框架只保留三步

继续使用 Design 1 → 检查实际状态下的修正是否仍有依据、是否仍划算 →
必要时在预算内完整重建，建立新的状态起点。

质量依据与计算费用分别判断，不凑成含义模糊的健康分数。多次更新、特殊状态和
短历史进入同一个流程：前两者可能使修正失去可靠依据，短历史可能即使修正准确
也不值得继续支付适配费用。重建改变后续使用的真实 KV，而非只换本次输出。

## 二、检测对象

已经发生的历史并非未知；未知的是这些历史在当前模型下完整重算后对本次查询的结果。
服务时可见实际缓存、历史事件、当前模型、query 和 Design 1 输出，缺少逐用户
Current Exact 参考，因为取得它正是希望避免的计算。

第一版直接目标为同查询最终输出的绝对残余：

\[
e=|z_{\mathrm{adapt}}-z_{\mathrm{Exact}}|.
\]

服务时不能读取右侧 Exact；开发和独立校准可以取得参考来评价检测效果。
不要预测单用户“未来 AUC”：AUC 依赖一组带标签请求，不是单份缓存的当场属性。
最终系统仍需真实 AUC 评价，教师距离与 AUC 已知不完全一致。

检测的是“应用 Design 1 后，当前状态与查询是否落在它能可靠处理的范围”，
不是旧 KV 的变化是否很大。大变化可以被准确修正，表面正常的缓存也可能被严重过修正。
使用绝对输出误差或明确定义尺度的读取误差，不除以接近零的模型更新 AUC 收益。

## 三、不宜作为核心的便宜指标

1. **版本年龄、历史长度。** 它们提供背景和成本信息，不直接表达修正方向是否正确。
   但执行语义上的固定规则仍合理，例如版本/修订不匹配应刷新，满足已验证依赖消退
   条件可关闭修正；这与“年龄过阈值就是坏缓存”不同。
2. **修正幅度、输入范数、预测熵。** 大修正可能必要，概率接近 0/1 也不意味着复用正确。
   既有源范数缩减没有发现全部大误差用户；native 响应为零时关闭修正会删去目标模型
   可能需要的合法变化。数值异常不等于修正缺乏依据。
3. **两种近似方法一致。** native 输入与摘要输入预测差可作诊断，不能单独证明正确：
   两者可能共享盲区、一起预测错。重复刷新或分组前后相同也可能只是线性公式恒等，
   并未提供独立证据。不优先做“两个近似器同意就放行”。

## 四、首选指标：修正是否依赖未被校准确定的方向

在一层实际输入固定后，共享修正对系数线性，因此正则最小二乘不仅回答怎样拟合，
也允许问：是否有明显不同的系数同样解释校准数据，却在当前用户上给出不同修正？
若有，当前预测缺乏约束；若所有符合拟合证据的邻近系数给出相近预测，则该方向更稳定。

例子：校准中两个输入总是几乎相等，依赖第一项或第二项都能拟合。
新状态两个输入一正一负，范数仍正常，但两种系数产生相反预测。
范数检查可能漏掉，而方向约束检查能发现依据不足。
摘要、query、native 响应之间也可能出现这种组合关系；这只是机制例子，
尚未证明连续迁移的错误都由此产生。

先考虑一层一个输出分量。将源状态与 query 的交互以及 native 响应合成实际输入 f；
不能只用 PCA 后源编码。若 H 是已有正则最小二乘目标的二次项矩阵：

\[
u(f)=\sqrt{f^\top H^{-1}f}.
\]

它表示在相同拟合目标容许的系数变化范围内，当前输入预测可变化的程度。
大 u 表示预测依赖校准约束较弱的方向，不用标签或服务用户 Exact，
也不另训好用户/坏用户分类器。

回归几何有统计基础，但覆盖、估计误差和模型近似误差不能混同。[来源 1](https://arxiv.org/abs/1106.2363)
必须采用实际算法的权重、归一化和长度换算。若拟合的是率、服务乘历史长度，
不能只看率坐标就判断聚合响应风险，也不能给检测随意另定标准化。

与源范数缩减的区别是：看输入关系；包含本次实际 query 和 native 响应；
参照本次目标版本的校准目标。它判断实际修正输入，不给用户身份贴标签。
旧状态、少见用户不必一定拒绝；常见长度、新 producer 也不必自动通过。

## 五、补上误差尺度与输出影响

### 独立残余校准

u 首先是预测约束程度，不是缓存错误概率。在独立于参数拟合的用户上同时记录 u
与适配后的真实残余，先问：低 u 是否对应小且稳定的误差，高 u 是否集中严重失败？
成立后，才依据事先明确的误差容忍度确定经验续用范围。

这是为有计算意义的标尺校准适用范围，不是再拟合高维用户分类器。
留出误差分布估计有相关研究，但依赖数据条件，不能直接推成任意跨版本保证。
[来源 2](https://proceedings.mlr.press/v151/patil22a.html)

必须按 UID 分组；同用户的 16 个 query、多个快照不等于 16 名或更多独立用户。

### 输出敏感程度

同样的局部修正变化在不同层对最终分数影响不同。可进一步利用模型导数，
观察本层修正轻微变化时最终 logit 如何变化，再衡量前述不确定性。
计算链应包含下层修正改变上层 query 的影响，不把层当成相互独立模块。

先分开验证“仅回归约束”和“再加输出敏感度”。只有后者带来额外识别价值才考虑采用，
并计入反向计算和相关统计的 FLOPs，不因理论完整而默认上线全部导数。

## 六、主要盲区：稳定地预测错

校准约束充分不等于函数形式正确。摘要若遗漏关键信息，不同状态可能表现相同，
却需要不同目标修正；所有合理系数可一起稳定地给出错误答案，u 很小仍错。
强正则也可能稳定地收缩到错误预测。参数稳定不能解释为目标误差一定小。
误差界需要真实函数、数据或噪声假设，不能仅加“置信”名称。
[来源 3](https://arxiv.org/html/2408.09033v1)

尤其要检查既有拟合用户的严重过修正是否也被判为高可信；
不能只展示跨 UID 检测成功，忽略拟合内系统性盲区。

若两份缓存向检测器提供相同摘要、query 和 native 响应，却需要不同 Current 修正，
仅靠这些观测就无法区分。此信息限制不证明现实一定大量碰撞，但排除了预先承诺
覆盖所有用户、状态和版本。合理目标是在目标负载上实测低分区域能否可靠续用。

若大量严重错误集中在低 u，应承认现有观测不足，研究独立核对目标计算的信息，
而不是反复改阈值、扩大同类风险网络或排除难例。

随机对部分用户做 Exact 可评价整体误差，不能自动判定另一个未检查用户安全。
候选指标不同：对每个被服务的实际输入都可计算；少量教师只用于校准和评价。
有限校准不覆盖任意新状态，系统可输出“当前缺乏依据”，不强迫产生错误概率。

## 七、运行时机与重建

- **发布时：** 除共享修正系数，保留必要二阶统计和独立校准误差记录，按目标版本共享。
  先检查 producer 支持、格式和目标匹配等确定条件；它们不预测质量。
  如需发布时判断用户状态，可用少量预先规定、当时合法的检查 query 读取实际缓存，
  不构建人口 Exact；新增读取计 FLOPs，结果不保证未来所有候选。
- **实际评分时：** 使用已经产生的 query 和 native 响应检查本次修正。
  缓存没变可复用视图，但新 query 的质量依据可能改变；view 不 dirty 不能代替质量检查。
- **状态或模型变化时：** 新事件改变摘要与视图，发布更换转换器及其统计。
  不永久标记用户安全/危险。结构确定不需修正时可绕过对应近似检查；
  一般低分只提供经验续用依据，不意味着状态 Exact。
- **接回重建：** 依据不足不意味着立即重建，还要看预算和费用。
  即使依据充分，短历史重建更便宜也可重建。短历史无需硬塞进误差检测器。

## 八、检测自身的成本

p 维输入直接计算二次型需要平方级成本。当前联合特征在全层、全 head 上稠密计算，
可能明显贵于低维修正；没有教师不等于几乎免费。

候选方向是在发布时分解共享矩阵，读时投影到少量重要方向。
丢弃其余方向会压低不确定性：应保守处理余项，或明确它只是经验近似。
输出导数、检查查询、分组重拟合也都有费用：

\[
F_{\mathrm{Design2}}=
F_{\mathrm{prepare}}+F_{\mathrm{check}}+F_{\mathrm{rebuild}}.
\]

暂不确定最优压缩。先验证准确计算的指标有识别能力，再研究便宜计算；
原始指标无效时，压缩优化没有意义。

## 九、下一轮只验证核心假设

共享适配器的严重失准，能否由校准约束不足识别？输出敏感度是否带来额外价值？
先冻结 Design 1，使用已开放的单边、连续和短历史诊断，保留全部状态。
先仅用可部署信息算指标，再从独立诊断参考取得真实误差；不先造预算调度器，
不直接启动新 6000 人修复实验。

三种关键读数：

1. 允许续用比例增加时，剩余误差如何变化。不能拒绝几乎所有用户才显得可靠。
2. 同重建 FLOPs 选状态时覆盖多少严重误差；对照年龄、长度、旧源范数，
   同时保留不带成本的识别结果，防止把选择便宜短状态误称为检测准确。
3. 低分但严重失败的完整案例，尤其既有拟合用户过修正；假阴性可比平均相关性更关键。

阈值只能在拟合之外的校准侧确定，再到开发侧评价。按 UID 删除或分组重拟合时，
各分支应重新生成自己的上层 query；固定 query 的解析更新只是局部条件诊断，
不能称完整闭环留出。确认集继续不读。

假设成立后，下一轮才接“续用或重建”预算分配并测真实质量；
否则明确承认适配器内部统计不足以识别自身错误，转向独立观测研究，
不立即训练更大的风险网络。

## 建议落点

检测中心从“用户是否异常”改为“Design 1 对当前修正是否有充分依据”。
Design 1 从校准中得到如何修正，Design 2 尝试从同一计算证据得到何时有理由相信修正，
再由预算机制决定何时结束续用、建立新的真实状态。这一关系可解释且可落地，
但必须经低分严重失败的实测检验，不能凭公式就称检测已解决。
