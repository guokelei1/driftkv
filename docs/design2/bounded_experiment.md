# 三机制的完整原型实验

已完成，见[初稿主版本结论](../../results/design2/bounded_01/analysis/conclusion.md)。主候选为有限观察且在安装触发时采用目标输出；保持旧触发响应的版本作为失败时机消融保留。
完整回放2119.97s，全部分块exit0，原Fresh参考复用；直接候选输出入口与配对响应/动作/成本逐元素一致。

本轮用户已授权继续实现与实验，目标是形成机制覆盖完整、逻辑成立的论文初稿候选，不以调出某一小数点AUC或最优参数为目标。原Benchmark的数值目标仍逐项报告，不改成已经通过；参数敏感性和其他模型后置。

已实现真实请求边界安装、候选观察额度、witness逐请求输出和候选驻留事件。额度先固定为构造FLOPs的1/4。前次计划中的请求后安装/有限观察现在有可执行代码；结果完成前不称验证通过。

小样本验证：两个8UID开放canary均通过。post与已有完整即时witness动作相同，所有变动输出均为安装触发请求，共11评分行；预算canary覆盖3次耗尽、1次后续安装和模型变化失效，输出严格等于安装前服务值。128UID资源探针88.48s，主实验64块/四GPU估计37.75分钟，tmux d2_bounded_01；用户授权范围内，无训练、确认集或新模型。

直接回放两个策略post（无后续额度）与bounded（1/4额度），原4082UID及所有请求保持，轨迹独立。每次已经同时得到旧服务分数与候选分数，因此另保留安装时机×观察期限的配对返回规则对照：仅在真实安装时选择候选输出。固定回放的事件与请求不依赖返回分数，状态轨迹不变；必须先验证同样映射逐元素复现旧无期限即时原型，再形成有额度即时对照。不拼接未来状态，不利用标签改动作，不做加权分数混合。

三机制分别验什么：

| 机制 | 证据 |
|---|---|
| 共享服务证据，选择目标观察 | 原匹配消融保留；本轮记录真实筛查、构造覆盖与费用，检测参数不改 |
| 复用目标构造核验、观察、更新 | 同一构造的后续核验/安装、witness相对Fresh差异、写入及跨发布后的状态收益 |
| 有限观察与状态转换 | 额度是否真正限制后续工作；峰值候选驻留；请求边界改变哪些响应；正常服务和完整尾部的取舍 |

评价包括原全请求Fresh主/辅助尺度、AUC及routine逐边非劣区间，必须包含触发请求；补充后续请求指标仅解释持久作用，不能替代完整结果。额度控制的是候选后续追加/读取及检查计算；初次构造、首比较、安装与准入 bookkeeping 另列完整账本。观察期持久KV驻留按时间线报告，不把GPU分块运行峰值当人口峰值。

如请求后安装只留下严重触发错误，论文必须据实将它定位为取舍/消融；如果有限观察省费又保留保护，它仍可作为有意义的主机制。不能为了保住所提新规则而遮掉原型对照，也不承诺三个新选择都必然有效。
