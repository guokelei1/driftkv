# Benchmark后的三项推进

2026-09-09，用户授权适度扩大人口，检验短历史与连续状态，优先处理正常服务退化；
成本保持完整理论账本，允许3万约30%多、10万20%多、百万低于20%，不追求极限优化。
本轮工作目标3万≤40%、10万≤23%、百万≤15%，10万上限按此次要求放宽，非看结果后调整。
未来Design3可能节省的计算不预支、不隐藏。

固定[配置](../../configs/design2/scale_followup_01.json)后比较两项策略：首次实际请求才执行原费用/质量检查，
以及首次请求仅由质量拒绝触发重建。后者检验“检查贵就重建”是否对本来正常的状态作了不必要干预。
没有M1特殊规则，不改变C/H/校准分组或阈值。下一模型仍使检查与原重建锚点失效。
16候选的生成规则与随机种子固定；实际候选、query与native响应取首次请求时的合法历史，
因此不是与原发布面板相同的输入，也不宣称保持原动作。两条策略同时按这一新决策时刻比较。

自然负载扩大到2048UID（原1024＋标签无关哈希排序选1024成熟资格UID），新增人口排除拟合、残余校准、
原Design2各组和封存确认UID。分开报告原组与扩展组；扩展组是Design2新用户，不称整个研究从未使用的正式确认。
短窗口32/128各使用原前512UID，自M0起按同一个保留规则连续服务，所有真实请求与事件保留；
这些状态增加压力覆盖，不增加独立UID数量，不冒充自然短用户比例。

复用原四分支回放原语，各策略拥有真实KV。重建使用64行因果分块的五层完整计算及最后一层norm/KV，
逐点核对与完整Current KV一致；计入块内多余上三角GEMM，不能把稠密计算称成理想三角计算。
短窗口追加块不超过保留窗口，避免摘要淘汰尚未写入的条目；C的冻结坐标/依赖mask继续不改。

比较固定哈希30%首请求重建对照，采用同一真实重建动作、不支付不需要的检测准备。
它首先是费用—质量对照，不预先称严格同预算。若实际费用不同，完整展示差异，不靠只匹配重建次数造公平。
本轮不实现复杂预算调度器。

费用分别列实际闭环、仅共享准备KV计算作相同闭包改写的理论账本。不得删教师、删校准用户或套用未来压缩。
参考检查沿用首请求与写入1/128/1024/6144的固定检查点，FreshCurrent仅用于评价。
语义和费用canary先通过，再逐项开展约几分钟至十余分钟的四GPU队列；不启动训练或读取theta3/确认。

## 有限的追加备选：提交前核验

完整risk队列后，正常结构背景M4的AUC差出现负区间，两个队列中都保留了这一问题。
因此在输出前固定[guard配置](../../configs/design2/scale_guard_01.json)，再跑同2048UID一次；
不继续搜索分组或阈值。原risk/demand/hash30结果均保留。

guard不增加免费的教师：仅对已由risk提议重算的状态构造Current KV，再比较当前实际请求的旧C与新KV输出。
只有真实差异超过原tau才安装新KV，否则保持原状态。所有重算尝试、两次额外读取、旧C修正与准备都收费，
summary只在提交时构建。账本service_correction包含这次核验调用，不能漏掉或误称完全服务复用。
这项观察不使用标签，不保证后续窗口安全，也不预言AUC一定改善；它检验能否避免小误差状态的不必要轨迹替换。

## 完成状态

六个人口/压力队列与12个参考任务全部完成，结果集中在[本轮结论](../../results/design2/analysis/scale_followup_01/conclusion.md)。
费用曲线已有可行性，M1退化明显缩小、严重残余减少；正常M4在guard后仍退化，cap32 AUC也未通过。
因此保留risk/guard作为开发基线，不称最终合格策略。新增规则/分组搜索停止，下一步优先研究正常低干扰。
共享准备的分块费用是理论重计费，实际服务重建已执行，不混淆两者。
