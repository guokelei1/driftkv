# Design 2在论文中承担什么

**最新实际主版本**见[有界观察实验结论](../../results/design2/bounded_01/analysis/conclusion.md)：保留三个机制，
额度固定为构造FLOPs的1/4；出现安装条件时采用已计算的目标分数，随后在请求边界安装真实KV。
两条4082UID回放和直接入口canary已完成。原“当前响应保持不变”的提议经完整对照基本失去尾部保护，
因此只保留为时机消融。下文提出该建议及“未实现”的描述属于当时阶段，不是当前状态。

章节主线固定为**一个问题、三个机制**：有限目标计算怎样支持必要的持久更新，同时保留D1低成本续用。
三机制依次是①共享服务读取证据，选择目标观察；②复用同一次目标构造，供当前核验、后续观察与可能安装；
③限制观察寿命，在请求边界安装或释放。它们管理同一候选缓存的生命周期，不是按困难用户类别拼接算法。
系统位置是D1默认服务能力之上的状态管理；D1维护视图，D2必要时替换普通KV。公式、阈值和额度是
这三个机制的具体实现，不能取代机制本身成为章节主线。文字组织清楚不等于新版本实验已通过。

最新论文方法已改为**请求后安装＋有限观察额度**：当前请求使用已有服务状态的输出；
检测及目标核验只决定请求边界后的状态替换。未安装候选继续观察前，先检查剩余额度是否覆盖
完整的候选追加、读取及控制费用，不足则释放；释放后本目标的一次构造额度不恢复。
额度数值/规则需要在新实验前固定。线上不使用标签或后验正确性反馈。
这两项目前是论文中的新方案，代码和实验尚未完成；以下原型结果仍对应即时返回目标分数、
无FLOPs观察到期的版本，不能转写为新版收益。新版评价必须保留触发请求本身的误差。

对应未决问题：重点处理第2项观察寿命/费用和第4项评分路径干扰，为第1项任务质量提供一个
可检验的改进，但不保证后续AUC或保护率。第3项检测遗漏与第5项跨模型/负载推广保持原范围。

最新扩大验证见[4082用户场景实验](scan_30k.md)与[结论](../../results/design2/scan_30k_01/analysis/conclusion.md)。
当前统一框架为“复用真实读取证据→有限目标构造→复用目标观察及可能安装→独立状态连续服务”。
一次性观察与保留目标轨迹是同一计算/状态机制的两个寿命选择：前者便宜，后者覆盖晚发错误。
它们不按特殊用户身份切换算法。自然短历史、老谱系、混合来源、活动异常只定义Benchmark暴露。
新实验已将主失败样本从此前18UID扩至新队列59UID，增强了尾部保护证据；AUC与目标残余不是同一目标，
不能据此宣布整个Fallback合格。额外排序分差门控只作为固定开发检验，未替代冻结主结果。

当前论文实现与最终证据见[本轮结论](../../results/design2/sparse_01/analysis/conclusion.md)。
本文后半保留探索过程；其中首次使用检查和0.043095提交阈值都是早期对照，不是当前默认方法。

## 当前可以写成论文的方法

**选择性状态更新（Selective State Renewal）**：Design 1负责让状态继续可用，Design 2用有限目标计算结束已经观察到严重失准的状态寿命。管理对象始终是实际KV及其后续轨迹。

1. **共用读取，取得证据。** 从真实Design 1读取中取得源编码和native响应，用225个已观测坐标的岭回归二次型筛查；不额外生成16候选，不重新做模型读取。512独立残余校准UID给它固定12组的非负尺度。低分不等于安全；这个225维下界与旧225维精确重排不同。
2. **等待第一次风险触发，合并核验与动作计算。** 每个UID/目标在首次风险越过冻结90%校准阈值时，构造一次合法Current KV，以同一真实请求测量实际残余。超过事先已有的主严重尺度0.5才安装；否则保留旧状态。已构造的KV和已计算的输出直接复用，不再支付第二次重建/服务读取。低分请求继续等待，避免首个正常请求让后面的失败永远不被检查。
3. **一次观察额度约束状态寿命。** 每个UID/目标至多一次付费构造，无论是否安装都消耗额度。安装后走当前模型native轨迹；模型变化取消锚点并重新开放观察。未安装后的“已检查”只是资源状态，不代表后续安全。各策略持续维护自己的KV，不在下一发布接回共同Parent。

这三个机制依次解决额外检测计算、低价值干预、状态错误持续继承。它们消费同一条证据和同一次目标构造，不依赖“短用户/旧用户/异常用户”的分支补丁。后台结构分组仅用于固定Benchmark和尺度校准。

实际仍会对许多服务读取计算廉价证据，**不能称检测调用本身极少**。稀疏的是昂贵Current构造和安装；完整账本同时报告廉价检查数量及其FLOPs。一次额度是次数约束，当前方法不是任意负载下的硬20%预算保证。

本轮完成自然2048UID和短窗口32/128各512UID真实连续回放，规则冻结后将FreshCurrent扩展至所有实际请求。默认保留225维首次风险候选，完整1281维、仅背景、首次使用和首次使用Exact是对照；全请求结果不再用于调整阈值、分组或额度。

## 早期设计推导与保留消融

本轮重新以完整方法为交付单位。Design 1解决给定实际缓存怎样低成本读修正；Design 2决定何时结束这份近似状态的续用。目标是少量核验、少量真实更新，减少严重兼容性失准，同时使普通状态大体保持Design 1的服务路径。一次查询改分、人人检查后截断预算、整体AUC小幅上涨，都不能独立支撑这个贡献。

## 统一问题与机制链

状态是唯一管理对象：合法保留事件、真实KV、摘要、视图、目标版本、修订号及重建锚点。连续版本、罕见活动和短历史产生不同状态，不产生三套修复算法。

1. **证据取得**：复用Design 1的源编码、实际读取与拟合统计。先研究廉价观测能否筛出值得支付完整检查的状态。低分只表示未触发本次筛查，不能证明误差安全。
2. **有限核验与动作**：只为筛中的状态支付查询面板或更强证据；需要修复时，比较剩余检查与重建费用。预算必须覆盖证据取得和动作，不能先耗完检查费用再宣称有预算保护。
3. **状态更新**：按合法历史重建并替换真实KV、摘要与起点；同目标后续native服务，下一发布重新评估。收益必须出现在后续真实请求，不能只来自重建当场。

这三部分分别处理“核验贵”“干预不一定值得”“一次修正不能消除继承误差”，依次消费同一份状态证据。它们不是按不同用户类型拼接规则。仅当实验同时支持这条链，才能称为通过验证的方法。

## Benchmark与验收

沿用[benchmark.md](benchmark.md)的冻结定义与`benchmark_01.json`的工作目标，不按新结果移动边界。

| 论文主张 | 必须测什么 | 工作目标/证据限制 |
|---|---|---|
| 少量检测 | 实际付费完整检查状态数、UID数、所有检查FLOPs；未筛状态保留在分母 | 本轮筛查候选固定10%，评价实际偏移；筛查率不等于零成本 |
| 困难状态保护 | challenge的FreshCurrent严重UID率与超额残余，0.5主尺度及0.1/1.0全报 | 主率与质量加权超额各降30%；少于30个主失败UID只能探索性报告 |
| 正常低干扰 | routine真实AUC、logloss、新增严重错误、重建率与费用 | AUC容忍0.001、logloss相对0.5%；重建≤10%，额外服务费≤自身Exact的2% |
| 连续状态收益 | 同M0起点的M0–M5独立KV回放；首次重建后、追加后、下一发布分开报告 | 不接回Reuse缓存；不以替代场景拼接生命周期；M2仍是状态失效边界 |
| 短历史适用性 | 自然短用户；完整回放cap32/128压力负载 | 两类分开；压力负载不冒充自然用户，保留Frozen C窗口mask的适用性限制 |
| 总体低计算 | 全准备、教师、维护、筛查、重建的理论FLOPs | 3万≤40%、10万≤20%、百万≤15%的工作区间；实测人口与外推人口分列 |
| 检测有选择价值 | 同完整费用的无需检测重建对照 | 更昂贵的检测方案优于更便宜对照，不足以证明分配价值 |

人口成本应写成`K + U*a + U*p*c + U*r*e`（各项按真实调用计量），而不是要求总成本对人口严格次线性。固定工作负载下人口侧通常线性；共享准备摊销使单位成本下降，但极限由服务项决定。不能用“将来规模大”隐藏过高的人口侧成本。

## 本轮计算候选：嵌套观测证据

原二次型为`fᵀH⁻¹f`。对于已观测坐标I，最小可能值为`f_Iᵀ(H_II)⁻¹f_I`。实际联合特征包含33维源编码与33维增广query的乘积，以及192维native响应。query截距为1，因此无需新query就知道33个源坐标；已有真实读取再给出192个响应坐标。得到33维状态证据、225维读取证据、1281维完整证据的嵌套关系。

这是**几何量的下界**，不是实际误差的上界。它与此前225维精确收缩不是同一个算法。缺失query方向可能恰是失败来源，必须在512 UID交叉校准后冻结规则，再看1024开发用户。廉价分数的残余尺度仍需独立校准和同组背景对照；不能沿用完整分数的校准系数当成等价判定。

两个候选在固定10%筛查份额下完整报告，不搜索分组、分位数或AUC赢家。若低成本证据不足以集中失败，停止候选，并在论文中明确当前稀疏保护尚未验证，而不是把数学正确包装成系统成功。

## 实现后的必要收缩：让目标计算同时提供证据与动作

512自然用户的首轮消融中，源筛查选中65/860个活跃状态，完整几何核验58次、另7次公式短路，全部要求重建。去掉完整核验后，65个动作及所有反馈logit完全一致，服务费用从0.2453TF降至0.2298TF。因此完整几何不是必须保留的一层。

随后的`observe`候选保持源筛查、分组和阈值不变，只将选中状态的重建作为一次付费观测：构造合法Current KV，比较同一真实请求的适配输出与Current输出，超过既有固定容忍值0.0430952204才安装，否则保留旧状态。新KV直接成为重建起点；实际选择的旧/新logit直接用于服务，不重读一次。这把“核验费用”和“修复费用”合并为同一次目标构造，全部未提交构造仍收费。

源证据只决定哪里值得观测，不再承担“允许续用即安全”的核心承诺；提交依据是被选择请求上实际可测的输出差。也不声称这个差保证后续请求或标签质量。候选次数、安装次数、后续写入效果、下一发布效果分别核对；M1或同组低源分数失败仍必须留在失败清单。

该实现对应的费用为`K1+K2+U*(a+c_screen+p*(c_build+c_extra_read)+r*c_install)`。`p`是付费构造率，`r≤p`是安装率；不能再次为已构造KV收一次完整重建费，也不能把未安装构造退费。普通D1准备/维护、旧残余教师准备以及本次源矩阵准备全部保留计费。
