# Design 2 初版审查：现有接口、可行性与待修订项

2026-09-08。第1–9节是首轮静态审查；第10–11节记录用户后续授权的中规模检测及结果。
最新：[完整实验报告](../../results/design2/analysis/detection_01/report.md)。
建议来源见[专家存档](expert_route_2026-09-08.md)，本阶段范围见 [README](README.md)。

## 结论

**现有框架可以支撑这个研究，但不能说 Design 2 所需接口已全部具备。**
冻结 Design 1 的联合岭回归、实际读取回调、摘要维护、原生回放与 Current 前缀重算
提供了必要计算原语。缺少的是二阶统计导出、检测输入接线、独立残余校准划分、
真实重建后的状态替换及分支回放。预算管理尚未实现，检测的有效性也完全待验证。

首轮优先研究“校准约束是否能识别修正失败”合理；先实现完整调度器会跳过核心未知。
这里的可实现性指可以搭建忠实的诊断和同步原型，不等于已证明质量、成本或任意发布泛化。

## 1. 核对的 Design 1 究竟是哪一版

## 3. 将专家公式落实到实际拟合坐标

以下是根据 fit_joint 的代数核对，不是新理论或运行结果。固定目标 e、层 l、头 h，
源 latent 含截距共33维，头 query 归一化后含截距共33维，native 是本层全部192维响应率：

\[
x_s=[1;\mathrm{PCA}_{32}(\mathrm{source}_s)],\quad
\bar q_{sjh}=[1;(q_{sjh}-c^q_h)/s^q_h],\quad
o_{sj}=(a^S_{sj}/N_s-c^a)/s^a,
\]
\[
f_{sjh}=[\operatorname{vec}(x_s\bar q_{sjh}^{\top});o_{sj}],
\qquad p=33\cdot33+192=1281.
\]

source 已使用原冻结 center/scale/projection；native 响应必须取 C 实际下层修正产生
的当前 q 对普通 KV 的读取。它既不是原始 Reuse 全前向的 q，也不是只取本头32维 native。
特征 flatten 顺序必须对应 W 的 source-major/query-minor 和随后 U 的拼接。

设 S 为该目标拟合场景数，Q=16，w_s=N_s²/mu_A，lambda=.01。
使用平均目标的二次项（不是多一个2的 Hessian）：

\[
G_{lh}=\frac1{SQ}\sum_{s,j}w_s f_{sjh}f_{sjh}^{\top},
\qquad H_{lh}=G_{lh}+\lambda I.
\]

代码保存于局部变量 system 的矩阵实际是 S H，正则项为 .01 S I。
因此若用 system 求解，平均目标坐标下

\[
u_{\mathrm{rate},lh}^2=f^\top H_{lh}^{-1}f
=S f^\top\mathrm{system}_{lh}^{-1}f.
\]

不能混用两种约定后跨拟合场景数比较阈值。含截距的 W/U 都参与正则；
原拟合按场景平均，UID等权只是报告口径，重建 H 时不能悄悄改成 UID 等权拟合。
训练目标不使用服务消退 mask 剔除样本，没有额外输出通道标准化。

服务返回聚合响应且应用本层 active mask m_l，固定本层实际输入时应记录

\[
u_{\mathrm{aggregate},lh}=N_s\,m_l\,u_{\mathrm{rate},lh}.
\]

这只是局部修正系数变化的尺度，不是 logit 误差、不是真实失败概率，也不是跨层误差上界。
同头32个输出共享 H；怎样合成多头、多层或整个请求组的检测分数仍需明确，
只能在校准侧定规则，不能看开发残余后选最有利聚合。
inactive 代表该局部修正被结构规则关闭；不能据某一层为零称整个状态 Exact。

几何解释也应更精确：对单输出岭目标，最优点附近的目标增加为
delta_theta^T H delta_theta。若容许增加 epsilon，最大预测变化是 sqrt(epsilon) u。
u 本身没有给出 epsilon 或真实残余分布；正则同样贡献 H，强正则造成的“小 u”
不全来自数据识别。它也不是一般岭估计的频率学预测标准差。

原 raw 只保存场景索引、Exact/预测及一些误差统计，并未保留完整 f/H。
可在冻结 C 的原拟合状态、fit16 查询和坐标下重新读取 actual q/native 来累积 H，
无需为了 H 再取教师响应或重拟合 C；但普通状态重放、读取和分解均须计费。
诊断 held64 不能替代 fit16 来重建“原拟合 H”。已知输出可用于核对重放一致性，
不能宣称直接从现有结果表恢复了全部矩阵。

## 4. 初版说法需要怎样改

| 原建议或容易产生的理解 | 应采用的修订 |
| --- | --- |
| Design 1 已经提供二阶检测接口 | 校准过程中已有二次矩阵，尚未保留；低层读取可暴露输入，服务层尚未接线 |
| 小 u 表示被数据充分约束 | 小 u 表示在指定正则目标和坐标中的预测稳定；数据约束与正则收缩不能混同 |
| 利用独立校准残余即可获得可靠范围 | 可研究经验范围；原128诊断UID已反复使用，不能重新命名为全新独立确认 |
| 版本、修订不匹配必须重建 | 先判定是哪种失效；过时视图可能只需刷新，缺少质量依据或不支持的状态才进入后续处置；硬失效不能被低 u 放行 |
| 当前模型写出的 token 都是 Exact | 上层 KV 仍可能继承旧前缀误差；producer 相同不表示依赖已经消退 |
| 缓存没 dirty 就沿用安全结论 | 只允许复用源视图，新 query/native 仍可能落入不同方向 |
| “Current Exact”是唯一且已经统一的参考 | 必须区分当场重建参考与发布时重建后持续回放的 Exact 分支，见下一节 |
| 有不确定性导数就有输出界 | 导数是局部敏感性，H 也是条件于本层输入的几何；跨层耦合和遗漏信息不由两者自动覆盖 |
| 重建可以沿用基础实验共享 KV | 从首次选择性重建开始，方法与 Reuse 普通状态分离；以后各自追加、淘汰、跨发布 |
| 短历史一定应重建 | 需要同一可见工作负载范围的边际成本比较；既有 96/N 只是 U 与两次历史矩阵乘法的比，不是重建阈值 |
| 同预算覆盖严重残余等于系统收益 | 这是检测/选择的离线读数；一次状态重建作用于多个查询和后续生命周期，实际质量要独立回放验证 |

## 5. 重建的含义与连续状态边界

**首先明确 Exact 参考。** 专家定义更贴近“在当前决策时刻，对合法保留前缀用 Current
完整重算，再评分同一 query”的当场重建参考。旧基础质量表的 Exact 是在发布点
重建后持续 native 追加、淘汰的独立分支；窗口移位后，上层 KV 可保留此前上下文影响，
不应假设它与每请求重新计算窗口相同。C 的场景教师属于该场景的 Current 前缀参考。
后续检测实验需写明采用哪个参考；不能把两种 Exact 的残余拼成一列或静默替换旧表。
当场重建残余可衡量本次动作的输出变化，不能直接代表未来 AUC 收益。

**真实重建至少包含：** 取时刻 t 前合法前缀（排除完整同 timestamp 目标请求/写入），
Current 重算保留窗口 KV，按相同 timestamps 重建 writer 摘要，记录新的精确起点，
使已有 source/view/prepared 与质量判断失效，并从新 KV 继续真实追加和淘汰。
立即评分应可走无近似修正的 Current 缓存；不能沿用“发布年龄=0，所以开启所有修正层”
而给刚重建的精确缓存再加 C。需要区分发布年龄、重建起点和已验证的依赖消退状态，
保持 Design 1 原输入年龄定义，不通过重写冻结特征偷换算法。

同模型下从精确起点普通写入可维持对应的重建后谱系；下一模型发布重新产生兼容性问题。
单纯清空旧 producer、重装 view 或替换一次 logit 都不是此重建动作。
当前同步原型只需清楚的状态替换与计数，不需要并发 revision 框架或持久化服务系统。

基础 evaluator 能共用普通 KV，是因为三个适配方法只改读、全部 native 写入。
Design 2 重建后此等价不再成立；必须保留方法自己的状态，不能下一事件又接回 Reuse，
也不能下一发布重置精确 Parent 后声称连续改善。Exact 控制、Reuse 和方法采用同一因果
事件序列，各自从自己的 KV 写入。摘要从真实 KV 维护，不翻译上轮的预测摘要替代实物。

预算不足时如何响应“缺乏依据”尚待设计，不能默认为安全或承诺立刻重建。
质量观察单位可以是 query，动作单位却是 UID 的当前状态。相同预算评价应去重计一次
状态重建，不按该用户多条 query 重复收费或重复算成多个独立成功。
实际候选/请求组如何合并检测、何时重建和重打分，留在后续小诊断设定中明确。

## 6. 数据划分与关键反证

后续区分三种角色：Design 1 参数拟合（连同冻结坐标准备所用 UID）、Design 2 残余
校准、Design 2 开发评价。后两者都不得混入拟合 UID，彼此按 UID 分开；
同 UID 的 query、快照、多个发布不能跨组充当独立用户。

原128诊断 UID 和成熟4091开发人群都已使用，不能声称其输出从未看过。
第一步可以在已开放数据中固定 UID 划分做探索，但应标记这种历史暴露，
先固定阈值/分数聚合与严重误差定义，再看开发结果，确认集继续封存。
这轮未选择新的 UID、容忍度、阈值或预算，也没有创建新的实验合同。

已知失败用于反证检查，不用于挑样本或定向重建：

- C 的 M5 诊断：UID 547600（N=1024）连续/早期旧谱系失败，同 UID 的 Parent 初始化辅助状态较好；
  UID 254830（N=19）纯旧 producer 也失败。不能把问题只归因于混合或短历史。
- 拟合 UID 988060：C 在 M4/M5 的 fit16 本身有局部严重过修正，M5 held MSE 约7.1505。
  这些拟合内反例应单列检查低 u 假阴性，不能并入“独立校准成功率”。
- 当前 C 的 M5 诊断平均误差接近 Reuse，少数状态主导尾部；所有状态和不利结果应保留，
  不能用成熟域主结果覆盖这些边界。

上述均来自[原残余报告](../../results/design/analysis/native_coverage384_report_01/report.md)，
不是本轮新测量。多 query 不增加 backbone 重复数；当前只有 seed17 开发证据。
如做删 UID 重拟合，各分支必须重新产生其上层 actual q；固定 q 的解析删组只是局部诊断。

## 7. 计算可行性：有入口，但绝不免费

p=1281，六层六头每目标36个矩阵。若保留全部稠密 FP64 H，
共有36×1281²=59,074,596个数，约450.7 MiB/目标（不含分解临时量）；
同维 FP32 约225.4 MiB。每查询全36块稠密二次型约5907万 MAC，
约1.18亿矩阵乘加 FLOPs，尚未包括构造 f、其他算子和梯度。
这些是尺寸算术，不是实测运行时间或端到端成本。

首个研究实现可使用 FP64 分解与 solve 算准确二次型，不需要显式求逆或先设计压缩框架。
实际跑前用小样本估计耗时、显存和矩阵分解成本；本轮没有 launch，因而不捏造秒级估计。
低秩近似若丢弃 H 的小特征值方向，恰好可能丢掉 H^{-1} 的大贡献；
只在原指标有用后才研究余项保守处理或标明经验近似。

专家 F_prepare+F_check+F_rebuild 应明确为 **Design 2 的新增费用**。
总方法增量还包括保留的 Design 1 准备、摘要初始化、刷新、读取与维护，
以及重建后实际避免的这些调用；共享准备不能重复计，研究教师费用也不能隐去。
同一生命周期匹配 Reuse 增量为0与 Exact 的依赖闭包重建分母，并分别记录
理论 FLOPs、实测时间和辅助存储。

短历史比较应针对当前可见请求或预先规定的服务范围，未来读写数量若估计，
只能基于过去/当前合法信息。不能查看完整未来 trace 为在线用户计算完美盈亏点。
离线已实现费用可事后报告，但必须与在线决策可用量分开。
输出敏感度、发布检查 query、重建后的摘要初始化和可能的重打分都要收费。

- [Patil等，AISTATS 2022](https://proceedings.mlr.press/v151/patil22a.html)
  用 GCV/LOOCV 扩展估计高维岭回归样本外误差分布，结果有分布条件和渐近设定。
  不能直接移植到相关 UID 轨迹、顺序拟合的非线性闭环或跨发布分布变化。
- [GP 有界噪声误差界](https://arxiv.org/html/2408.09033v1)
  研究对象是高斯过程回归及有界支持噪声，不是当前 W/U 联合岭回归。
  只能作“误差界需要额外假设”的背景，不能当本检测公式的直接理论证明。
