## 候选方向清单

### D1（主推）：流式派生个性化 KV 的一致性管理 for LLM4Rec serving
- 新问题？✓（见 `03` 四判据全中）
- 真实 workload？✓（Netflix/Kuaishou/LWGR 工业证据）
- 与 TokaDB 关联？✓（直接延伸）
- 4×A40 可验证？✓
- 风险：RcLLM 已占静态空间维；需明确时间维是剩余空白（已在 `02.D.2` 论证）。

### D2（备选/可作为工作4）：多候选 fan-out 的请求级 serving 调度
- 新问题？部分--新 workload（1×N fan-out），但偏系统优化，易被判为"工程优化"。
- 现有覆盖：RcLLM affinity 调度、Douyin RLB（模型侧）、vLLM prefix sharing（通用）。
- 结论：单独成文偏弱，作为 D1 的子工作4 更合适。

### D3（备选）：行为序列存储与派生 KV 的协同存储抽象
- 新问题？中--新抽象（联合管理），但若只做分级/分片易陷"新实现"。
- 现有覆盖：RcLLM 分层存储、Tutti（SSD KV）、FlexGen（offload）。
- 结论：作为 D1 的子工作3；需绑定一致性/新鲜度才有新意。

### D4（否决）：LLM agent 长程记忆/状态的数据管理
- 新问题？中--agent 状态管理是真问题（Pythia [arXiv 2604.25899] 已切入）。
- 与 TokaDB 关联？弱--远离推荐/行为序列积累。
- 结论：方向好但与已有积累关联弱，不符合"关联性"约束。降级。

### D5（否决）：面向 LLM4Rec 的向量库 / ANN 检索优化
- 新问题？弱--向量库/ANN 极度拥挤（Faiss/Milvus 等），且 RAG-for-rec 已被 ReLLa 等覆盖。
- 结论：难找新问题，否决。

### D6（否决）：LLM4Rec 的指令数据/SFT 训练数据管理
- 新问题？弱--偏 ML 数据工程，系统新意不足。
- 结论：否决。

### D7（备选/风险对照）：生成式推荐的语义 ID 索引/解码数据结构
- 新问题？中--语义 ID（SID）的索引/trie 解码是数据结构问题（GR4AD personalized trie、UniVA trie）。
- 与 TokaDB 关联？中--索引/存储相关。
- 风险：偏算法/模型侧，且工业论文密集，系统侧新意需仔细论证。
- 结论：作为 D1 之外的次级备选；若 D1 立论受挫可转向 SID 索引/存储的系统化。

## 对 D1 的批判性自评（principle #1/#6 的自我反问）

### Q1：D1 是否只是"prefix cache + 流式失效"的工程组合？
- 反驳：单纯失效是工程；本工作的核心是**新一致性模型**（KV 一致性级别谱系 + 有损性/粒度处理）与**新评价维度**（新鲜度-延迟-精度 trilemma），这是新问题定义而非组合。需在论文中**先证明 trilemma 无法靠现有 prefix cache 参数调优解决**（实验：扫 vLLM/SGLang 的刷新周期，展示不存在同时满足三界的点）。

### Q2：causal LLM 下纯尾部追加的 KV 本就有效，问题是否被夸大？
- 部分成立。需在 `03` 中明确：纯追加下旧 KV 数学有效，但现有系统不识别（按 miss 全量重算）--这本身就是"系统未利用数学性质"的证明，是工作1 的第一个贡献点。但更普遍的推荐场景是**语义检索重排/分块重摘要**（ReLLa/LIBER），此时 prefix 内容整体变化，旧 KV 真正失效--这才是核心难区，问题不夸大。

### Q3：RcLLM 是否已隐含覆盖时间维？
- 否。RcLLM 的 block 是静态内容；其分层存储是空间维。时间维（行为流驱动的内容演化 + 新鲜度）在 RcLLM 中不存在，且其评测无新鲜度轴。这是可论证的精确空白。

### Q4：4×A40 是否足以让结论可信？
- 足够。方法验证不依赖规模；192GB 可服务 8B–14B。规模外推可用分析方法补充。CCF-A 系统论文常见 4–8 卡实验。

### Q5：是否过度依赖未核验的工业说法？
- 已规避：所有立论引用均经 arXiv 核验（见 `07`）。staleness 论点的关键引证（Netflix [2605.23312]、LWGR [2605.18771]、LIBER [2411.14713]、HyMiRec [2510.13738]）均已核验摘要原文。
