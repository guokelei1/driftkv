## 因果数据与模型准入

- 人口、角色和词表按初始可见历史固定，不能用未来标签筛人或拟合初始映射。
- 请求前缀严格早于目标时刻；候选查询是暂态输入，不进入持久历史。
- 各规模使用自己的 item mapping、OOV 和反馈审计规则。未知目标与有效分母必须显式报告。
- 先完成同窗口 Parent/Current Full-only 准入，再解锁该边的 Reuse 评价。
  未准入候选不改变服务父模型或缓存谱系；开发例外不改写原 admission。
- checkpoint endpoint 不等于 release。当前 18 个端点以[固定清单](unified_training_2026_09/model_versions.md)为准；历史候选的失败记录不改写成当前端点的结论。

## 拟合、开发与确认

共享校正模型的拟合用户、开发选择和最终评价分开。归一化、投影、源层选择、
容量、loss、停止规则及教师数量随开发配置记录，在正式确认前固定。
已观察过的开发日期或 UID 不得重新称为全未见；不得用 qualification/scale 结果调参。

历史 Insight 1 使用固定3000用户、五边及每边64候选；旧 Insight 划分的
discovery [0,512)、confirmation [512,3000)与偶/奇32候选有其原协议。
该3000人群已参与历史研究；尚未开放的确认用途继续受原协议约束。
新方法拟合须避开受保护人群，不能直接把这些旧划分当作新实验的独立确认。
具体角色与接触范围见各次冻结配置，不在导航文档中重分配 UID。

当前共享校准允许摘要/KV派生监督和重建目标；报告教师来源与全部费用。
评价用户上的逐用户教师拟合作为明确标识的诊断，不能同时称为该用户上的未见泛化。
所有预声明版本、种子、预算、失败和负结果都保留；训练种子是重复单位。

## 参考路径与评价

同一版本边、历史和请求至少区分：

1. Parent Full：父模型读取其原生历史状态。
2. Current Full Recompute：每用户每次发布重建一次保留历史，此后正常原生追加/淘汰和查询。
   主执行方式为首次请求触发；发布时全人口预先重建的Exact单独报告。Fresh每请求重算仅作历史诊断。
3. Current Reuse：当前模型读取父版本或实际混合 producer 的持久状态。
4. Method：在相同初始状态上执行可部署迁移与维护，再由当前模型评分。

当前完整方法的Full参照为上述首次请求触发的一次重建，缺口恢复率为
`(M_method - M_reuse) / (M_rebuild_once - M_reuse)`。
单版AUC在该版请求上计算，全链质量主汇总为等权各发布AUC差异的比：
`mean_v(AUC_method_v - AUC_reuse_v) / mean_v(AUC_rebuild_once_v - AUC_reuse_v)`。
全部预定边进入汇总，不能剔除不利边；总平均一次重建缺口非正时整体恢复率不定义。
逐边绝对AUC、logloss与恢复率同时报告；跨版本pooled AUC仅作补充。
保留原始绝对质量、增量与分母；近零、反号或无显著gap按该实验预先固定的规则单列，
不能为得到好看的比例临时换分母。显示截断不改变原始结果。

Yambda 的 AUC、log-loss 等任务质量与概率/响应保真度是不同指标。
例如逐用户误差比的均值 U 不等于平均误差之比 P；不得用较有利者替代冻结主指标。
概率功能探针的64候选不等于真实反馈 AUC 请求集。
RecFlow 的候选排序、beam自由生成和exact全目录排序分别定义，不能互相冒充。

当前三规模 [15 条 Full/Reuse 边](../results/unified_reuse_2026_09/README.md)、
[四种局部重算](../results/selective_recompute_2026_09/README.md)和
[非线性 Q/H](design/read_correction_probe_2026_09.md)分别保留自己的用户面板、
完整结果与实际成本口径。旧图的增量成本以 Reuse 为 0%、逐请求Full重算为 100%，
计入各次配置实际采用的校准、拟合及应用成本。这些历史轴不能直接改名为一次重建；
如作为当前系统成本图展示，须用匹配的一次重建对照重新核算，原数据保留。

论文附录仍引用的[历史统一AUC诊断](../results/insight/unified_auc_10k_teachers7144_20260920/README.md)
采用发布时的1024-event固定快照和真实E14反馈，不是逐请求滚动缓存；
其正gap >1e-4规则属于该次诊断，不自动成为以后实验的阈值。

## 持续状态与对照

真正的连续评价从上一次迁移输出继续，覆盖多 producer、真实追加、部分/全部淘汰、
长驻旧状态和再次发布。每条边重新从原生 Parent 初始化，只能建立单边结论。
Current producer 标签只说明生成参数，不保证该行等于 Exact；
旧 producer 全部退出也不消除后代继承误差。

所有路径采用相同事件顺序、保留、时间/位置和淘汰语义。
发布时重建参考与“Current从最初一直在线运行”的轨迹分别命名。
若研究等待期，就绪前Reuse请求及其后代写入也计入总体质量与覆盖；
同步视图就绪后的小实验不证明异步服务行为。

对照按研究问题选择：Reuse/No-op/Exact、真实摘要或响应教师、同容量摘要、
无源状态消融，以及[可执行迁移方案](../src/hstu_kvcache/baselines/README.md)。
Exact-KV splice 是干预，不进入可执行成本前沿。旧oracle结果不继承为方法效果。

## 成本与最小验证

发布增量以同场景每用户每发布一次重建为分母，收取校准源/教师、拟合和选层、
坐标准备、既有缓存摘要初始化、转换及人口写回；不能把教师访问或首次扫描记为零。
在线摘要维护、读取修正、刷新、追加/淘汰、存储与I/O另计。
生命周期比例必须先固定服务时段，累计绝对工作量后再求比，不能直接相加比例。
理论MAC/FLOPs、GPU时间、端到端时间及峰值内存分别报告。

2026-10-04用户更新的是完整Design1/2/3共同目标：至少80% Full−Reuse AUC缺口恢复，
完整新增FLOPs目标10%–20%、上限20%；低于10%不需要增加开销。此前D1的15%目标保持为历史记录。
2026-10-05用户进一步明确以论文框架的合理性和稳定高恢复为主线：80%保留历史参考，
某个开发子集/端点跨线不构成成功。模块需有明确问题、机制及可检验作用，迁移、群体覆盖与
真实服务证据检验整体；成本和紧凑状态约束保持，不以扩大有利开发人群代替独立确认。
同日进一步澄清：机制验证可以聚焦一个已固定模型案例，不要求所有发布均有收益。
已有版本链保留为实验条件；固定模型案例说明机制，更广配置测适用范围，二者不互相替代。
分母是**预先固定服务场景**的一次重建策略−Reuse计算缺口，详见[计划](design/plan.md)。
常驻人口、模型、发布时点、服务区间、读写轨迹与历史上限先固定；校准、准备、维护、读取和
实际重建增量按发布和用户累加，再除以同场景的Full−Reuse工作量之和。质量评价抽样不改变
服务人口或共享准备费的摊销。实测、真实事件形状解析计数、采样估计和人口外推分别标识。
主路径首次请求触发重建，Exact-All另报含空闲用户的工作量；不能为了较低比例替换执行方式。
每次query的额外FLOPs、时间及内存访问另与原生query/attention比较，须足够小，不能靠重建分母掩盖。
校准人数、质量样本和服务人口独立：可固定约1000–2000校准用户，研究更大人口的准备摊销；
人口扩大后的质量须验证，条件性资源外推不等于新人口实测。原草稿90% stretch是历史目标。
新确认实验应事前固定可解释的质量和成本标准；低成本但弱恢复、高成本或持续性失败均如实保留。

## 论文实验空间与阶段

完整论文需要覆盖质量/成本、持续状态、迁移边界和实际服务表现。最终空间不能由当前一次
开发运行的用户数决定，也不要求把所有轴做全排列。先明确主张，再选能区分解释的代表性实验：

- 质量：冻结方法和人群选择规则，按用户完整轨迹评价；用开发数据的不确定性与分组覆盖决定
  确认样本量。原10k、4096和已经读取结果的512均不能重新称为未见终评。
- 规模：现有30k/79681/200k真实人口是资源基点；区分常驻人口、活跃用户、请求/写入率。
  固定工作负载组成的人口复制仅能给资源估计，不能给新群体质量或实测吞吐。
- 发布：主回放跨连续版本，保留空闲用户和真实写入。已有15条相邻边只提供对照资产，
  不能替代新方法连续运行。发布日期变化不能让模型看到发布之后的训练/校准信息。
- 模型与数据：现有三个Yambda配置的数据量、词表、人口并不相同，不能声称单一深度因果扫描。
  RecFlow需先适配当前真实候选排序任务。更多seed、长context和新训练按必要证据另行推进。
- 服务：最小到达驱动基准需覆盖读取/写入、排队、发布准备与切换；比较吞吐、p50/p95/p99、
  CPU/GPU内存和传输，以及Exact/首次请求重建的停顿。当前同步回放时间不代表这些指标。
- 机制：D1提供紧凑读取视图，D2用发布前Current教师先做局部读取对齐、再做完整query联合拟合，
  D3维护连续状态有效性与切换；历史反馈强度协调保持为已完成探索，服务不使用未知反馈。
  每个对照直接对应所属问题；V5完整与逐层联合参数替换检查D2的完整query作用，
  全部替换保留，不选择部署策略，也不把已使用validation称作独立质量确认。
  针对各自职责验证，不要求三者都有可比或很大的独立AUC贡献。

本阶段先核算Medium原30k人口的D259–301真实成本，并准备原10k连续开发回归。
它们是整篇论文验证路径上的检查点，不是最终人口或完整OSDI证据已确定/已完成。

先以能回答当前问题的小样本检查实际使用的组件：原算子/参考的一致性、count与坐标、
实际查询下的闭环修正、追加/淘汰和必要资源。HSTU checkpoint 的激活、偏置和归一化
必须一致；不能将旧ELU+1聚合或忽略偏置的oracle直接套到SiLU/RecFlow。
softmax需要组合numerator/normalizer，不能照搬无归一化segment求和。
高成本弱收益应继续研究，不能以流水线能运行作为成功结论。
