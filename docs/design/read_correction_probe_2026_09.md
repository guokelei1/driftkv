本方案是两个读取修正探针，不承担完整 Design 的实现或连续多发布验证。

本轮用户澄清：历史增强分支的目的，是允许较高计算成本，在 correction 中显式加入
用户信息，观察质量恢复潜力。撤回初稿中的固定 64 维表示与增量维护探索。
当前阶段不搜索紧凑表示或廉价维护方式；内部尺寸仅是实现参数。

## 研究问题与预期

1. 不显式编码历史的共享 query 修正，能否在很小的额外计算下恢复 AUC，
   并优于已有重算方法在相近成本下的实际结果？增加校准用户后，收益是否趋于饱和？
2. 训练和使用 correction 时，额外向它提供该用户的历史信息，能否在相同校准用户数下
   获得更高恢复？允许在每个 query 上为此额外处理完整历史，记录实际成本。

原生推荐路径本来就使用用户历史；上层 q 也已包含下层历史读出的信息。
两臂的区别是 correction 的显式输入，不是原模型是否使用用户历史。
用户信息的来源是当前被评分用户的合法历史，不是其他用户的未来反馈。

这些都是待检验假设，不把“必须胜出”“必须饱和”“历史方法必须昂贵”作为筛选或停止标准。
已有重算结果总体随预算改善，但不能概括为全部线性：例如 Medium V3→V4 的单层重算
在 22.2188% 成本下已恢复 95.2622%，之后趋于饱和。论文的绝对化表述需随最终证据收敛。

## 两个主实验

模型、embedding、score head 全部冻结，每个 scale/edge 单独拟合共享修正规则。
修正加在每层的历史 attention 聚合结果上，进入该层后续原生计算；不直接改最终 logit。

| 方法 | 预测规则 | 新增信息 |
| --- | --- | --- |
| Q：query-only correction | `delta_l = b_l + A_l q_l` | correction 显式接收当前分支的原生 attention query |
| H：correction 额外使用用户历史 | `z_l(q,H_u) = mean_i phi_l(q_l, K_ui, V_ui)`；`delta_l = b_l + A_l q_l + B_l z_l` | correction 额外访问该用户当前的完整历史缓存，按当前 query 计算用户信息 |

两臂保持相同的 query 仿射项结构，优先复用现有按 attention head 拟合的实现。
H 的具体建议是 `phi(q,K,V) = SiLU(Wq*q + Wk*K + Wv*V + c)`。
它在非线性之前同时接收当前 query 与该用户逐位置 K/V，按请求产生用户特征；
然后通过额外的 `B*z` 输入 correction 的线性输出层。
参数跨用户和历史位置共享，每层独立；训练与推理均实际提供这条用户信息支路。
不以逐用户拟合参数或评价用户教师替代可执行的推理输入。

该定义用于本轮高成本潜力探针，和正文当前“不含 q 的逐位置编码后均值”有具体差别，
需要在实验记录中区分；本次不修改论文。也不引入后续 Design 的摘要、参数视图或状态维护。
内部尺寸在开发时固定，不做维数曲线或以达到低成本为选择目标。
已有 native read 直接作为输入是另一种可选探针；若今后采用，只计新增变换，
不能把原本已经计算的 native read 再收费。本方案 H 明确执行额外的 query–history 处理。
为数值稳定，可以沿用旧实现拟合 `delta/N`、应用时乘 N 的规范；
两臂一致处理真实有效历史长度，所有标准化参数仅从校准组获得。

### 拟合目标

- 逐层拟合。当前层 q 来自本方法已修正的低层路径。
- 在**同一个 q**上分别读取校准用户的 Current 重算缓存与继承缓存，
  以两次历史响应之差为监督；不能拿 Full 路径自己的另一组 q 混作目标。
- Q 使用岭回归，初始沿用 `ridge=0.01`；H 使用同一响应误差目标，训练用户信息支路及线性输出层。
  H 的学习率、训练轮数及正则强度先在独立开发用户上确定一次，再固定用于全部正式点。
  对照开发残差，避免将 H 未收敛误判为历史信息无效。
- H 同时增加了显式信息和表达能力。开发阶段可用同结构关闭历史输入的最小对照区分二者，
  不把全部提升自动归因于用户信息；此对照不扩展为结构或容量搜索。
- 校准教师沿用已有 Current Full 的输入整理口径；既有 Full 与服务缓存对同时事件的排序
  差异需显式处理和记录，不能默认为两条路径完全相同，也不修改已保留的 Full 分数。

## 用户、时间与预算

- 正式评价保持现有 15 条边（3 规模 × 5 相邻发布），每边原来的 3,000 用户、所有请求、
  日期窗口、1024 容量及 Full/Reuse 分数；不重新选用户，不重跑四个基线。
- 原面板按 Full–Reuse 差异选出，是诊断人群。新方法仍只在这个人群上作配对比较，
  不将其平均收益写成全人口无偏估计。
- 新校准名单按固定 UID hash 和发布前合法历史选择，排除本规模五个评价面板的 UID 并集，
  以及独立开发/数值 canary 用户。不得按新方法结果或未来标签挑选。
- 建议嵌套校准用户数 `C = 32, 64, 128, 256, 512, 1024`。
  两臂同一 C 使用相同用户和候选；预算较小的名单是较大名单的前缀。
- 每用户固定 16 个从已知目录抽取的标签无关 query，固定 seed17；不按推荐标签挑教师候选。
- 第一版仅用发布前历史、发布时查询时间做校准，拟合后规则固定。
  评价继续使用完整滚动窗口，不能用评价期轨迹补教师后再回评此前请求。
- 开发首选事先指定的 Medium V0→V1、独立 128 用户。若发现发布时校准不能迁移到混合缓存，
  可另记一次仅用发布前事件构造混合生产者状态的开发试验；原失败结果保留。

## 服务状态与 correction 的额外用户信息

与四基线一致：Parent 在发布时产生历史缓存，随后 Current 原生追加/淘汰；同时间先查询再追加。
Q/H 只修改当前请求的读结果，持久 K/V 和后续 append 不受修正影响。

H 在每次查询 correction 时额外访问该用户的保留 K/V，计算依赖当前 q 的用户特征。
同一用户的不同候选 q 可获得不同特征和修正；不能用已有的无 q 均值摘要替代这一步。
该支路的工作量随请求数和历史长度增长，是显式引入用户信息的实际计算代价。
原生历史读取在两臂保持相同规则，只有 correction 新增的支路计作增量。

实现可以正常批处理、分块及复用与 q 无关的中间投影，避免无谓串行和内存拷贝。
这些算子层优化不改变全历史、逐 query 交互的实验定义。
本阶段不开发持久摘要、增量均值、压缩视图或低成本替代方案，也不做相应成本曲线。

## 统一质量和计算量

`Recovery = (AUC_method - AUC_Reuse) / (AUC_Full - AUC_Reuse)`。

`Relative cost = method_extra_FLOPs_over_Reuse / (Full_FLOPs - Reuse_FLOPs)`。

直接复用当前四基线的实际请求及 Full−Reuse 分母，包含其 Current append 扣除方式。
不切回旧静态实验“每用户只重建一次”的分母，也不摊销到未实际评价的额外人口。
每种方法、每个 C 作为独立部署完整计费：

1. 校准用户的父/教师缓存、配对响应与逐层查询生成；
2. 归一化、岭回归或 encoder/head 的全部前后向拟合；
3. H 在评价请求中额外执行的 query–history 特征处理；
4. 每个请求的修正应用。

实验中共享教师、加载和遍历能节省执行时间，不减少各独立方法点应承担的成本。
另记耗时、峰值显存和临时特征存储，不能用 FLOPs 替代延迟测量。
H 允许消耗明显更多计算来检验恢复潜力；其实际开销和相对 Full 的比例依照测量报告。
不要求 H 进入低成本区间，也不因它较贵而改用摘要。训练成本和请求期成本分别报告，
不能只靠增加校准人数的训练开销来声称每次推理引入用户信息更昂贵。

## 输出与判断

- 两方法各 15 条曲线：每方法 3 张图，每图同规模的 5 条边；全部 C、负恢复和非单调点保留。
- 原始 AUC、绝对 AUC 差、恢复率、总成本及四项成本分解一起保存。
- Q 补充固定低成本区间 `<=1%、<=5%、<=10%` 与四基线的已测点比较。
  某方法没有该区域的实测点就说明未覆盖，不画外推点或将连线当实测结果。
- H 首先比较同一 C 下相对 Q 的恢复提升，同时展示增加的训练与推理成本。
  它用于检验高成本显式用户信息的恢复潜力，不承担低成本胜过基线的目标。
  不能仅凭相同 C 就声称计算效率更高。
- 逐规模汇总均值/中位数并保留逐边值，不能只选有效边。
  配对用户 bootstrap 可估计固定面板内部的不确定性，但不充当多训练种子验证。
- Q 便宜且有效、Q 随 C 饱和、H 提高恢复、H 成本显著右移，四项分别判断。
  不要求共同成立，不以期望恢复率作为中断或删点条件。

## 实现与执行安排

建议按 `query_only/`、`history_conditioned/` 隔离数值代码和测试，
使用独立 `scripts/read_correction_2026_09/` 与对应 results/configs 目录。
复用当前滚动执行器、聚合、四卡用户划分和断点机制；不复制整套数据流水线。

已有 `scripts/design/query_read_probe.py` 和 adaptation reader 可提供拟合/注入原语。
旧 candidate+response、PCA32 和 `N*b+T*r` 实验不等于这里额外的 query–history 特征支路；
旧静态分数也不能直接接入这次滚动曲线。

先用独立小样本确认：零修正回到 Reuse、注入位置与同 q 教师正确、K/V 不被修改、
额外用户信息确实进入 correction 的训练与推理、分块和直接计算一致。
随后每规模做一次小型速度/显存探针，按实测重新定 batch。
保留 70% 显存安全线、GPU0/1/2/3 全部使用、用户分块断点和约两小时进度报告。
encoder 反向传播有新增显存，不能直接套用旧纯推理 batch 或承诺旧 2h42m 耗时。
准备好脚本、canary 和运行估计后汇报；正式全量启动仍等待用户明确指令。
