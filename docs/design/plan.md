### 本轮Design的分工与最小候选

| 部分 | 必须回答的问题 | 当前实施边界 |
| --- | --- | --- |
| Design 1：读取机制 | 如何用已有历史恢复Current的读取，同时保持每query足够轻？ | 当前候选用共享窄code调整Key分数和Value读取，合为一次history attention；原生KV只有一份 |
| Design 2：发布准备 | 如何在未知未来反馈时，准备对推荐任务有用的共享规则？ | 少量发布前历史提供Current教师；先对齐读取，再联合对齐最终打分，独立验证后发布固定参数 |
| Design 3：持续状态 | 规则如何随真实追加、淘汰和下一次发布保持有效？ | 编码与KV逐行对齐，目标变化重编码；重建或因果清除后退出。所有初始化/维护均计费 |

三部分共同承担目标。D2校准D1实际具有的残差分支，不要求新候选继续拥有旧K/V/Response
三种强度；D3维护新候选实际使用的状态。不能因旧接口存在就保留昂贵组件，也不强行要求
三个模块各自贡献显著AUC。论文当前同步到local-KV轻量机制；旧Item64/Response256证据仍保留为历史记录。

已实现[最小Value候选](../../src/hstu_kvcache/design_one/lightweight.py)：每层每head用该head的
旧K、旧V及Current item片段，经小型SiLU映射生成2/4/8维code。Key保持原生；一次QK和激活后，
同一个AV聚合原生Value与code，code的加权和投影回Value维度并加到read上。
可选Response宽度为0/8/16。无需在query时重新编码历史，没有第二次attention，也不持久化完整映射KV。
当前PyTorch参考会临时拼接`[V; code]`，其复制和内存开销明确保留；尚非融合kernel或速度优势证明。
独立数值检查覆盖与显式Value变换的输出/梯度等价、identity、基础模型冻结及追加/淘汰对齐。

### 固定计量，再判断结果

每次发布的AUC在该版请求上计算，按论文原先的等权发布差异汇总：
`recovery = 100 × mean_v(AUC_method_v − AUC_reuse_v) / mean_v(AUC_rebuild_once_v − AUC_reuse_v)`。
所有预定发布都保留；总平均缺口非正时不定义整体恢复率。逐边仍列绝对AUC、logloss、
原始缺口与可定义的恢复率；pooled跨版本AUC只作补充，不能事后替换主指标。

计算用同一服务场景的**绝对FLOPs先累加再求比**：
`cost = 100 × sum_v(发布源/教师/拟合/验证 + 编码准备维护 + 读校正 + 实际重建增量) / sum_v(一次重建策略全服务工作 − Reuse全服务工作)`。
每版共享准备收一次，每个方法收其实际需要的准备；完整研究批次的无关对照不重复收费。
保留教师、拟合和验证费；新方法真实减少准备才可以减账。主一次重建路径使用首次请求触发；
发布时对全人口预先重建的Exact同时报告，明确其空闲用户工作量。每个用户每次发布最多重建一次。
同一策略的质量和计算使用相同轨迹；Fresh只保留为历史诊断参照，不能代替一次重建质量。
FLOPs、执行时间、峰值显存、常驻状态与传输分别报告。
子样本实测只证明子样本质量/单位工作，完整人口解析账或统计估计应明确标识，不能称为全量执行。

**Design 1的完整读路径。** 原生K/V与Current物品表示产生可复用Item窄码；读取时将
线性K/V输出投影并入attention计算，避免保存完整校正K/V副本。得到`r_compact(q)`后，
Response执行`r_hat = r_compact + N * g([q; r_compact/N])`。`N`用于归一化和恢复尺度，
不是额外网络标量输入。Item读取与Response都使用当前query；Response只读取聚合结果，
不再访问历史条目，也不增加用户持久状态。完整历史`d1`评分与当前Design 1保持同一含义。

**教师拟合与任务协调分工。** Design 1先逐层拟合Item表示及投影，再冻结全部Item，
逐层拟合Response。第一阶段使用已拟合下层Item产生的query；第二阶段还包含已拟合下层
Response。每层在同一query上读取Current重建历史作为目标，没有跨层端到端梯度。
十项诊断表明教师误差与推荐质量可能不一致，且分支贡献与层间传递会相互影响；这些观察
引出用历史标签联合校准强度的假设。训练优化跨请求正负对的判别损失，服务只应用冻结参数；
它不把新请求的读取偏差换算成真实质量，也不提供在线检测与修复质量的闭环。

**Design 2校准候选：发布固定的逐层三强度。** 为每层设置`a_K/a_V/a_R`，
`s = 1 + tanh(a)`；六层共18参数，全零初始化使三个强度均为1并精确恢复完整D1。
K强度作用于attention激活前的Key校正，V强度作用于加权Value校正，R强度缩放Response增量。
Response接收经过K/V强度调整后的聚合read；上层query也随下层协调变化。主模型、Item和
Response参数冻结，但任务梯度穿过整个当前query前向及下游query，联合更新所有层的强度。
训练和验证只使用发布前已完成请求与已到达反馈，发布后固定共享表。新请求的真实标签未知，
方法不能据此判断其质量或选择修正强度；在线不读教师，也不修改原生写入。
这与Design 1的逐层教师拟合是两种明确不同的梯度范围。

上一轮候选对应已完成的`coordination/round2`静态模式（历史结果键`constant_task`）。
使用固定fit1024/validation256、每版发布前28天真实反馈；已有角色隔离和新增768拟合、240验证
用户的未来评价排除规则不变。batch16按真实标签类均匀有放回抽8正/8负，平均全部64个

同一checkpoint、8轮、lr0.0001，配对保留响应目标与联合Full-logit目标，分别计入继承校准。

append768状态间交替8轮，检验混合状态覆盖。额外场景费用全计，预估14.776%。

第十六轮回到第十一轮网络，仅将校准query改为最近16个known历史物品（不足时原seed补齐），

两者共用Full教师和评价；先检查同query读响应误差与最终打分是否一致改善，

摘要维护、共享参数生成、读修正和状态更新的最小闭环已实现，
