## 1. 推进原则

- **先有完整 v0，再联动迭代。** 摘要、翻译、读取、持续维护都进入第一版；某个组件尚不理想，
  不妨碍先接上其他组件。真实摘要参考与 learned Translator 同轮比较，不把摘要达标当成开始翻译的前提。
- 四条主线保持；slot 表示、网络、loss、读时权重、刷新策略及它们之间的接口可以一起调整。
  数值、因果和评价口径必须正确，但初始超参数与模块边界都是可撤回的工作选择。
- 摘要或 K/V 衍生目标上的拟合是可用手段，旧的 target-KV fitting 笼统禁令已撤销。
  按完整流水线的收益、成本与可执行性判断方案；四个组件都承担实际工作，内部实现先小后改。
- 一轮围绕一个可解释的假设，必要时联改两个模块，回到同一闭环检查。避免同时铺开参数网格，
  也不为维护某个局部方案不断增加复杂性。局部失败记录后继续修；路线级反证按第 7 节处理。
- 所有模型前向与方法实验使用 **6L/H192/6 heads/context1024、seed17 的 D14 V0–V5**。
  小样本减少用户、请求或训练步数，不换四层、小随机 backbone 或十层模型。纯张量公式对照不另建模型。
- 同步、内存中、顺序执行足以起步。只补会影响研究结论的检查，不先做通用配置框架、并发事务、
  服务部署、状态序列化兼容或完整测试矩阵。每轮留下足以复现结论的记录即可。

统一记号：方法写作**方案0、方案1、…**，方案编号不是实验次数；同一方案可有多次校准和对照。
模型使用**M0–M5**，五次模型切换为M0→M1→…→M5；M0是初始基线，M1–M5是五个目标模型。
**C0–C5**表示对应服务阶段的实际持续缓存状态；C0为初始缓存，C1–C5分别在M1–M5服务期间
追加、淘汰及维护。C_i可能保留多个模型生产的K/V，不等于全部由M_i生成。
历史叙述的小写v编号对应方法方案，大写V编号对应同号模型M。既有run_id、路径、配置与
封存证据保留原名，后续对用户的说明、结果表和新记录统一使用上述记号。

## 3. 方案 v0：四部分共用的一条闭环

### 3.1 一次请求与一次发布怎样连接

```text
实际存储的 event K/V ──写入/扣除──> source sums + count/坐标/producer/revision
                                            │
发布通过 Full-only admission ──> 共享 Translator ──> 当前目标的 translated view
                                            │
本层实际 query ──> 普通历史读取 + translated read − source read
                                            │
                       原模型 normalization / gate / projection / residual
                                            │
                         下一层 query；真实事件追加时产生新的 K/V
                                            │
                更新 source，必要时刷新；下一次发布仍从原 source 转换
```

状态最低限度包含普通 K/V、每事件固定归属、source 累加量与结构 metadata、producer、
source revision，以及一个目标版本的 translated view。这里的 source 是**实际写入状态的摘要**，
不是理想 Parent/Current Exact state。暂态候选只查询，不进入 persistent history 或摘要。

### 3.2 四个部分的初始实现

| 部分 | v0 的最小选择 | 与其余部分的连接和可调整项 |
| --- | --- | --- |
| 写时摘要 | 沿用每段 64 events、每层两个连续 slots；累加实际 cache K/V、count、时间与事件序号，按需计算均值；先用原 cache 精度和 FP32 sums | 淘汰扣除原贡献，归属不随窗口重排；后续可联改统计量、slot 数与 reader，边界额外容量照实计量 |
| 发布时翻译 | 小型残差网络：编码一个 segment 的跨层 slots，结合按时间顺序的累计上下文和 producer 标记，解码各层 K/V 残差；只输出 payload | 初版用简单累计上下文加 MLP 即可；若信息不足再比较小型序列网络。每目标一个共享网络，单边时退化为 edge-specific；不做逐用户网络 |
| 读时加权修正 | 同一 query 按原 HSTU 算子读 source/translated slots，以 count 加权，两者相减后加到 S4 历史聚合 | 首版修正系数为 1，不加学习式 gate；后续只有证据支持时才研究校准集共享的幅度控制。不能混合最终预测分数 |
| 连续维护 | 顺序实现追加、部分/整段淘汰、发布封段、source revision 更新、剩余旧段同步刷新，以及第二次目标切换 | current 段走普通路径；再次发布以原 source 和真实 producer 为输入。初版无后台任务或并发，未覆盖 source 的请求计入 Reuse |

网络宽度、学习率、步数和 loss 权重先给一组简单初值并记录；小样本成本检查后确定该轮配置，
不把初值变成长期规则。
默认输入只有需要迁移的旧段，符合当前论文；旧 source 改动后刷新该用户全部剩余旧段。
新增 current 段暂不进入 Translator。如果以后改变上下文输入范围，必须同时修改刷新依赖和成本计量。

**2026-09-06 权重配置复核纠正：**实际六层 Medium checkpoint 使用 `legacy/elu_plus1`，
不是初稿假设的 `hstu_reference/silu`。v0 slot read 严格使用
`count × (ELU(scale × q·mean_k) + 1) × mean_v`；这些模型没有 relative-position bias，
也没有 `/max_seq_len`。读取先做原 attention out projection，再做 SiLU gate 和 residual。
代码以实际模型配置为准，不修改 backbone、不把 legacy 结果称为原生 SiLU HSTU 验证。
这里的权重不是 softmax 概率，也不能除以 slot 数。
两次摘要读取与普通历史读取共用本层实际 query；加上模型规定的暂态 self contribution 后，
按原 block 顺序继续。新时间/位置规则不能靠网络补偿。

### 3.3 校准与梯度也要进入 v0

先以 identity Translator 接通一遍，验证修正为零时与同一实际 cache 上的普通读取一致；它只是接线检查。
**v0 的完整交付必须包含一次真实的共享 Translator 短校准及未参与拟合用户的输出**，
不能只留下 identity 或 Exact-summary oracle 就称为方法跑通。共享校准已纳入用户确认的开发范围，
直接记录划分、监督来源、配置与预算，不为“是否 KV 拟合”再设审批。

初始 loss 沿论文使用固定尺度的 summary reconstruction 与 response-difference 两项。
教师只来自独立 calibration users，使用同一可见历史、mask、坐标和实际 query 比较完整缓存响应。
低层修正产生下一层 query，训练保留这条梯度路径；冻结 backbone 参数不等于对整个 reader 使用
`no_grad`。教师缓存和监督目标停止梯度，不允许把 Current Exact query 的独立前向替代闭环。
先保证六层当前请求内部可微；跨事件和跨发布的持久状态按实际前向生成并 detach，不在 v0 保留
整段服务轨迹的反传图。表示重建与响应 loss 是起点，可根据闭环效果调整或替换，不以重建误差单独选模型。
训练每步用当前参数重新生成 translated payload，避免复用前一 optimizer step 的视图。
训练结束后固定本轮译者，重新生成用于后续发布的校准/开发轨迹；不把训练途中的旧译者状态
当作最终部署状态。这样即可起步，无需实现在线译者热更新。

一开始就纳入少量追加与部分淘汰形态，不等待静态摘要训练到高精度。混合 producer 校准按固定
发布顺序实际运行先前译者和追加过程生成 source；不能用各版独立 Exact K/V 拼接冒充服务轨迹。
目标发布时的校准只能使用该时点前已可见的数据；若以后研究延迟校准，需报告真实完成时间与覆盖。
在一个目标的校准过程中，可用当前译者重放校准用户的发布前前缀，生成追加/淘汰训练形态；这些是历史回放，
不是用目标发布后的评价请求训练。更换前一目标的译者后，需要重新生成受影响的后续混合状态。

混合状态中先用 producer 确定需要翻译的旧段集合，summary 和 response 监督都对应这一集合，
教师摘要沿用 source 的事件归属。当前版本新段的后代误差单独测量，不默默把它混进旧段教师。
若以后尝试用旧段修正补偿整个历史响应，再明确增加该目标并验证其输入信息与效果。

### 3.4 v0 的最小运行与完成标准

建议按时间顺序从 **模型 V0→V1，随后 V1→V2** 起步，对应 day231/day245；按版本顺序选起点，
不按已知恢复率选“容易边”。单边使用 8–32 个开发用户；连续链先用其中 2–4 个用户跑真实事件，
保留到下一次切换所需的轨迹。校准可先从固定独立 UID 次序中取 32–64 个用户，具体数量由 canary
校准。以上是起步预算，不是冻结的人口或效果门槛。

先完成以下整链接线与测量工作：

1. 一个可重复的命令，输出 Reuse、Current reference、Exact-summary diagnostic、learned 方法的紧凑表。
2. 从写入到读取、真实追加/淘汰、再到第二次目标切换的一条状态轨迹；各版本的训练与读时输入可追溯。
3. 译者确实在未参与拟合的用户上执行，教师没有进入这些用户的方法输入或优化过程。
4. 有限数值、identity 一致性、逐事件 writer 增删参考及一条因果轨迹检查通过；留存耗时、显存和差距。
5. 对当前主要误差给出判断和下一轮假设；数值/因果错误先修好，不能据其判断路线。

**接线完成只是中间进展；v0 初步有效还需要成本与恢复方向成立。** 在未参与拟合的开发用户上，
修正要带来清晰、有实质意义的差距恢复；一次发布的计算应明显小于 Exact-All，在线读取和维护
不能迅速吃掉节省。起步不设严格的 80%/20% 数值门槛，但 90% 计算换 10% 恢复、接近零恢复，
或只有孤立样本获益，均记录为待改原型，继续联动迭代，不宣布 v0 方法有效或进入正式扩展。
极小样本的波动不足以判断时，在原定开发用户顺序上适度补样本；不挑有利用户或版本。

真实事件不足以覆盖某种状态时，报告未覆盖，另用小型状态操作检查接口；不能人工改发布窗口、
制造未来事件或重置为 Exact 来取得“连续迁移成功”。

### 3.5 同一份缓存跨多个版本怎样演化

连续优化的对象是缓存的实际生命周期。一个 V0 写入的事件只要仍被保留，其普通 K/V 与 producer
就继续属于 V0；服务 V1、V2 时，变化的是对应目标的 translated view 和读取结果。
新事件则由当时服务的模型在修正上下文中写入，因此同一用户会有不同 producer 和不同继承误差。

| 发生的事情 | v0 的状态处理与执行次序 |
| --- | --- |
| V0→V1 | 关闭 V0 未满段；从 V0 source 得到面向 V1 的视图；之后新写入建立 V1 段 |
| 真实事件追加 | 容量不足时先淘汰、扣除 source；若旧段输入改变则先刷新，再用修正路径处理事件，最后保存实际新 K/V 并更新 current source |
| 只有 current 段追加，旧段输入未变 | 更新普通 cache 和 current source；当前译者不读这些新段，因此无需重翻译旧段 |
| 部分/整段旧历史淘汰 | 按固定事件归属扣除；移除空段，刷新同用户剩余旧段；不要先用过期视图读一次再刷新 |
| V2 发布而 V0 尚未淘汰 | 一个面向 V2 的译者读取原 V0/V1 source 和 producer 标记，替换旧目标视图；不把 V0→V1 的预测当作 V0→V2 输入 |
| 很久没有新事件，但仍有旧 K/V | source 随保留事件存在，后续目标继续覆盖它的 producer；年龄本身不触发删除。无匹配视图时用户走当前目标的 Reuse，计入覆盖和质量 |
| 旧 producer 最后一段退出 | 去掉其直接摘要修正；其后代 K/V 的误差仍可能存在。在线来源支持退出以所评估人口实际无引用为条件 |

满窗口下，每次真实事件追加都可能扣除一个旧段贡献，触发剩余旧段的全量摘要刷新；频率可能是
逐事件，而不是每 64 个事件一次。v0 的 canary 同时测一次刷新和轨迹中的刷新次数；若累计开销
主导成本，优先联改译者计算或刷新方式，不能只用发布时的一次转换成本判断轻量化。

source 保存稳定的事件序号和时间统计，读时再映射到当次窗口坐标。translated revision 对应的是
**该目标 Translator 实际输入的 source 内容**，不因无关 current 段追加失效；v0 用输入变化标记
即可，无需并发 revision 框架。目标变化总是重建该目标视图；不支持任一活跃 producer 时首版对整用户
使用 Reuse，不掩盖未覆盖比例。同 timestamp 的请求仍先按严格 prior history 评分，再纳入真实写入。

从 V1 到 V2 的小轨迹负责接通接口，后续在固定开发用户上覆盖长驻旧段、快速全部淘汰、多个
producer 共存等真实情况，报告每类的用户/事件数与未覆盖范围。当前目标段的误差、来源年龄、
旧段剩余量、刷新次数和质量一起记录；不能把旧段清空当作误差已经清空。

额外机制按证据加入，例如混合来源/淘汰前缀校准、按来源条件化、读时幅度控制、减少刷新工作，
或有明确成本的局部 replay/rebase。新增机制必须接回完整生命周期，报告改变了哪些普通 K/V、
source 与依赖；只保留能解释收益或必要性的部分，不一次实现所有候选机制。

开发中改变 summary schema 时，同一运行的各版本统一使用新 schema，必要的 backfill 单列；
改变早期译者、reader 或维护规则时，从受影响的发布点重新生成后代轨迹。后续译者不得继续把
旧方案生成的混合输入当作新方案分布。纯指标汇总修改则直接复用原始数值，不重跑模型。

首轮采用同步转换/刷新，轨迹明确标记为视图就绪后的机制测量，单列发布准备时间和刷新阻塞成本，
不据此声称异步迁移已达到全覆盖。完整服务时段评价时再纳入就绪前的 Reuse 请求及其实际写入，
并报告模型切换与视图就绪两个时点；这些写入产生的后代也要进入后续轨迹，不能只补几行等待期分数。

## 4. 迭代路线：每版都有整条链路

| 迭代 | 研究问题与最小工作 | 交付与下一步依据 |
| --- | --- | --- |
| 方案 v0 | 四部分接通，小校准、单边读和两次发布轨迹一起跑；身份对照和真实摘要参考定位误差 | 整链运行记录，并验证低计算、实质恢复的方向；高成本弱恢复时继续改原型 |

## 5. 数据、对照与“比较 OK”的判断

### 5.1 分开拟合、开发与确认

- **Calibration**：从既有 Medium 固定人口内，按标签无关规则选择、排除整个 3,000-user Insight cohort；
  与开发及最终确认 UID-disjoint。可按固定顺序扩容，不能因 target response 好拟合而挑人。
- **Development**：优先复用 Insight selector `[0,512)`，先小后大。已有 `[5,3000,64]` panel
  继续保持原顺序；开发使用其中对应子集，不把 anchors 用作新方法的逐用户教师。
- **Confirmation**：原 `[512,3000)` 在 Insight 2 下有冻结前禁读约束，但这些用户已参与 Insight 1。
  因而不能笼统声称它们在研究过程中完全未见。建议保留原边界，并在首次方法实验前，另从剩余
  eligible users 中预留一组对方法未读、与 calibration/development 不交叉的最终用户；先固定 UID，
  不读取其目标响应或质量来做选择。确认规模在正式运行预算中确定。

用户划分针对适配方法；不声称这些用户未参与已有 backbone 训练。现有模型结果也已经可见，
五条更新提供同一 seed 的跨版本证据，不是五个独立训练重复。扩大人口不增加训练 seed 数。

无标签 candidate probes 用于响应/概率一致性，不给这些候选编造正负标签。
真实推荐质量复用 explicit-feedback 请求、已冻结指标和严格时间先后；同 timestamp 的请求
不能读到该组尚未发生的写入。持续回放不能仅反复使用 cutover 的候选集合代表真实线上任务。

### 5.2 最小对照与诊断分解

每轮首先保留 Reuse、Current reference、learned 方法；需要分解时同批运行真实目标摘要参考。
参考只用于测量，不向方法分支提供目标状态。少量 full-response 注入可定位实现错误，属于诊断。
后续按具体假设增加一个对照，如去掉一项 loss、局部 mapper 与跨段 Translator、paired 与仅加
translated response；不先恢复整套旧 PRO/controller/frontier 对照。

连续轨迹的 Current reference 在相同发布点执行 Exact-All，并在其后使用相同追加、淘汰、时间
和位置语义；方法和 Reuse 分支从自己的实际状态继续。每次请求重建滑动窗口的 Full 如需测量，
单列为另一个参考，不能把保留策略差异计入版本误差。五个重新初始化的单边实验不能充当连续链。

记录四类量：摘要差分的压缩误差、译者的响应/表示误差、闭环的预测与任务变化、连续状态误差和成本。
Exact-summary 效果弱不构成所有 learned 摘要的严格上界；它提示需要联改表示与功能目标。
oracle 效果强而 learned 效果弱，也只能说明当前估计器尚未成功。

### 5.3 已确认的方向与分步验收

用户已确认目标是少量计算换取大量差距恢复。v0 按第 3.4 节检查方向是否成立，
较成熟结果继续向以下目标推进；具体阈值在开发期测量后、正式确认前固定：

- 在开发集上逐步接近 **80% 的 Full–Reuse 质量差距恢复**，90% 作为争取目标；沿用草稿的方向，
  但不把这两个数字当作 v0 的完成条件。最终主指标及聚合方式需先固定，不能在 AUC 恢复和概率
  gap recovery 之间择优替换；建议真实任务 AUC 为质量主指标，概率差距为机制指标。
- 报告每条边、绝对 AUC/PR-AUC/log-loss/Brier、Full–Reuse gap，以及用户等权的未裁剪机制恢复率。
  gap 近零或反号时报告绝对量及 No-op，不用不稳定比例制造成功；数值容差在开发期确定。
- 两次及以上真实迁移后，收益仍存在，后代误差没有把收益持续吃掉；旧 producer 全部淘汰也不能
  自动宣布新 K/V exact。全体请求计入质量与覆盖，未迁移/不支持来源的 Reuse 不从报告移除。
- 一次发布计算目标沿用 **同人口 Exact-All 的 20% 以内**，包含教师、训练、初次 backfill 和转换；
  在线写入、paired read、淘汰刷新、I/O/存储另计，再在固定服务时段累计比较。

小校准和微型评价的成本先报告绝对数；对完整人口的外推明确标注，不能靠换分母宣称达到 20%。
正式人口、history-weighted 分母、服务时段和成功口径在确认前固定。
第一张表即并列给出恢复与成本；辅助测量用的 Exact/oracle 开销与方法必需的教师/训练开销分列，
后者全部进入方法成本。小样本成本外推使用事先写明的同一目标人口，不把更大人口当作临时省成本手段。
微型无标签 probe 的概率恢复不能证明 AUC 恢复；真实反馈不足以稳定估计 AUC 时标明未验证，
在开发扩大阶段补齐，不能把二者互相替代。

## 6. 每轮怎样运行、估时与留存

先写一句本轮假设与最小对照，保存必要配置，再做小样本。运行前用同一路径区分模型加载/取数、
teacher 构建、译者 step、用户转换、单次 read/append/refresh 的耗时与峰值显存。
估算可用 `固定开销 + 用户/前缀数 × teacher 时间 + steps × step 时间 + 请求/事件数 × 路径时间`，
同时计入未包含在 steady-state 计时内的 I/O，并给范围而非虚假的精确 ETA。

| 作业 | 执行方式 |
| --- | --- |
| 文本、接口检查和公式对照 | 直接运行最小检查；不加载完整模型作无关验证 |
| 首次六层 canary | 先取 1–4 个用户或数个 step，测真实资源，决定该轮规模 |
| 预计不超过 30 分钟的开发运行 | 直接运行并主动监控，回报进展与预估变化 |
| 预计超过 30 分钟的运行 | 先有资源估计及适用的 launch 授权，用 `tmux` detached 启动，退出交互终端；留日志、退出码、结果路径，结束后继续分析 |

短任务发现明显低估时，及时重估；必要时停止可重做的开发探针、缩小规模或改用 tmux，不能
默默让前台变成长作业。tmux 解决执行方式，不替代长校准或正式人口实验的授权。
GPU 0/1/2/3 可用；初版优先单卡，一次只做一组模型/edge。确有需要时才用四卡，一个模型最多
一个 four-rank FSDP job，seed/release 串行。允许安全的 CPU 取数、mapping、join 和 aggregation 并行。

每次运行保存 `configuration.json`、`summary.json` 和足以支持结论的原始数值；耗时/资源可写入
同一个 summary，长作业再给 `resource_estimate.json`。记录代码 commit；有未提交代码则留本次
patch/源码快照，不能只记一个不能重现运行的 commit。列明 checkpoint/输入 manifest 的引用及 hash、
UID 划分、seed、命令、耗时、峰值显存、关键指标与失败状态。已有 hash 可引用，不为每次小改动全量重哈希。

当前 [.gitignore](../../.gitignore) 已支持 `results/design/` 中的紧凑配置/summary 与本地 raw 分离。
研究记录、配置和支持结论的紧凑证据进 Git；raw、权重、日志留本地。保留正负结果与当前方法必要权重，
不默认保存重复 teacher cache、每步 checkpoint 或巨量 trace。若必须清理某次探索的原始量，
先注明保留内容与恢复限制，不能只留有利结果。模块测试仅覆盖相关公式、梯度连通、时间因果和聚合；
同一小样本可兼作 correctness canary 与资源估计，通过后不惯性扩大到完整 pytest。

## 7. 失败如何分类与处理

| 观察 | 判断与动作 |
| --- | --- |
| 均值摘要弱、某层误差大、短校准欠拟合、一次发布变差、刷新较贵 | 首先视为局部问题；记录证据，修改相关模块或联合接口，再用最小对照检查 |
| 真实摘要诊断强，learned 方法弱 | 排查输入可预测性、监督与泛化；不引用 oracle 数字作为方法结论 |
| current 后代 K/V 漂移，或混合来源覆盖不足 | 实际轨迹上判断程度，研究训练形态或有明确预算的局部维护；不能按 producer tag 宣布正确 |
| 证据显示只有给评价用户目标状态/未来信息、逐请求近似全量重算，或放弃核心四条链路才能成立 | 路线级反证候选；停止扩展实验，保存最小反例并及时告知用户 |

发现路线级反证候选时，先做足以排除实现/指标错误的最小复核，不反复加网络寻找偶然正数。
记录：被推翻的核心假设、支持证据、已排除的局部解释、哪些结论仍成立、是否需要重设研究路线。
若确需整条链路重做，暂停方法推进并讨论；不自行把论文换成另一条路线。单个弱配置、单条小 gap edge、
预算外的一个实现点都不能直接推出根本不可能。**目前短校准只支持局部失败判断，尚无路线成立或失败的充分证据。**

## 8. 用户澄清后的决定与 review 结论

| 已澄清的问题 | 当前决定 | 对实施的影响 |
| --- | --- | --- |
| target-KV fitting | 撤销笼统禁令。摘要拟合、K/V 衍生监督及共享校准均可用，按方法整体效果与成本选择 | 不再因拟合名称、重建 loss 或局部监督调整申请新权限；保留四条主线的实际作用 |
| 连续优化 | 同一份 cache 从产生、混合追加、淘汰到跨多个目标版本的演化，包括长驻旧段及必要的额外机制 | 实现第 3.5 节的顺序生命周期；不是把独立单边结果拼起来，也不要求一开始跨版本联合反传 |
| 比较 OK | 低计算、大量恢复从初期就是方向要求；准确阈值可在开发中逐步落实 | 接线完成与方法初步有效分开记录；高成本低恢复不能作为成功版本交付 |

当前 [AGENTS.md](../../AGENTS.md) 与活动实验文档已移除过时限制。既有 sealed 合同中的禁止训练/
拟合条款留作原实验的历史记录，不拿来约束本次新方法。开发仍明确 fitting、development、confirmation
的用途：若使用评价用户的目标状态拟合，所得数据应作为相应拟合诊断或对照，不能同时宣称这些用户
上的未见泛化；所需目标计算照实计成本。这是结论的解释条件，不是另一条 KV 拟合禁令。

Review 已修正：旧监督许可限制、v0 验收过松、淘汰/刷新次序、无关追加导致的多余刷新、混合状态教师
范围，以及早期模块变更后下游轨迹失配。详细记录见 [iterations.md](iterations.md)。
剩余的摘要表达能力、翻译泛化、后代误差和长期成本是 v0 起就要测量的研究问题，没有发现要求先
重设计整条路线的计划缺陷；这里不预判尚未运行的效果。

用户随后授权本阶段六层冻结模型、已开放数据及 GPU 0/1/2/3 范围内的开发、长 Translator 校准和正式
六层评价；本指令即该范围的明确启动授权，不逐项重复确认。长作业仍先落实前瞻配置、资源估计和
canary，超过 30 分钟使用 tmux detached，完成后继续分析。不重训 backbone、不触及 theta3。

首个 canary 使用 2 calibration / 2 development / 1 trajectory users、两目标、每目标 6 steps；
网络为跨层双 slot segment 编码、64 维累计上下文残差 MLP，Adam lr=0.001，summary loss 权重0.1。
校准包含截止发布前的真实末尾事件重放；第二目标 source 由第一目标最终译者连续回放生成。
独立确认 UID 已在首次模型输出前冻结，详见迭代记录。首轮结果决定下一次短校准规模。

当前v2探索将真实source均值作为共享预测器输入，source/translated读取view使用ELU+1零key
常量基，预测每层历史响应变化；仍执行paired correction并保留真实cache生命周期。writer采用
1024事件上限×1slot、发布封段以精确维护producer；全用户聚合使每次输入变化只需一次小网络。
这一表示由v0/v1均值KV读取和泛化不足的证据触发，未验证有效，具体初值和负结果见迭代记录。
第3节仍保留完整v0定义，便于复现对照，不能把它当作当前v2的实际网络或读取公式。
当前候选是按producer分别累计特征的rank32共享岭回归，预测per-old-event响应变化率，再按
真实old count还原聚合修正；以修正后的实际query重新生成calibration目标，做3轮共享闭式拟合。
该选择由128人response proxy的低误差触发，不代表闭环质量已成功；2人canary的严重过修正也保留。
128人完整闭环和后续负变体已记录；当前保留rank32与独立Parent-Exact补充校准场景。
执行器已接入V5独立Full-only诊断seal与实际extension反馈manifest，保留E14_partial及
非serving admission解释；v3五边512人长轨迹已完成，真实反馈14164条，见迭代记录及

v2的CC常量修正应用到实际write token会显著增加新K/V误差，详见128人写入诊断。
