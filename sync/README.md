# 两台机器间同步本地数据

本仓库在两台有 GPU 的机器间通过 Git 同步代码。训练任务会不定期地在任一机器上运行，运行量也不相同；模型 checkpoint、原始/处理后数据体积很大，且按 `.gitignore` 规则不进入 Git。没有共享云盘时，需要人工用移动硬盘或其他直连方式复制数据，但必须先知道应该复制什么。

本目录把可共享的同步说明和脚本纳入 Git；机器清单 `202`、`201` 则是本机文件，已由根目录 `.gitignore` 排除，分别记录对应机器上被 Git 忽略的数据文件和训练模型 checkpoint。清单只收录 Git 当前判定为 ignored 的文件，路径相对于仓库根目录，附文件大小。已被 Git 跟踪的文件不需要列入清单。JSON 等普通实验结果不在收集范围内。比较两机清单时，需通过介质或直连单独传递清单文件，Git 不会传递它们。

202 的软件栈、GPU/CPU、代码中的设备假设，以及 201 的单卡验证配方见[环境目录](环境/README.md)。

## 更新本机清单

在仓库根目录运行：

```bash
./sync/inventory.sh 202
```

在机器 201 上运行 `./sync/inventory.sh 201`。该命令只更新对应机器的本地清单，不会复制或删除数据。清单按“数据”“模型 / Yambda”“模型 / RecFlow”组织；数据按原始、manifest、处理后数据及用途细分，模型按 Yambda 规模和 RecFlow 模型链细分。每个条目有说明和编号，各类别编号预留 001–100；文件路径及大小列在对应编号下。新增文件沿用原条目编号，新增类别应追加未占用编号，不要重新编号旧条目。扫描收集被 Git 忽略的数据文件、Yambda 各尺度 checkpoint、RecFlow checkpoint、Query Relay 候选模型快照和特征库；校准权重、分数及 JSON 实验结果不收集。

## 手动复制

先在两台机器分别更新清单并比较 `202` 与 `201`，再按本次实验需要选择要同步的条目。机器清单是完整盘点，不代表每次都要复制其中所有文件。可按条目编号复制，并保留仓库相对路径：

```bash
./sync/copy_to.sh 202 /挂载盘/evokv D007 Y002
```

例如 `D007` 是 Yambda 500M 处理后数据，`Y002` 是 Yambda Large 训练模型。必须指定一个或多个编号；不带编号或任一编号未匹配文件时会报错，不会开始复制。复制前先查看编号下的注释和文件列表，确认容量及依赖。

此例会把选定条目放到 `/挂载盘/evokv/` 下，保留 `data/...`、`results/...` 等相对路径。然后把本次选定的对应路径从介质复制到目标机器的仓库根目录下；在目标机器重新运行 inventory 更新本机清单。脚本不会删除目标文件，也不会通过 Git 同步清单、checkpoint 或数据。

## 同步实验结果

小型结果摘要、设置和说明通过 Git 同步。每台机器写自己的新结果目录，例如 `results/environment_201_2026_10/`，避免覆盖另一台机器的输出。根 `.gitignore` 已允许 `results/**/summary.json` 和 Markdown 说明；提交前用 `git status --short` 确认实际纳入哪些文件。提交并推送后，另一台机器拉取即可。

大权重和数据继续走上述按需复制流程。分数、校准权重等不在机器清单收集范围内，某个实验需要它们时按明确路径另行复制；不要把整个 `results/` 强制加入 Git。两机结果都记录机器、GPU、软件版本及命令；硬件不同的路径耗时分别报告。

## 通过 SSH 从 202 拉取

2026-10-21 已在 201 验证 `ssh -o BatchMode=yes g202 hostname` 可免密登录；202 的仓库根目录为 `/home/gkl/work/evokv`，201 为 `/data/gkl/work/evokv`。可以按具体文件路径使用 rsync over SSH（或 scp）。例如在 201 仓库根目录拉取一个 checkpoint 并保留相对路径：

```bash
rsync -aR -e 'ssh -o BatchMode=yes' \
  g202:/home/gkl/work/evokv/./results/unified_training_2026_09/medium/seed17/checkpoints/v2/checkpoint_100.pt ./
```

将 `/./` 后的部分换成本次选定的文件或目录即可。批量拉取可用 `--files-from` 指定仓库相对路径清单。本次真实 Yambda smoke 已通过该方式只拉取必要数据和 v2 模型，详情见[环境记录](环境/README.md)。机器本地清单和大文件仍不进入 Git。
