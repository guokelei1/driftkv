# 两台机器间同步本地数据

本仓库在两台有 GPU 的机器间通过 Git 同步代码。训练任务会不定期地在任一机器上运行，运行量也不相同；模型 checkpoint、原始/处理后数据体积很大，且按 `.gitignore` 规则不进入 Git。没有共享云盘时，需要人工用移动硬盘或其他直连方式复制数据，但必须先知道应该复制什么。

本目录把可共享的同步说明和脚本纳入 Git；机器清单 `202`、`201` 则是本机文件，已由根目录 `.gitignore` 排除。`202` 记录当前机器（202）上被 Git 忽略的数据文件和训练模型 checkpoint；`201` 目前留空，等在机器 201 上扫描后填写。清单只收录 Git 当前判定为 ignored 的文件，路径相对于仓库根目录，附文件大小。已被 Git 跟踪的文件不需要列入清单。JSON 等普通实验结果不在收集范围内。

## 更新本机清单

在仓库根目录运行：

```bash
./sync/inventory.sh 202
```

在机器 201 上运行 `./sync/inventory.sh 201`。该命令只更新对应机器的本地清单，不会复制或删除数据。扫描包含 `data/` 下的文件，以及仓库里已知的训练模型目录：Yambda 各尺度 checkpoint、RecFlow checkpoint、Query Relay 的源模型/发布模型和特征库。校准权重、分数、JSON、日志和其他结果不收集。

## 手动复制

先在两台机器分别更新清单并比较 `202` 与 `201`，再把来源机器的清单对应文件复制到移动硬盘或网络挂载盘。可用脚本按清单打包式复制并保留仓库相对路径：

```bash
./sync/copy_to.sh 202 /挂载盘/evokv
```

此例会把 202 清单中的文件放到 `/挂载盘/evokv/` 下，保留 `data/...`、`results/...` 等相对路径。然后把对应路径从介质复制到目标机器的仓库根目录下；在目标机器重新运行 inventory 更新本机清单。脚本只复制清单中的数据文件，不会通过 Git 同步清单、checkpoint 或数据。
